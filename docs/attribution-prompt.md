# Attribution 提示词与任务分工

归因链路为 Compact → 组件并行调查 → Trace 摘要 → Session，独立 Attribution 与 Comparison 共用同一规划、材料和恢复契约。

## Compact

Compact 字段 Agent 接收代码整理的消息目录、请求返回关系、原始名称及有界原文片段。每个字段任务明确给出当前字段、value 类型、提取要求和完整提交示例；模型只提交这个字段的内容。摘要与结论实际进入后续归因，不提前判定问题类别与责任；`compact/default` 只校验代码拼装的完整结果，不调用模型。

固定浅层字段见 [`schemas/compact/result.schema.json`](../schemas/compact/result.schema.json)，每项仅有程序编号、文字槽位和 evidence；匿名模型组件只用规划、推理、答案合成三类，具名组件保留真实名称与类型；说明用一句话交代目的、动作和结果。只记录实际收到的轮次与可见思考，不补写隐藏过程，不记录评测者未核验等自述。一个输入记录按轮次、字段拆成独立单轮会话，另生成两条会话概览文字，程序插入工具调用与报错统计。代码共享原始事实整理，优先保留数值与稳定坐标；字段会话默认关闭额外思考，无探索调用，只提交自己的字段，代码直接拼装完整 compact，不调用汇总或复审模型。

模型材料只保留当前字段用得到的信息：`key_data` 只接收终稿完整短句或表格行，不混入工具数据、数值菜单和核验材料。模型只选 `evidence` 编号，程序逐字复制 key_data_content；其他字段填写固定文字槽位并选择原文，程序填写条目编号以及固定的 {evidence_id, quote} 引用。字段任务提供完整提交示例；关键数值示例使用当前材料中真实可选的编号。程序保留完整来源，字段及条目结构严格固定，禁止自由嵌套；meta 与完整最终回复由程序透传。

字段使用专用提交说明：调用 `submit_evaluation` 提交 `{"value":...}`，无相关内容时提交空数组；正文 JSON 不代表完成。说明不混入 Comparison 候选项、排名等规则，不增加复审或提交校验循环。

## Trace

`attribution/component` 每个任务只调查程序绑定的一个 Compact 组件。`invocations` 按实际调用配对参数/代码和回执，保留各次执行及修复顺序；逐次对照主体、期间、单位、字段和计算，不能用最后两次调用或成功状态代表全链路正确。相关工具契约、已加载 skill 原文、前序用户约束及必要替代路径可直接审查，长原文保留完整句段并提供补读入口，未核实须说明不确定。模型提交本组件 content/evidence/tool_error_reviews/problems，不提交 actor_index 或组件名；程序复制目录名称。终稿沿用已偏离请求的上游结果属于故障传播，终稿只承担自身新增错误。组件独立审查，允许分别记录同一故障的真实责任动作。

`attribution/trace` 在组件任务结束后只写简短 summary，有标准时附正确性判断；问题由程序按目录顺序合并。组件部分失败允许继续，摘要标明覆盖缺口；Trace 失败阻塞 Session。单轮 Session 由程序组装，多轮使用 `attribution/session` 一次轻量审查，接收有序 Trace 结论和必要原始问答，独立跨轮问题必须有至少两轮原文依据。正式 Schema 不变。


统计范围识别单独定位总体、子集、调整前后的实际混用；不同口径数值都正确且已说明差异时不报矛盾。结论一致性要求对象、时点、统计范围、调整方式和适用条件相同，不能把未展开的口径解释自动当作互相矛盾。

问题须由完整原文对照确认；先排除合理解释，区分已实现事实、正在推进、预计和目标。不能把更新文章中的预测当作新近已实现结果来否定回答。证据不足时不生成问题，组件调查、Session 均允许空问题列表，不设类别或问题数要求。

原文明示的计划、目标、预测、推进中、已完成状态被读错时选择实现状态识别。状态理解正确、仅对其影响的推测语气过强，才选择置信度校准；不能用宽泛置信度条目代替明确的状态误读。

代码核对的是引文与原文相同，不替材料内容背书。被评回答的自述只能证明模型说过什么；事实、执行状态和计算方法仍须对照工具返回、实际代码、执行结果或用户条件，不能拿回答自身的“事件重叠”等自述作事实依据。

## Session

`attribution/session` 使用有序 Trace 总结、问题概要、必要原始 QA 与原文补读入口，新增独立跨轮问题和整体总结；逐轮归因由程序原样回填。跨轮问题只选择 Compact 联合目录编号，证据映射回原始消息；单轮 Session 不调用模型。

## 程序边界

- 组件任务按 Compact 目录固定绑定检查对象，不预设问题或责任；Trace 仅摘要合并结果，Session 只选择跨轮问题的既有目录编号。
- 关键观察用 evidence 选号，程序回填固定的 {evidence_id, quote}；key_data 直接复制所选终稿原文，不重写数字和单位。调用计数仅由程序填写，模型摘要不另写共N次或第N次调用；元信息和完整最终回复直接透传。字段来源先筛选再分配预算，保留完整短文与长文完整句段，预算不足时少写，不机械切首尾。组件的长命令另保留真实脚本和 skill 的原文导航。
- 同一条完整 evidence_id 的原文在归因材料中只展示一次，重复处保留编号及来源；相同文字来自不同消息或范围时仍分别保留。该精简只作用于模型展示，不改写正式 compact 或归因结果。
- 组件调查、Session 共用[问题表达与严重程度规则](../packages/prompts/resources/attribution/problem-output.md)。所有新生成描述使用中文，尤其 label/definition；不增加语言校验、语义复审或润色循环。
- 组件任务由程序绑定 Compact 目录；Session 独立跨轮问题从联合目录选择已有编号。组件按[逐组件核查规则](../packages/prompts/resources/attribution/component-choice.md)。每条问题独立核对要求、实际动作和交付影响，不沿用上一条的责任、不强求类别分布；用户条件误读、具体数值动作、事实补写、内容转写、结论一致性分别定位。终稿引用未绑定选择引用绑定，有替换前后记录才能定位引用标签替换。不以缺值和成功状态同时出现推定服务错误，原因不明时不编造工具契约。
- 恢复提示只说明本任务的错误路径和修正方法，Compact、Attribution 不接收 Comparison 的候选槽位规则。静态提示文本在进程内复用；来源整理按输入记录共享，关键数值按需提取，不建立跨运行正文缓存。
- Compact 与 Session 各自接受后立即正式落盘，Trace 为内部任务。恢复通过收据、持久化任务 UUID 和 JSONL 行号关联，不重复保存摘要正文。
- Compact 失败暂缓本 session 的归因，其余 session 继续。流程与正式输出结构见 [Session 归因](attribution.md)。

component 只表示实际责任组件；不再生成静态责任类别。程序按 Compact 目录绑定独立组件任务并按目录顺序汇总，正式 component 直接沿用该槽位目录的职责或真实名称，失败环节在问题描述中定位。正式输出结构不变，问题描述定位具体错误步骤。会话生成脚本的代码错误定位该文件；调用参数错误定位参数生成环节，shell 执行异常须有运行环境或执行证据。被额度守卫强制结束不等于主动停止；必要质量检查不自动视为预算浪费。

候选SQL、规划草案和实际执行分开核对；没有执行依据的片段不作为已发生故障，不以另一段SQL替代字段契约。草案已改正且无残余影响时不单独定责。
