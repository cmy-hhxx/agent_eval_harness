# 实施计划与验收口径

本次目标是用本机最新稳定版 prime-agent 评测已有回答，得到可关联、可恢复、符合 demo 3.1 的两两比较记录。配置、提示词、schema 和控制代码分别维护。

## 1. 核实环境和输入

- 核对安装的 prime-agent 与官方稳定版；记录版本、二进制路径和 SHA256。每次新运行要求最近 24 小时内完成检查。
- 使用 uv 管理 Python 和锁定依赖，初始化 Git。
- 按 `batch_id + case_id + version` 建立输入索引；禁止按行号拼接。
- 拒绝重复输入、问题冲突、标准答案冲突和缺少最终回复的记录。没有某个版本，只跳过涉及它的组合。
- 保留 A、AA 不同的原始链路结构，建立轻量适配器，不重写原始输入。

验收：当前 37 份有效回答、14 个 case、2 个批次，形成 34 组比较，50 个缺失组合单独记录。四份输入中的有效记录数为 8、9、11、9。

## 2. 两阶段评测，减少重复工作

- 第一阶段：仅有标准答案的 case×版本调用 `gpt-5.4-mini`，只传问题、标准答案和最终回答。
- 第二阶段：`gpt-5.6-luna` 比较两份回答及其可查阅链路，复用冻结的正确性结论。
- 无标准答案按主观题处理，不调用第一阶段；正确性字段为 null 和空字符串。流程状态仅进入审计元数据。
- 同一输入的独立正确性只计算一次。缓存键包含输入、模型、提示词、schema、程序和 prime-agent 指纹；比较阶段额外绑定正确性结果。
- 固定种子分配候选 A/B，程序保存实际版本映射，降低固定位置偏差。

验收：当前只需 2 次独立正确性判定和 34 个比较任务；35 份主观题回答跳过第一阶段。默认不使用 sol。

## 3. 由协议约束输出

- 通过 prime-agent 扩展注册 `submit_evaluation`，在原生请求层设置 `strict: true`，要求工具调用并关闭并行工具调用。
- 身份、批次、版本、trace、正确性结论均由程序填充，裁判只判断胜负和具体优缺点。
- 证据用已有 `ref` 选择器提交；schema 按候选限定合法编号。程序恢复原始 `message_index + quote` 并逐字校验。
- 本地工具只提供本题消息读取、检索、内嵌图片和数值计算。独立正确性阶段不开放历史读取工具。
- 对显式倍数、比例等问题，双方分别计算后才开放提交工具。
- 无效提交返回具体问题，有限修复；只把验证成功的结果写入业务 JSONL。

验收：字段符合 demo 3.1；引用来自对应候选的原始消息；无越界、错配、编造引文和主观题流程旁白。

## 4. 调度、速度和故障恢复

- 默认并发 8，单任务总超时 300 秒，流式静默 45 秒后重试，临时故障额外重试 2 次。
- 有效终止工具回执到达后立即收尾，不等待额外的自然语言回复或会话结束事件。
- 首轮保留完整最终回答和有上限的链路材料，其余按索引读取；不自动压缩上下文。
- 增量原子写入结果，使用运行锁；支持阶段运行、恢复和失败重试。
- 每个 run 使用独立 daemon socket，结束时关闭所属后台进程；不依赖全局共享 daemon 的会话状态。
- 每次调用保留 prompt、原始 RPC 事件、工具提交、约束协议、耗时和模型返回用量。密钥只从环境变量读取。

验收：中断后不重复成功任务；旧缓存缺少审计目录时不复用；网络失败不伪装成平局或答错。

## 5. 交付与质量调优

- 输出六份按无序版本对分组的 JSONL，实际候选位置以行内 models 为准。
- 每次比较在同一次严格提交中补充具体任务要求、得分点、red flags 和原始回答耗时分析；程序复用 verdict/findings 生成逐题 JSONL 与 Markdown 总结。
- 问题明细包含原始问句、对象、日期/区间、口径和核心要求。每项优劣势指出具体内容、差错/缺项和影响，提供对应原文，不能只写抽象形容词。
- 原始回答的首 token、首回答、完成时间从输入 meta 读取，按可配置单位换算；缺失保留 null，不用裁判耗时替代。总结保留候选到真实版本的映射。
- 附正确性记录、跳过清单、失败清单、汇总报告和校验结果。
- 自动验证输入快照、候选关联、schema、原文引用、重复配对、结果数量和跨配对正确性一致性。
- 新版只重新运行固定 5 条比较，另有 2 次必要的 Mini 判定，不启动全量评测。旧试跑输出及失效缓存删除，原始输入保留；清理明细见 cleanup.md。
- 运行 Python 测试、pyright、Node 扩展测试；记录真实批次的耗时与重试，完成初版 commit。

需要区分两类验收：结构和证据完整性可自动检查；裁判判断质量只能结合抽查确认。当前题量较小，不把试跑胜率当作总体模型排名，也不把格式通过率当作判分准确率。
