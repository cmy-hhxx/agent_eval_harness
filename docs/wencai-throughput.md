# 问财归因吞吐实验

从 main `4eafbf7b` 开始。正式归因输出和统计上传 Schema 保持不变；问财日常跑四路输入、Fast/Expert 各自 A/B 对战，专项仍跑独立 Attribution。

## 固定对照

`configs/benchmarks/wencai-atomic-c20.json` 固定 2026-10-27 的六个问题、24 条回答、12 场对战，包含历史终稿超时和代码执行长尾。原始输入仍在来源目录，只保存业务 ID。两轮使用同一个网关、deepseek-v4.1-flash、low 推理、20 并发和相同超时/修复预算。实验串行运行；不与另一轮叠加至 40 并发。服务器其他生产任务的资源争用须作为限制报告。

目标：完整 session 吞吐至少为基线的 2 倍，组件任务 p95 不超过 300 秒，固定样本无归因超时阻断。逐项复核关键问题、责任组件与原文证据；不得以删除问题、丢弃长样本、放松校验或改变正式输出换取性能。该小样本达标仍不能证明全量质量非劣。

```bash
node dist/apps/host/src/cli.js preflight --config configs/host.json --config configs/benchmarks/wencai-atomic-c20.json
node dist/apps/host/src/cli.js run --config configs/host.json --config configs/benchmarks/wencai-atomic-c20.json --run-id <新ID> --test-eval --debug
node scripts/attribution-throughput.mjs /mnt/fin_bench/eval_data/0_wencai/eval_output/test_eval/<新ID>
```

模型凭据与统一日志目录通过服务器既有环境配置加载。`--debug` 只用于本次工具循环、模型时间和证据审查；所有产物在来源的 `test_eval/`。汇总同时报告所有未完成状态、组件/trace/session/对战完成数、首条产出、完整结果每分钟、已结束任务累计 p50/p95、实际有记录的 attempt 模型时间和工具数。已完成样本的耗时存在选择偏差，不能忽略未完成长尾；暂停造成的 cancelled 不算模型失败，coverage 不等于执行成功率。

## 原子审查

每次真实工具请求和可可靠关联的返回构成一个审查任务；每次中间模型调用独立；终稿按完整原文章节划分，短章节合并。所有范围保存原始坐标，不复制输入。任务首屏给出该调用参数/返回或该终稿章节的可提交引文及引用来源；完整原文仍可按需读取。trace 等待所有范围，统一问题 ID 后汇总；session 接受后立即交付。

已规划的同 run 归因单元保持其恢复边界和 UUID，不因更新程序而重新展开、重评已接受工作；新的 run 使用原子规划。正文子章节独立划分，长资源保持完整审查范围，超长原文首屏仅展示 1600 字并提供精确续读入口。当前实验实现为 r423。

调用审查首屏优先展示本次参数和返回的可读原文，按 400 字生成可直接引用的连续片段，总量有界。默认执行目录只列出本次消息及直接相连边界；定向消息、证据和关键词查询仍能补查上下文。调用审查的默认文本搜索限定本次消息并返回搜索范围，终稿主张仍可按关键词检索所有原始来源。不按数据集或模型名称分支。

组件到 trace 是“结束后汇总”的依赖，只有成功、失败或超时可放行；排队、执行中、暂停取消不能冒充完成。成功组件保留原问题，失败组件不产生虚构空结果；trace 明确未核查范围，收据的 incompleteDependencies 记录并传播接受时的缺口。其他必须成功的依赖不放宽。人工补跑不清空已付出的预算，也不悄悄改写既有汇总。衡量完整归因吞吐时排除带缺口的接受结果，部分结果单列。

提示词清查覆盖 Attribution、Criteria、Comparison、Score、Instruction Review、Clustering、Rewrite、Eris、共用材料、工具描述及错误修复反馈。删除“组件名称由程序提供”“其他会话负责”“程序回填/绑定”等内部实现说明，保留可执行的审查对象、字段含义、证据边界和提交动作；撤回 r422 的图表专用提示，不添加问财或 AIME 专用判断规则。材料占位也只说明内容未提供，不再暴露内部评审流程。

## 质量与基础设施验收

归因质量优先于吞吐。逐项核查问题是否成立、责任组件是否有因果证据、引文是否属于被评回答或相应工具来源，并单列误报、漏报及未核实范围。main 结果不是人工金标，代理审阅不能冒充人工标注。AIME 另用 `aime-quality-c20.json` 复测已有语义案例：买币意图不强加行情查询、译文语言缺陷、真实空返回、已标日期与来源日期冲突的区分；使用当前清洗输入，不能只依赖历史 r407 的审阅结论。

`scripts/attribution-material-benchmark.mjs` 单独测量真实输入的材料准备与保留，无模型调用，不代表完整 200 Worker 压测。r424 在 AIME 四条输入中等距选取 20 个不同组件：准备约 96.1 秒，读取记录 20 次，传输序列化共 82,330,401 字节，峰值 RSS 1,534,058,496 字节。计划 200 个的试验在第 60 个触发 GC 前的 2 GiB heap 保护，准备约 129.7 秒，其中绑定约 108.0 秒、目录构建约 102.1 秒、准备校验约 20.5 秒、序列化约 0.9 秒；GC 后保留 heap 约 1.10 GB。不能据此宣称 200 会话通过。后续脚本在阈值处先 GC 再判断保留量，避免把可回收的瞬时垃圾当成稳定占用。

同一 AIME Expert 轨迹的 business_chains 序列化约 135,254,300 字节，原始公开材料约 5,112,177 字节；组件请求重复携带完整关联材料，提交校验并不使用它。r425 将组件内部请求缩小为身份与范围，保留原始证据和工具导航，正式输出不变。同时每个输入集合只保留最近一个解析记录，命中也校验源文件修订；轨迹目录按源消息数组共享，原始对象释放后可回收，不保存跨 run 评测结果。新增复用、切换逐出、源文件变化拒绝、证据及隔离回归。真实并发与最终质量效果仍待验证。

运行时验收只执行确定性契约规则，不用自然语言启发式充当语义裁判。移除组件描述的占位词黑名单、相似措辞和重复语义拦截；保留结构、字段、引用身份、原文坐标、读取证明和数值范围等合法性检查。语义准确性单独离线审阅，不自动重开来源结果。观察脚本单列首个 attempt 首次提交即接受、内容修复后接受及提交计数未知；不能把重试后的成功率当首次成功率，也不能用降低语义抽审标准换吞吐。

r425 的材料压力实验使用 200 个不同规划任务，在 189 个时达到 GC 后 2 GiB heap 保护：原始记录实际读取 4 次、输入访问 189 次，准备 22.668 秒，保留 heap 2,147,260,032 字节，峰值 RSS 2,402,611,200 字节。读取复用已生效，200 个任务仍未全部通过。导航已只携带坐标；r426 删除 Host 准备阶段对不可变导航的逐任务深拷贝，实际 Worker 副本与模型历史仍需另测。

AIME 质量 run `aime-quality-r425-c20-20261028` 预检通过（4 sessions / 24 components），以 20 并发运行。首条完整结果已经暴露质量失败：`thread_c4ab4b58f4ac4c319514251b960f9caf` 将买币指令推导成必须查询行情，并因没有工具返回而否定助手陈述能力限制的依据。这些是待纠正的误报，不能因为首次提交接受便认为语义准确；不得添加案例专用规则或在线语义重试来掩盖。
