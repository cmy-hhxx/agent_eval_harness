# 问财归因吞吐实验

当前资源验收同时记录 Host 与全部 Worker 后代的 RSS、匿名页、文件映射页，机器级 Cached/Buffers 单列且不归为本 run 消耗。真实会话脚本统计实际模型额度占用积分、等待积分及有排队却未占满 20 额度的时间；记录已观察后代的退出残留、CPU/IO 累计值、固定结果/状态/SQLite/WAL 文件大小、检查点与 outbox 峰值，不扫描整个结果目录。进程每秒采样，文件每 30 秒和退出时采样，短时峰值仍可能漏测。

## 原子审查

每次真实工具请求和可可靠关联的返回构成一个审查任务；每次中间模型调用独立；终稿按完整原文章节划分，短章节合并。所有范围保存原始坐标，不复制输入。任务首屏给出该调用参数/返回或该终稿章节的可提交引文及引用来源；完整原文仍可按需读取。trace 等待所有范围，统一问题 ID 后汇总；session 接受后立即交付。

已规划的同 run 归因单元保持其恢复边界和 UUID，不因更新程序而重新展开、重评已接受工作；新的 run 使用原子规划。正文子章节独立划分，长资源保持完整审查范围，超长原文首屏仅展示 1600 字并提供精确续读入口。当前实验实现为 r423。

调用审查首屏优先展示本次参数和返回的可读原文，按 400 字生成可直接引用的连续片段，总量有界。局部输入目录和经调用标识、参数原文确证的直接关联提供精确读取坐标；不再构建全局责任图。调用审查的默认文本搜索限定本次消息并返回搜索范围，终稿主张仍可按关键词检索所有原始来源。不按数据集或模型名称分支。

组件到 trace 是“结束后汇总”的依赖，只有成功、失败或超时可放行；排队、执行中、暂停取消不能冒充完成。成功组件保留原问题，失败组件不产生虚构空结果；trace 明确未核查范围，收据的 incompleteDependencies 记录并传播接受时的缺口。其他必须成功的依赖不放宽。人工补跑不清空已付出的预算，也不悄悄改写既有汇总。衡量完整归因吞吐时排除带缺口的接受结果，部分结果单列。

提示词清查覆盖 Attribution、Criteria、Comparison、Score、指令遵循归因、Clustering、Rewrite、Eris、共用材料、工具描述及错误修复反馈。删除“组件名称由程序提供”“其他会话负责”“程序回填/绑定”等内部实现说明，保留可执行的审查对象、字段含义、证据边界和提交动作；撤回 r422 的图表专用提示，不添加问财或 AIME 专用判断规则。材料占位也只说明内容未提供，不再暴露内部评审流程。
