# 评测工作台产品契约

[返回首页](../README.md) · [界面规则](../PRODUCT.md) · [数据服务](../server_dashboard_ths/README.md) · [运行与恢复](usage.md#运行与恢复)

工作台围绕收到数据、清洗、评测、定位失败、查看结果和按需聚类组织。本文维护已确认的产品行为；具体已开放的操作和接口以数据服务与使用指南为准，不把产品要求当成已实现接口。

## 对象与范围

- 任务有持久化 UUID、名称、来源和评测类型，可包含多个压缩包批次。
- 一个压缩包对应一个工作台批次，独立记录发现、归属、清洗结果和原始位置。它不替换输入原有的 `batch_id`、`case_id`。
- 来源为 wencai、AIME、ifind，类型为日常或专项，两个维度独立。目录规则决定自动归属；无法识别的包等待人工归属。
- 一次评测运行可以选择多个批次，同一批次可以多次评测。聚类作业独立选择已接受归因，不随评测自动触发。

## 日常评测

首页同时显示「问财日常四路」和「AIME 日常全量」。两条来源各自启动、暂停、继续、立即停止和调整并发，可同时运行。打开页面、保存配置和服务重启不会启动任务；关闭浏览器后已启动来源继续执行。

问财扫描 `0_wencai/1_7z_data/A_AA_comparision_data`，稳定上传包自动清洗并进行标准、归因、比较、改写，全量处理 A/AA 的 Fast 与 Expert 有效配对，正式文件落盘并独立增量交付 MongoDB。日期和数量默认不设边界。Mongo 失败单独重试，不阻断输入安装及评测。

AIME 扫描 `1_aime/1_7z_data/online_data`，Fast、Expert 每条有效单轮回答分别执行 Score 与 Attribution。首次核对现有规范输入与两阶段收据，只补缺少阶段；多轮、缺 trace 身份、空回答和冲突保留隔离坐标和原因。AIME 不要求两模式配对，结果只落盘并由页面读取。

日常来源的统计日志生成和上报关闭。专项与手动范围操作保留在「更多」，清洗报告、任务归属和聚类继续可单独操作。

清洗整理结构、检查可评测性、规整 meta 并计算 RUED 难度分数；保留明确难度标签。原包保留，规范输入按来源组织，运行引用输入。字段口径见[标签与效率清洗](../server_dashboard_ths/docs/metadata.md)。

## 清洗与批次报告

- 缺回答、空回答、可定位的格式错误默认排除，其余记录继续，不要求逐条确认。
- 回答质量差、答非所问或拒答交给评测器判断，不作为清洗排除理由。
- 部分模型缺回答时保留其他模型和有效模型对，缺回答不计输；无有效数据不启动空评测。
- 无法解析的文件或包记录失败，其他独立数据继续。报告保留原始分母、纳入和排除数，回答、问题、对局分别计数。
- 报告提供每条排除的包、成员文件、行号、可识别的样本和模型、原因；未解析出样本 ID 时仍有原始坐标。
- 包列表与报告默认每页 10 条，可选 20 或 50 条；服务端按实际页大小读取。纳入报告只为当前页关联日常运行的当前任务和成功收据，保留改写依赖与 MongoDB 交付状态。
- 已处理包不重复自动执行；不能仅按文件名判断重复。重复记录排除并计数，业务身份冲突不静默覆盖。
- 补传包建立新批次；修订包关联原批次，旧输入与运行保留。归档不生成压缩交付包，不为展示复制结果。

## 页面组织

一级入口固定为评测、结果、更多，默认评测。评测顶部并列两个日常来源，显示状态、未完成／成功／失败、真实 LLM 请求、来源并发和操作；选择来源后默认进入总览，也可切换阶段进度、包报告和运行。结果按来源、运行与样本分页读取，分别使用 comparison 和 answer-review 正式契约。更多收拢专项、手动范围、聚类问题库和完整错误历史。页面不展示流程定义、Schema 或提示词说明。

总览使用本地 Tabler 组件与 Apache ECharts，界面统一白底与灰阶文字，去掉彩色选中底色和装饰底板。默认关注有效回答总量、完整评测、完成率，以及每日数据与当前覆盖、模式分布、评测状态和清洗排除原因。图表可以切换成同范围的精确数据表，包名保留在数据包页签。

`GET /runtime/api/daily/{wencai|aime}/analytics` 只读聚合完整来源，独立于列表分页与运行控制。有效回答和模式分布来自数据服务的已发布去重索引；清洗排除原因来自已有正式清洗报告，报告缺失时显示缺失范围，不能把未知当作零。评测覆盖来自正式接受收据；问财按可发布对局计数，AIME 按 Score 与 Attribution 均接受的完整回答计数，包含当前 watch 台账以外的既有正式运行，按真实 trace 去重，历史日期取输入业务日期。阶段任务单独统计。完成率与状态分布明确展示已纳入评测的分母，不把全量有效回答和评测范围混用。状态分布互斥，失败优先于部分完成；已接受一个阶段且另一阶段未失败才计部分完成。

每日趋势按业务日期对照有效回答量和当前评测覆盖，代表各日期数据目前完成了多少，不表示过去某天完成任务的历史曲线；问财回答与对局分别标明单位。趋势可选近 7 天、近 30 天或全部日期，以实际最新数据日期为窗口终点，起点不早于实际首个数据日期；只改变趋势范围，其他分布保持全量。缺日期、统计读取失败和历史报告缺失明确显示，打开总览不会扫描、清洗或启动评测。

问财默认 Flash high（改写 low）、并发32；AIME 默认总并发64，两阶段共享。并发实时生效，其余设置下次启动或暂停后继续时生效。保存配置不启动工作，已成功项不重评。暂停停止派发新工作并等在途收尾；立即停止取消在途并保存已接受结果。服务重启后等待手动继续。

AIME 问句、回答与阶段任务分别计数，只有两阶段都成功才显示回答完整完成；部分成功保持可见。Mongo 完成状态与问财模型评测完成分别显示。

## 错误与恢复

清洗排除、被评回答质量问题、评测器执行错误分别展示。错误页默认显示未恢复问题，按错误类别和阶段聚合，可展开每条样本与完整历史。

错误记录关联任务、包批次、文件/行号、样本、run、阶段、执行任务、尝试次数、被评模型与实际评测模型。显示原始错误、校验位置、影响范围、重试时间和恢复状态。根因未知时明确未知，恢复后保留历史。

临时网络错误有限重试；单任务持续失败只阻断依赖它的工作；鉴权、模型配置等公共故障暂停受影响范围。各层自动化不能通过重启无限补发预算。

- 继续未完成：沿用原 run 和成功结果。
- 补失败：沿用原 run，只选择失败项及必要未完成依赖。
- 重评成功结果：新建 run，不覆盖旧结果。

代码、模型、参数与评测器变化不拒绝同 run 续跑，未完成项使用当前有效配置；实际执行配置应可追溯，影响判词的修改更新 `evaluatorVersion`。

问财与 AIME 各自分配模型请求额度，分别显示实际在途任务与请求。来源暂停不影响另一来源。控制由 Host/运行层承担。

## 结果、聚类与目录

每个 run 独立保存范围、配置和结果；同 run 补跑补入原结果，新 run 不自动混合。任务默认查看最近一次运行并显示完成状态，跨批次汇总明确选择运行，重叠样本不得重复累计。

聚类只纳入选定范围的已完成归因，显示未完成数量，不重复纳入同一份归因；新增结果等待下一次主动选择。问题库每模型共享，区分本次分析范围和当前共享类。

源区保留原包和规范输入；生产 runtime 复用 `data/sources/` 必要共享快照、`data/input-catalog/` 索引和 `data/problems/` 问题库。运行产物只放在来源的 `eval_output/`：批次日常运行在 `0_daily_eval/<任务 UUID>/<run UUID>/`，专项在 `1_task_eval/<任务 UUID>/<run UUID>/`。任务与批次只增加轻量关联，清洗明细是业务结果，不复制正文。确切路径见[部署](deployment.md#目录)、[数据服务](../server_dashboard_ths/README.md#当前布局)和[运行产物](usage.md#运行产物)。

运行日志仍为 `runtime.log` 与 `evaluation.log`；完整提示词、原始模型响应等排查材料仅在 debug 下保存，开启 debug 不补造历史。统计交付继续使用冻结 Schema，不加入任务、批次或清洗字段，落盘与上传均严格校验。

## 当前批次运行操作

1. 在数据与任务勾选同一任务的已清洗批次（支持部分文件失败但有有效回答的批次），点击「评测所选批次」。
2. 在评测运行中选择引擎和并发，预检后查看回答数、归因数、对局数、被评模型、评测模型和产物目录；点击「开始评测」。预检不调用模型，输入异常或空计划不能启动。
3. 运行列表显示接受、运行、待处理、失败和阻塞数量。「样本与结果」进入既有运行详情；「错误与恢复」显示原包成员/行/项、业务样本、被评模型、阶段、执行任务、累计尝试、校验错误和未完成依赖。
4. 「重试此项」仅准备该项与必要依赖/下游；「重试失败」准备当前失败项；「继续未完成」恢复原 run 的全部未完成范围。成功结果和已用预算保持不变，后追加的输入不进入冻结范围。达到累计预算时须先调整 Host 配置中的上限；按钮不重置预算。
5. 公共故障修复后使用「修复后解除暂停并续跑」。停止使用现有 Host 停止语义，在途任务可能中断，已接受结果保留。系统崩溃或重启后可以恢复；没有 state.json 的启动失败保留启动记录和错误。
6. 错误页同样提供批次运行定位。默认显示未恢复任务，按阶段/样本过滤；勾选「包含已恢复历史」读取统一 runtime.log 中的原始失败。没有任务关联的进程错误显示「恢复状态未知」，不推测恢复。关闭 debug 时不展示不存在的提示词/原始响应。

批次范围由数据服务的清洗报告生成，固定模型、业务身份、输入文件与行坐标，不能由浏览器传任意输入路径。问财按配置的有效模型对比较；未配对回答以及 AIME/ifind 运行独立归因，不把缺回答计为输。聚类不随批次启动。

生产 `<configDirectory>/workbench-runs/<run UUID>/`保存轻量启动关联 `launch.json` 和输入配置 `inputs.json`；包含任务、包与坐标，不保存回答正文、密钥或模型响应。预检先保存输入配置，再发布启动关联；并发读取或中断遗留的未完成登记不进入运行列表，已发布登记的解析与读取错误仍明确报错。run 的 state/results/report 在来源输出目录。续跑使用当前 Host 模型与配置及原范围，不因评测器标识变化拒绝。

批次运行当前复用各 Host 的并发与重试控制，跨手动运行和自动化的统一资源队列及完整配置编辑仍属于后续工作，不把它们标为已经支持。


## 结果归档与手动分析

1. 在批次运行点「结果与聚类」，进入「聚类与问题库」并带入当前运行；也可以直接进入该模块，按任务选择一个或多个压缩包批次，再勾选运行。默认只勾选该任务最近一次已启动运行，不自动混合历史运行。批次不选时包含所选运行的全部包。
2. 点「查看所选范围」，按回答查看模型、业务批次、样本、原包成员/行号和评测状态。清单每页 40 条，可按纳入状态筛选；「查看样本」召回原运行的正式结果。
3. 清单分别统计本次可纳入、已完成分析、已占用/待恢复、评测未完成、已被较新归因替代。只在显式选择的同一任务范围内，按模型、业务 batch_id、case_id 取接受时间最新的归因；较早归因保留可查，数量不重复累计。归因未完成包括尚未建立任务的回答；比较或改写未完成不妨碍已接受归因进入分析。
4. 点「预检聚类」查看冻结归因数、聚类任务数、问题库待观察召回数和作业目录，再点「开始聚类」。预检不调用模型、不占用范围。启动在跨进程锁下重新检查，以来源 run、归因任务、submission ID 登记唯一占用；双击、并行页面或重启都不能把同一份归因登记到两个工作台分析作业。预检过期或来源收据改变会明确报错。
5. 已启动分析保持冻结来源，后续评测新增结果等待下一次手动选择。分析作业失败或中断仍占用原范围，用「继续未完成」沿用作业 ID、成功收据与累计预算。已暂停阶段在修复后显式解除；不通过新建作业绕过原任务预算。进程在完成登记前退出时也保留作业，可重新续跑。所有任务接受且报告写出、进程正常退出后才显示已完成；页面重启丢失退出回调时，可续跑补齐完成登记。
6. 作业明细展示冻结归因清单、任务状态、原始校验错误与统一日志历史、产物路径，并可逐条返回来源样本。无问题的已接受回答也算本次已分析；已纳入不等于一定创建问题类。已有待观察问题按既有聚类流程显式计数召回，问题库仍是每模型共享知识库。
7. 「产物」显示现有报告与正式 JSONL，可单文件下载；「归档」在运行停止后登记归档时间。部分完成也能归档，页面继续显示部分完成与未完成数量。归档不搬移或复制文件、不删除原始输入、不生成压缩包；原 run 再次续跑会清除归档标记，完成后可重新归档。

分析启动关联保存在 `<configDirectory>/workbench-analysis/<job UUID>/job.json`，冻结的归因和待观察引用保存在同目录 `selection.json`；不复制回答、归因正文或密钥。跨进程占用锁位于 `workbench-analysis/.claims/`。作业正式状态、结果和报告保存到所选任务现有输出目录的 `clustering/<job UUID>/`：

```text
eval_output/
  0_daily_eval/<任务 UUID>/
    <评测 run UUID>/{state.json,results/,report.md,stats.json}
    clustering/<分析 UUID>/{state.json,results/,report.md,stats.json}
  1_task_eval/<任务 UUID>/
    <评测 run UUID>/{state.json,results/,report.md,stats.json}
    clustering/<分析 UUID>/{state.json,results/,report.md,stats.json}
```

归档关联和分析占用不是跨 run 结果缓存。工作台分析入口管理通过本入口登记的作业；现有 CLI 任意路径作业不会自动注册为任务/批次作业。统一日志仍只写根 `runtime.log` 与 `evaluation.log`，不产生分析专属日志。
