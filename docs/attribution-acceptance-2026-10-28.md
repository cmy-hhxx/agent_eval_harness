# 通用归因收尾验收（2026-10-28）

## 范围与版本

本次只做收尾验收，不继续增加机制或调整任务边界。实现冻结于 `c7783d2d9503c8fc30d35dd0ced8531250157c81`（r436），分支 `codex/wencai-atomic-attribution`。严格对照使用未修改的 `7b87154a51912ef9c6221e64aa4a0f813bbeea54`（main / r420）。不合并 main，不把未通过项标为完成。

两版共用 `wencai-atomic-c20.json`、`aime-quality-c20.json`：deepseek-v4.1-flash、low、20 并发、900 秒任务预算、相同结构修复和网络重试预算，命令观察上限 1,694 秒。问财固定六题、24 回答、12 比较；AIME 固定四条真实记录。真实模型实验串行，200 会话实验仍只有 20 个模型请求额度。

问财两版的 24 条来源路径、行号、模型、批次、case/session/trace 和问题逐项相同。持久化配置仅有未启用的问题库绝对路径不同；主配置除 evaluatorVersion 外一致。AIME 四条来源及全部执行配置相同。两路实际组件 spec 的 model 和 policy 都逐项相等，来源文件修改时间均早于候选实验开始。没有复制输入、按正文去重或新增哈希。运行时没有热替换代码。

main 的 AIME CLI 在启动前错误要求至少两个输入版本，没有调用模型。因此最终 AIME 基线通过 main 现有公开执行 API 运行：规划、Agent、提示词、Host、Worker、结果仓库全部来自未修改的 main；仅用 r436 配置解析器加载同一份配置，实际执行配置已核对完全相同。它是未修改 main 评测主流程的对照，不能说 main 的单模型 CLI 通过。首次外部 stdin 启动脚本还因 `--input-type` 被 main Worker 继承而失败，改为独立 `.mjs` 文件入口后正常运行；两次启动失败均在模型调用之前，单独保留记录。main checkout 最终仍是 `7b87154a`，工作区干净。

AIME 主流程对照中，两版完整率和 10 分钟率均为 100%；r436 耗时降低 46.0%，完整吞吐提高 85.3%，每条 Token 降低 46.7%，SDK 轮次降低 21.7%。这一对固定小样本的改善不能抵消问财未提升和 200 会话 SLA 失败，也不是多次重复实验的稳定性结论。

成本包含 criteria/component/trace/session 的所有成功、失败、取消和重试尝试。问财 main 共 23,244,343 Token、815 轮、144/144 份指标；r436 共 19,753,265 Token、671 轮、143/143 份指标，其中 14 份从原 Worker 记录补齐。r436 的不成功尝试消耗 1,762,307 Token、61 轮，包含在总数中；1 次网络重试消耗 3,713 Token、1 轮。AIME main 为 2,084,138 Token、120 轮，r436 为 1,111,211 Token、94 轮，两版均有 27/27 份指标，无失败或重试消耗；r436 的 3 个结构修复尝试共 153,479 Token、13 轮，已计入。

Token 是服务返回的累计 usage；中断中的未返回用量无法推算，不能当作已知零消耗。SDK 轮次按 `turn_start` 统计，包含等待额度时取消的轮次，不等于隐藏 HTTP 重试数。比较、额外归因维度与改写单列，不归入主归因成本；有结构修复的整次尝试成本不是“修复单独消耗”。没有新增语义复核或语义重试。

## 200 个真实会话

运行 `aime-live-final-r436-s200-c20-20261028`，使用 `aime-live-s200-c20.json`：30 条真实记录（Fast 12、Expert 18），248 个组件、43 个 trace、30 个 session。按来源顺序选择可解析记录并交错两模型，6 条格式不合法输入的排除原因保存在 `sample-selection.json`；不按模型结果筛样本。

使用 25 个八槽位 Pi Worker，实际出现 200 个同时活跃或等待模型额度的 SDK 会话，模型请求峰值为 20。321 个任务全部成功：248 个组件、43 个 trace、30 个 session，正式文件 30 行，部分结果、故障、超时及网络重试均为 0。正常退出，没有已观察到的残留子进程；2,507 次资源采样无错误。

200 指实际审查 Agent 的 SDK 会话数，30 指输入记录及其最终归因结果数，两者不能混算。复现入口为 `node scripts/attribution-live-benchmark.mjs configs/benchmarks/aime-live-s200-c20.json 200 <新run-id>`。整轮外部观察上限为 5,400 秒，组件预算仍为 900 秒；现有调度额度等待不消耗组件执行预算，但全部计入本报告的墙钟时延及 10 分钟提交率。

## 恢复、身份与契约

Comparison 的原缺陷已按“四条正文完全相同、外层 case_id 不同”复现为只有一行。修复 `4e3f5ee7` 用持久化任务身份和正式行引用贯通写入、读取、检查点和恢复；回归现在得到四行、四份正确关联收据，两次恢复不重评、不重复、不覆盖。相同 session 下不同 trace、不同模型和批次的八行隔离回归通过。该缺陷验证不使用补齐 meta 的样本替代。

当前真实 r436 已接受结果的规则验收通过：问财 89 个组件、19 个 trace、19 个 session；AIME 19 个组件、4 个 trace、4 个 session。原 Worker 提交 ID 与 Host 收据关联后，108 个组件的原文证据合法性检查通过，23 条正式记录元数据与输入原样一致。模型材料不包含传递用的元数据。首次离线检查脚本查找了已被清理的 pendingSubmission，随后改查原始事件；初次失败记录保留，不能记为产品故障或语义复核。

问财 r436 原始观察窗结束时 Host 已退出，但当时 state.json 仍是 running、没有 finishedAt，并遗留 run 锁；因此正常停止验收失败。原始停止状态与观察窗指标已记录。没有证据支持把根因归为 OOM 或 timeout 工具；独立信号小实验也不能替代真实 Host 复现。本次不以猜测补丁更改程序。

最终 r436 两次同 run 恢复均通过：AIME 使用真实 CLI，10.778 / 11.173 秒，27 份收据、所有尝试数及 4 行正式 JSONL 字节完全不变。问财使用真实 Host 的恢复与检查点路径，并预先取消派发，15.878 / 17.419 秒；138 份收据、所有尝试数、19 行归因、5 行比较、6 行标准结果均原样保留，13 份未完成核查状态中的 1 份草稿及 1,159 条证据不丢失，没有重评、重复或覆盖。该问财样本没有 inspection 对象，核查证明的冷恢复另由定向回归覆盖。

问财恢复后状态正常登记为 interrupted；这证明可以恢复保存，不能反过来抹去原实验停止未收尾的失败，也不代表重新完成了其未结束的评测任务。原实验吞吐仍使用恢复前封存的观察文件。两路证据分别保存在 `resume-observation.json`。
