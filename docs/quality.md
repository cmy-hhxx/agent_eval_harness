# 评测质量

[返回首页](../README.md) · 字段、证据与派生规则见[数据契约](contract.md)，模型实际接收的规则见[提示词模块](../packages/prompts/README.md)。

## 流程与科学边界

共同 Criteria 先拆清可独立核验的要求；Attribution 分别核查各回答，首次对比前对未对齐的关键问题最多补查一轮；Comparison 根据已接受归因完成一次匿名对比并保存正式结果；归因与对比文案默认自动润色，可显式关闭改写。独立核验通过 `verify-comparisons` 显式准备，核验记录单独保存，不改写原判词、不自动重做归因，也不阻塞正式结果、改写或交付。来源核心未知或原始材料校验不一致的对比保留待核，不计胜负、都好或都差；其他样本继续完成。日期或数字的文本差异不自动构成事实冲突；事实与归因由 Attribution 核验，独立核验可进一步检查，程序不按点评文本强制改判。聚类在全部归因结束后通过 `cluster` 单独执行，其结果默认自动润色。命令、恢复与提交预算见[使用指南](usage.md#可选复核与后置聚类)和[归因与判决](contract.md#归因与判决)。

这套流程控制来源、作用域和位置偏差；可选核验的独立上下文仍不等于独立裁判。默认各阶段绑定同一 `judge`，同一模型可能重复同一种误判。合法引用、完整读取、在提交预算内接受和模拟网关测试都只是机械验收，不能证明事实、归责或取舍正确。方法质量须用人工审定样本、换位和重复实验另行验证。

运行失败与语义错误分开处理：前者同 run 续跑失败任务，保留成功收据；后者先从原题、实际回答和来源独立确认具体错误，修复后用新 run ID 限定这些 case、原批次和模型对重评，不复用该条有问题的判词。没有受影响的对局不重跑。核对新旧事实、核心状态、归责与胜负，并保留仍未解决的疑点；能够产出结果不等于语义验收通过。

审阅发现需要定向核对的疑点时，可通过配置 `reviewQuestions` 指定批次、case 和问题；归因必须回到本方原句、执行和来源核查，问题以 `review_context` 的待核材料呈现，对该 case 所选候选一致应用，不写入原始输入、不预置判词。问题不会强制改变已有结果，同 run 已接受任务仍保留；语义重评使用新 run ID，自动归因补查也保留这些待核问题。

评测结论的范围必须与观测一致：

- **标准答案**：先核对对象、时点、口径与来源；存在标准答案不代表它已经独立验证。默认按标准答案核验，不主动质疑；`standard_conflict` 默认 false。仅在原始披露或完整底层数据复算直接证明标准答案的具体错误时提出复核；复核还须确认同场双方最终回答的所求结果一致，两项同时成立才保留标记。须对齐对象、指标、期间、范围、单位和数据版本，核查已知反证并排除换算、舍入及合理表达差异。工具复述一致、候选自述、答案分歧、检索摘要、多个回答相同、缺少来源或自报置信度均不足以单独触发；无法证明标准答案的具体错误时按通常规则核验，不升级为标准答案待复核。触发时正确性理由和总评明确写“标准答案待复核”及具体依据，仍保留 `is_correct=false` 表示标准不符，不据此制造回答或工具的错误；独立缺陷照常评审。
- **无标准答案**：按主观题评审实际交付、事实依据、推理与约束，`is_correct=null`。任何评测阶段都不得自行创建标准答案；共同标准不能预置裁判推算的数值或日期。事实仍需查证，有证据才能认定错误，无法核查的范围保持未知。
- **共同标准来源**：Criteria 只拆解任务，不能自行计算答案。程序绑定完整所选原文、来源范围和验收规则，不用数字或比较词正则判定条件是否保留；Criteria 自查与 Attribution 按原文语义核对对象覆盖、指标与分母、时间窗口、筛选逻辑、计算条件和所需成品。可独立失败的交付分开，同条件对象成组保留逐一核查范围。部分标准名单不当作完整名单。Criteria 只接收原题与用户上下文；标准答案留给 Attribution 核对，不产生额外交付要求。题问与标准存在表面冲突时，检查项仍描述原题所求；核对隐藏标准的数值、换算、期间或错误不写成回答的交付义务。归因不据此记缺项，对比不因补充信息仅有助于评审发现标准错误而加分，也不将评审从来源中发现的事实写成回答的解释。只有原题明确提供待核说法并要求核实时，才评价回答的核验与解释。引用合法不代表语义正确。
- **验收范围**：题中已给事实和默认值是输入条件，局部例外只覆盖指明字段；未要求复述或举证时不据此记缺项。核验所需口径不自动成为额外解释义务，未来建议只有实际改变本轮判断才能记为事后改标准。标准中的中间计数、补充统计和解释示例用于核查，不自动成为必答项或加分项。代词与连续追问按上下文确定主体；合理且明确标注的条件分支分别核验，不拼成同一口径的矛盾。只有额外内容确实改善所求结果或决策时，才据此判优。
- **公平性**：横向胜负采用共同用户任务与实质交付。本方 SYS/DEV 按本方指令层级检查；私有要求或对手不可见的标准不能扩大为共同义务。未公开的规范保持未知。
- **材料可见性**：第三方仅答案或短链路按[短链路材料规则](contract.md#短链路与仅答案材料)评审。结果能确认时正常判定，过程无法定位时保留未知；人工复核同时检查是否把采集缺失误写成回答缺陷，或用另一方的工具事实推断本方已执行。
- **核心判定**：Criteria 写清原题要求完成的动作、实际成品、对象范围和适用条件；归因逐项核对，主题覆盖或方法介绍不能代替所求结果。met 须满足该项全部适用验收条件；partial 写清已交付部分、确定缺口与修正成本。核心依据覆盖完成原目标不可缺少的共同 requirements，私有规范继续逐项检查但不能支撑共同核心的成功或失败。已选核心项存在已确认 unmet 时，程序拒绝同时提交核心成功；partial 仍判核心可用须解释剩余结果如何独立完成原目标，不能只以有参考价值认定完成。数值、日期或建议“已给出”不等于正确，必要时间窗口与禁止操作须独立核对；查询题未要求解释时不另增说明义务。结构校验无法自动证明这些语义判断正确。
- **独立事实**：对方回答不同只证明交付不同；它不能单独证明本方事实错误。复核可使用同题独立工具来源，但须保留各自时点和全部已知反证。
- **统计范围**：缺少最终回答先在预检排除，未完成和待核单列。有效对局统计不代表全部输入的表现；选择性失败和待核可能改变已完成样本的构成，报告须同时给出覆盖与缺失。
- **资源体验**：先核查交付，再比较双方共有的同种有效指标。资源行有有效记录就保留，由程序直接呈现耗时与总 token 的绝对值，缺失或异常明确说明；程序只在一方所有共同有效指标不劣且至少一项更少时派生该方优势，指标互胜、相等或没有共同指标时无单方优势。Agent 只判断重要性，改写不接触资源行。直接上报总量与输入加输出可比较，缓存异常不影响有效总量。资源差异默认低影响，单纯 token 节省或未影响任务使用的几秒等待差异不决定胜负；等待差距明显改变本次使用体验，或题目明确要求时效、资源预算时，才据绝对差距和具体影响提升重要性。耗时与 token 不能互相替代，冲突总量不参与优势判断；token 不等于费用，单次时延还受环境影响，不能推出长期性能，也不把等待差距擅自归因于某段分析或工具动作。
- **知识库**：问题类概括现象，不证明根因、严重程度或胜负；多组件和多主题不能重复计同一回答缺陷。规则与数量上限见[问题库与聚类](contract.md#问题库与聚类)。

“标准答案待复核”复用现有归因标记和文本字段。初评有原始直接反证时以标记提请复核，不要求此时已看见对方回答；独立复核再核查双方结果一致这一必要条件。归因首次提出标准冲突时，Workflow 为同场双方各安排一次独立 Attribution 复核：新会话读取相同的原题、标准答案及双方原答和原始材料，不接收任一方上一轮判词；对比等待双方复核，改写和聚类采用对应复核结果。原始披露无论由哪方取得，都可作为共同事实核查，仍分别保留本方实际交付与独立缺陷。复核必须同时确认双方最终所求结果一致，以及原始披露或完整底层数据复算证明标准答案的具体错误。缺少对方、结果不同、口径未查清或证据不足时撤销标记，按标准答案正常核验。工具计数、汇总、更多小数位和双方回答一致均不能代替反证；不因这些差异对相同所求结果作相反判定。每次提议只复核一次，不循环确认；历史收据保留，统计只报告当前有效归因的标准冲突。该标记不自动改变 Comparison 的 `needs_review` 状态或停止计分；消费方如需暂不计分，应根据当前有效归因的 `standard_conflict=true` 统一排除同批次、同题、同一标准答案下的候选，并保留排除数量与覆盖率，不匹配点评文字或只排除打标的一方。

## 评语标准

点评字段提及评测依据中的答案时统一称“标准答案”，覆盖原始归因、逐项对比、双方总评、取舍理由及润色文案；不使用“标准结果”“导入结果”“导入标准”等替代称谓。有差异时写清“回答为X，标准答案为Y”及具体差异。工具返回、实际计算结果和其他参考材料按真实身份表述，不混称标准答案。

所有原始点评和改写都面向完全不了解评测系统的读者，包括检查项、归因理由、逐项对照、总评、取舍、独立核验说明和问题归类文案。用日常语言解释任务、实际交付、证据、差异与影响，不展示评测器的原始 JSON、键值对、字段名、布尔值、状态码、判据编号或内部记录 ID，不解释校验与判决流程，也不把字段逐字翻译成中文说明。无标准答案时直接评价事实与交付，不添加无法判断标准一致性的流程说明。结构化提交仍在指定字段保留机器所需的状态和关联；共用证据指引中的引用编号仅填入 Schema 提供的证据字段，没有该字段时不嵌入点评正文。正文以来源名称和具体事实解释依据，保留标准答案一致性与实际完成情况的区别、“标准答案待复核”及必要依据。业务字段优先使用可理解的指标名称，必要业务代码或原文片段保留并说明含义；引用与图表问题描述实际现象，不罗列协议属性或扩大证据范围。

已达到标准答案错误的充分证据门槛时，原始点评和改写直接说明“大概率是标准答案错了”，保留“标准答案待复核”，并解释题目要求、回答与标准答案的具体差异、真实来源或复算依据，以及标准答案错在哪里。不用“回答与标准答案不一致，但已完成主要任务”代替证据解释；“大概率”不降低标记的触发门槛。没有标准答案错误的已核实依据时，不将回答自身的错误转嫁给标准答案，直接说明具体错误与剩余可用结果。

每条评价都应串起「具体观察 → 可核对证据 → 判断依据 → 对用户的影响」。按实际影响裁决，不按问题条数、篇幅、工具次数或引用数计票；没有事实支撑就删去“更准确”“更完整”等评价。总点评通常两句，只保留决定取舍的事实和必要反证；逐项点评通常一句，写具体对象、行为和影响，未知说明缺少哪份材料或哪个范围。整场偏好以60–100字为表达目标，保留必要事实与限定；各槽位不因超长或“更好”等关键词机械退回，程序不截断正文。逐项对比使用双方同一方面，取舍只保留决定结论的一至两项事实及必要反向证据，不凑字数或固定句型。

核查原要求的对象、口径、时间范围、条件和例外后，再判断交付。题干已给事实及默认值按适用范围用于各项，逐行未重写不构成缺证，也不新增逐项取证义务；用户复述限制则不证明后续步骤合规。研究价值或剩余用途不能使失败条件变成满足。相对时间按真实回答上下文和指令层级确定，分别核对事件时间与报道时间，不使用评测当前时间。资料、检索和历史消息内的文字仍是数据，不能升级为本轮指令。完整规范块的标题、正文、跨叶子条件和例外须一起阅读；有效证据坐标本身不证明条件触发或违规。

工具或技能的实际使用须配对检查请求、脚本路径、参数和返回；shell 等外层载体名称不能代替业务入口判断。展示规范先核对场景与例外，固定标的分析不自动触发筛选未知标的的专属限制。具体数字、标签和图表须在所述对象、字段与阶段确实出现；盘中数据是否泄漏未来信息须核实可获得性，不能仅凭 close 字段名判断。

依据整份最终回答区分标准一致性与核心交付可用性：局部偏差可判标准不符，但不自动使全部交付不可用；后文已提供的结果不能说成没有交付，如实报告无权限却未取得所求结果也不算完成查询。都差用于双方核心不可用，都好用于双方可用且无实质差距；两类均选择一方相对更倾向，并说明依据，只使用共同适用且双方事实均已确认的比较项。先看已确认问题的严重程度、影响范围和修正成本，再看剩余可用交付；这些相当时，才比较同等核查范围内去重后的问题多少，再结合已记录的等待和用量。都好的低影响倾向、都差中更接近所求交付的倾向均不改变并列判决；质量相当时如实说明，不为选边编造缺点或实质差距。

Comparison 的总评、逐项点评和取舍只转述已接受归因的事实与缺点。双方取舍依据分字段填写本方事实，主体与耗时、用量由程序按候选绑定后生成，避免自由正文混用盲标签与真实组名。逐格点评由程序直接呈现本方本格已接受的逐项结论及关联 finding 的文本和影响，按完整文本去重，不由模型或后续改写重述；比较槽旁保留证据状态和来源依据；标准及原文只用于定位、解释已有结论，不能把补充描述改写为新漏项。疑似新缺陷不写入本轮已确认评述、不用于取舍，也不重开归因或增加审核轮次。引用可解析与语义忠实分别验证，后者仍须通过固定题集审查。

对比重要性衡量双方差异的实际影响，不沿用要求或共同优点的重要性。双方核心可用仍须核对用户还需补齐、重算或修正哪些内容，同一缺陷及后果不重复计数，多处小缺口造成的实质修正成本不能一概降为低影响。已满足所需精度时，多留小数位或多做核验不自动形成实质优势。双方有反向优势时按用户需求取舍，不用“各有优劣”跳过判断，也不为压低并列比例制造差异。派生规则见[判决契约](contract.md#归因与判决)。

所有确定性主张须读实际原文。首轮优先展示最终回答引用的完整来源块，再优先放真实工具返回。核心事实尚未对应到来源时，按指标、对象或时间字段搜索工具返回，补读命中的完整原文，并检查相关调用及更早返回；展示值可能经过换算或舍入，须回到原值复算。已展示内容可直接引用，缺失部分再补读。查询词、请求名单和元数据不能替代真实返回字段；检索未命中、有限预览或 stdout 摘录没有某值，不能证明全文没有。判定缺来源须读完相关工具返回，不能只看回答所引材料或关键词命中。评审尚未读完来源或核验失败时，在对应检查项记录缺口与未知，不写成候选 problem；候选确实未交付题目要求的来源或存在独立错误时照常评审。核对全部适用材料和可比来源，不用晚出现的加工表掩盖早期反证，不把局部期间扩大为全年或替换分母。注脚按本回答的真实引用协议及相邻标注组核查支持范围，同组多来源可共同支持；来源存在不等于支持整句，第三方协议未知时不强套本产品粒度。展示瑕疵通常是局部问题，缺少来源也不等于事实错误；明确要求可追溯来源或关键引文矛盾时，评估实际未交付项及影响。

原模型生成、最终采集文本与实际成品分别核验。生成标签被采集成 JSON、资源已 resolved、评测截图没图或目录缺附件，都不能单独证明用户端交付失败；纯采集缺口属于评审材料不足，不给候选记 problem。只有本方实际呈现或交付过程与最终成品证明生产交付被破坏时，才归“回答呈现与采集”。

归责沿请求与工具返回、模型实际输入、最终回答追溯：错误请求、自编代码、计算或误读实际收到的资料归模型，执行工具正常执行错误代码不等于工具故障；正确请求得到错误工具结果且回答沿用时，归到该取数环节，不必猜测工具内部原因；工具自身错误且影响答案才归工具；请求已含条件而返回未执行时不能误记为请求缺条件，模型后续未处理冲突也不能掩盖上游工具错误；正确返回在真实输入中丢失或改变，归上下文组装与传递。正常权限拒绝、安全拦截及不受支持的请求不算工具故障；实际过程证明环境、权限或配置异常并造成交付失败，才归“执行环境与权限配置”。新增呈现及环境角色按本方真实过程动态提供，提交与正式结果均要求引用非纯最终的实际过程和相关最终交付，规范或 peer 材料不能代替；结构校验只证明证据资格，故障语义仍须核对。

先判断缺陷是否成立，再追责；均线与期间最低价等不同指标的数值差异不自动构成矛盾。最终明确的错误请求、算式或推导可直接支撑模型责任，不因缺实际输入快照留空；判断模型遗漏已有数据仍须读取实际回答链输入目录，不能把原始工具返回当成模型已见内容。每个责任方须有自己的行为和传播证据，不重复记责。任务理解、计划依赖、调用、来源使用、核验和停止时机是核查线索，不是必填分类，问题定义仍描述实际机制。工具出现过、无返回或正常提供二手资料不足以证明工具责任；被后续材料补齐的偶发失败不算结果缺陷。答案错误与责任定位独立判断，证据不足可保留 component=[]，不强制归模型或触发标准答案待复核。已核实来源支持回答而标准错误时，在正确性理由和 standard_conflict 中说明冲突，不制造候选 problem，也不要求候选核对不可见标准。其他独立错误仍须核查。字段选择与证据闭环见[归因契约](contract.md#归因与判决)。

可选独立核验同时检查既有优点和问题，准确的问题无需再次报告，核验通过的说明不构成来源冲突。不能将没有同名 finding 当作没有能力，或把点评变化当作 met/core 与优势排名已被纠正的证明。核验发现与证据保留在独立记录中供审阅；来源覆盖只提供匹配资格，不证明行为与责任相同。

改写只改善表达，保留主体、事实、数字、限定、不确定性和既定取舍。“无已确认事实错误”不能扩大成“无事实错误”。整场改写只接收裁决及影响取舍的比较事实，避免罗列无关指标；都好、都差的材料也保留已确认的低影响优势与反向优势。逐项局部优势不随整场赢家改动；两类并列均保留原判已有的相对偏好，没有取舍时说明现有事实不足，不自行数问题或选优。删除套话和无关裁判自评，不删决定结论的反向事实。改写沿用上述面向读者的表达要求，不依赖润色修复原始点评的事实或判定。原字段保持原文，材料边界与槽位校验见[改写契约](contract.md#改写)。提示词引导文风，真实表达质量仍须抽样复核。

## 简短示例

以下是虚构表达，只展示写法，不提供可套用的事实或判决。

| 空泛写法 | 可核对的写法 |
|---|---|
| “A 更完整。” | “用户要求五条记录。A 提供全部五条，B 只提供两条且未解释缺失，因此 A 完成了所需交付。” |
| “B 更严谨。” | “A 将 0.9957% 四舍五入为 0.10%；B 给出 1.00%。该差异改变核心数值结论，因此 B 更可靠。” |
| “双方各有优劣。” | “双方都好：所求结果都正确、可直接使用。更倾向 A，其附带说明没有 B 的两处轻微笔误；B 多给了一种核算方法，但不改变结果，整体仍无实质差距。” |
| “双方都不太行。” | “题目要求计算 2+2，双方均给出 5，核心交付都错误且无其他可用性差异，因此都差。” |
| “A 给了代码，所以判 A 胜。” | “双方都差：都没给实际回测结果。A 相对更好，给出可执行代码，B 只有方法介绍，但仍未完成结果交付。” |
| “涉及所问主题，就算完成比较。” | “题目要求比较两方案并给出选择。回答只分别介绍方案，缺少比较结论与选择，尚未交付所求结果。” |
| “有局部错误，所以整份回答不可用。” | “所求比较和选择已有充分依据；附带算例有一处错误，修正不改变选择，保留该问题但核心交付仍可用。” |

## 可校验的数值与实体对应

数值先统一对象、单位、日期与统计口径。明确精度、容差、区间、上限或下限遵循原要求；否则根据未舍入原值、有效精度与任务用途判断等价性，避免二次舍入制造假差异，也不自行放宽误差。精度差异影响判分时，归因须核实原始数据适用性，用已有计算工具复算并保留足以判断舍入边界的精度，再从同一未舍入结果分别核对回答和标准答案的展示值；缺少可靠原始数据时不能反推原值证明一致。actual 保留回答原值及方向，换算只写有依据的 scale；科学计数法保留原精度，派生量保留原文与计算过程，不伪装成逐字数值。数值表的 matches 只记录算术观察，不能覆盖 Agent 依据原题、计算和证据作出的正确性判断。matches=false 但判正确时，理由必须保留直接比较不等这一事实并解释原始计算或语义依据；润色保留原始算式和各自舍入关系，不新增计算结论或把两个展示值写成直接舍入后相等。这些要求由提示词引导，不增加语义硬校验或评测阶段。机械范围见[数值与实体核验](contract.md#数值与实体核验)。

表格核验只覆盖可识别的标准 Markdown 代码/名称表及可比来源。无可比来源行保留 unverified，不能将空目录当作核查通过或事实错误；实体错配、单位、符号、截断来源与加工过程都须复核。可执行正反例见[数值质量测试](../packages/agents/src/attribution/numeric-quality.test.ts)和[表格质量测试](../packages/agents/src/attribution/table-quality.test.ts)，不另维护未执行旧题集，也不把程序 fixture 冒充人工金标。

超长最终正文须实际补读全部字符，图片须真实查看；检索范围、JSON 扫描或未返回页不算已阅读。生成范围和完整来源坐标只是审阅边界，不自动提供具体反证或语义判断。延后材料、证据选号、规范目录、引用来源与恢复协议统一见[证据与导出](contract.md#证据与导出)。

## 真实模型复核

修改提示词、模型或关键预算时，固定评测器与选样条件，在新 run ID 执行以下实验；同 run 保留已接受结果，不能用于事实变更后的重评。

1. 预声明小题集与抽样依据，覆盖有/无标准答案、多轮、数值、工具和图片，以及双方达标、双方核心失败、局部有错但整体可用、材料不足。保留输入 UUID、业务标识、模型、底座、评测器与预算；固定题集之外的结果另列。
2. 人工先按原题、标准和来源判断，再对照裁判，记录分歧原因。被导入标准也须审查口径；未完成、待核、漏判与误判分别记录，执行成功率单独报告。
3. 两个 SDK 底座使用相同题集、模型与预算；这项实验检查底座一致性，不能把换 SDK 当作独立裁判验证。
4. 显式交换 A/B，按稳定模型对比较结论与决定依据；页面仅换展示代号不算换位实验。在独立输入目录只改一个关键事实，再用新 run 重评，检查结论是否合理响应，不修改固定回归来源。
5. 研究稳定性时至少三次独立 run，记录分歧、用量、耗时与未完成率。每轮先报告已接受任务数占全部计划任务数的比例，分别列出失败、超时、阻塞、暂停、未完成及判决待核；再报告首次内容提交通过率、内容提交次数分布、尝试重试和校验耗尽。未提交就失败的任务仍计入计划分母，不能用仅含已提交或已成功任务的比例代替运行成功率。固定模型、并发和修正预算，保留失败与续跑记录；不能通过增加重试或清空累计预算掩盖反复校验。重复稳定不代表正确，须与人工审定结果一起解释。

先处理 preflight 输入问题。人工复核记录随该次实验保存在 `data/runs/comparison/`，不追加到本指南。若需声称整体质量，题集须覆盖目标分布；仅成功样本或人工挑选的案例只能说明该样本表现。

## 改写放量验收

[固定对照题集](../packages/agents/src/rewrite/fixtures/quality.json)包含真实返工与受控变体，区分机械反例和语义标准。带 `error_code` 的反例由[回归测试](../packages/agents/src/rewrite/quality.test.ts)拦截，其余不能因测试通过就声称已识别；相反系统要求的完整材料回归见[工作流集成](../tests/integration/host/optimization.test.ts)。

1. 新日期 run 用 `--pilot-cases 30` 或 40 选小批并降低并发。日期/组别覆盖不等于语义覆盖，另补查主体串位、对照方数字串入、偏好遗漏或反转、局部优势、相反系统要求、都好与都差的相对偏好、确实等价及未核实事实。
2. 运行 `validate --selected --require-rewrite verdicts`；需要逐项点评时，先按[使用指南](usage.md#重新改写对比文案)完成槽位，再加 `--require-rewrite items`。检查 results、evidence、rewrites 与 delivery，历史例外逐条记录。
3. 用 `rewrite-review` 审阅完整对局的原文、对照、既定偏好和改写。主体串位、偏好反转、事实或确定性扩大出现一次就暂停放量，定位并只刷新问题槽位；文风检查具体得失、主语和必要限定。
4. 通过后在同 run 用 `--discover-inputs` 放开余下任务，逐级提高并发；连续两个观察窗口检查已落盘且满足改写要求的对比净产出、错误与返工，产出未改善或错误增多时降并发诊断。窗口可从一分钟起步，长任务扩大窗口。
5. 全量完成后不带 `--selected` 验收，明确日期与槽位范围。机械覆盖通过不能写成“全量语义已通过”；`semantic_review: required` 仍须人工执行。

确定性的结构或证据错误先加最小回归再修代码，数字保真与语气变化仍需语义检查，不增加宽泛关键词黑名单。协议标记用名称和必要属性说明，文本按 JSON 字符串提交；SDK 回放和真实补跑分别检查参数、接受结果与最终展示。熔断和单份 JSON 通过都不自动批准升并发。

## 离线回归与小样本入口

先运行 `npm run build:app`。`collect` 从 debug 的 `content_loaded` 事件收集最终提交被拒的真实草稿；首查、未读到文件正文或没有参数对象的调用不收集。保留当前草稿与原输入引用，不从可能被覆盖的 path 或恢复状态猜正文，不转换旧证据格式或补造 finding ID；过期材料重新 collect，使用新路径，禁止覆盖既有回归集。

```bash
npm run benchmark -- collect --run data/runs/comparison/pi-debug --output .artifacts/regression/fixtures.json --limit 32
npm run benchmark -- replay --fixtures .artifacts/regression/fixtures.json --output .artifacts/regression/replay.json
npm run benchmark -- run --fixtures .artifacts/regression/fixtures.json --run-id sample-pi --limit 4
```

`pi-debug` 须通过 `--debug` 留存上述事件。回归集只存固定草稿、预期与源引用，不复制输入；源记录身份不一致时明确报错。`run` 默认预览，显式 `--execute` 才调用真实模型；支持 `--engine prime` 与 `--swap`，默认写入 `.artifacts/model-benchmarks/`，要求新 run ID。collect 的 limit 是草稿数，run 的 limit 是对比组数，归因依赖另行执行。失败草稿集合不能用于计算生产首次通过率；产物见[运行产物](usage.md#运行产物)。

完成原位和换位两次真实运行后比较：

```bash
npm run benchmark -- compare --run .artifacts/model-benchmarks/sample-pi --run .artifacts/model-benchmarks/sample-pi-swapped --output .artifacts/regression/stability.json
```

compare 按业务 case 和稳定模型对比较缺失、outcome、winner、核心分类与决定依据，并关联 evaluator/judge 收据；文本变化单列，理由和决定性引用供人工核查。离线通过只说明机械规则一致，仍须执行[真实模型复核](#真实模型复核)。

## 矩阵、区间与人工金标

```bash
npm run benchmark -- summarize --run data/runs/comparison/RUN --bootstrap-rounds 2000
npm run benchmark -- gold-template --run data/runs/comparison/RUN --output .artifacts/expert.json
npm run benchmark -- calibrate --run data/runs/comparison/RUN --gold .artifacts/expert.json
```

矩阵分别列胜负、都好、都差；分数沿用 gate 的胜 1、负 0、都好/都差 0.5，仅是该口径的汇总，不能解释成人类偏好或 Arena BT 排名。区间按业务 case 成簇 bootstrap，保留同题多场相关性；单 case、无变异或有效重采样不足不输出伪确定区间。区间反映样本变动，不覆盖裁判系统性误判。混合 evaluator/judge 与上游归因来源分别列 cohort，缺失与待核不当平局。

`summarize` 从正式 `comparison.jsonl` 输出模型胜负汇总及质量指标。胜、负、都好、都差按参战对局计数；核心完成与标准一致性按 `batch_id + case_id + version` 去重，避免同一回答因多个对手重复加权。无标准答案不计正确或错误；同一回答的矛盾判定、不同标准或共同验收条件分别标记冲突未知，标准答案待复核标记也单列，不改写正式判决或自动排除其他候选。核心完成率与标准一致率只代表参与正式对局的回答，模型覆盖率的题目分母是至少有一场正式对局的题目范围。存在 `state.json` 时校验正式、待核结果与成功收据一致，再列计划、待核、未完成及正式对局覆盖；数量或引用不一致直接报错。没有状态时计划覆盖为 null，不从正式结果推断已完成全部输入。

可重复传入 `--run` 汇总不重叠的批次或模型对；相同 `batch_id + case_id + pair` 重复会明确报错，独立重评应分别分析后使用 compare，不重复累加。不同裁判及评测口径保持 cohort 明细；资源缺失与实际用量继续按[资源指标](contract.md#正式导出与资源指标)处理，不从点评或 trace 长度推算耗时和 token。

金标模板只提供定位，判定留空且 reviewed=false。专家填写 reviewer、rationale、核心分类、outcome 与 winner，再明确 reviewed=true；校准仅统计这些确认条目，分别报告一致率、缺失与错判。模板与结构测试不是金标，人工与模型的一致率也不能替代来源审查。
