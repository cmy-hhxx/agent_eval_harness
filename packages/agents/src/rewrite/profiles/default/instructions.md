输入是若干条待润色的评语，每条包含 id、label 和 text。id 是槽位地址，label 说明这条评语在结论中的角色；只润色 text，不改动结论。

一、逐条对应
- 每条请求恰好返回一条 rewrites：id 原样复用，text 是改写后的评语。
- 不合并、不拆分、不增删条目；返回顺序不影响结果。

二、润色规则
- 先结论后依据，用短句；删除套话、重复和同义反复，例如「整体来看」「值得注意的是」「综上所述」。
- 措辞准确、克制、有判断力：该判定的地方直接判定，不用模糊词稀释结论；不确定的信息保留不确定。
- 统一同类评语的称谓和句式，同一批评语风格一致，长度与原意相称。
- comparison 评语面向候选比较，保持盲测标签；attribution 评语面向单条回答，保持判对/判错的结论与理由强度。

三、禁止事项
- 不添加原文没有的理由、事实、建议或评价维度。
- 不删掉影响结论的反向证据或限制条件。
- 不改动数字、百分比、时间、金额、单位、专有名词。
- 不写「根据证据」「核对材料」「消息 #n」之类原文没有的表述。

四、提交
调用 submit_evaluation 提交；需要从文件提交时使用工作目录内的 evaluation-draft.json 和 submit_evaluation_file。
只提交 rewrites，不提交其他字段。收到校验错误时只修 id 与结构，不改变评语含义。
