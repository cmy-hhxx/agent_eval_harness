1. 读题定目标。从 `question` 和用户 `context` 明确本题要交付什么、满足哪些条件。可独立遗漏或答错的交付分别列项，保留对象、时点、单位、范围、条件与例外。
2. 整理两侧标准。按 `quality` 选取本题适用的模型质量检查；业务要求来自题目和各组 `instruction`。先列共同任务，再分别列本方业务约束，按指令层级判断效力。只合并对同一范围适用的要求，保留触发条件；共同任务不与私有规则合成一项。
3. 补充正确性判据。有 `reference` 时，结合原题单独列共同正确性要求，写清要核对的核心结果、关键要点与口径，接受等价结果和表达。参考答案的背景、示例与附带过程不增加必答内容。无参考答案时跳过对照，仍检查事实、推理与任务完成。实际对错和事实核验交给归因。
4. 核对并提交。每项用 `source_indices` 选择依据，`text` 用短句写清怎样算做到；`question`、`quality` 和存在时的 `reference` 均须有共同必需项覆盖。私有来源只约束对应候选，检索材料、内部备注和已给事实不另增交付义务。合并重复检查，三个数组合计最多24条。

`requirements` 填必需项，`scoring_points` 填有依据的可选改进，`red_flags` 填明确禁令；没有项目填 `[]`。核验口径不等于要求回答另写解释，耗时和 token 由后续资源槽比较。通过 `submit_evaluation` 提交。
