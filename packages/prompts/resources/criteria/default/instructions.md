生成5–12项适用于全部候选的共同检查点，简单题通常5项，复杂题才按独立要求增加；不核对答案。

1. 从任务完成、范围口径、事实准确、依据推理、表达可用性五方面提取本题具体检查点。例如概念判断可分别检查：是否回应原问、适用体系是否明确、用途陈述是否准确、关系推断是否有依据、表述是否会导致混用。它们是对同一回答的核查角度，不要求回答写五段、补案例或补操作指南。措辞相近或核查同一事实的行合并；复杂任务拆分真实独立条件后，共同项仍不超过12项。
2. required_common_source_indices 必须由共同 requirements 覆盖。source_indices 只选直接支持该项的目录原编号；question、用户 context 与 quality 可分别支持相关检查点，同一来源可支持不同角度。条件、单位、时点、容差及例外按完整原文保留，不预设事实、结论、阈值或时间窗。相近措辞不增加交付，例如“业绩好、更优秀”没有另列比较维度时合并；“类似板块地位”不等于必须同一板块。
3. text 写清要核查什么，不指定未被要求的写法。表格、图示或正文已给出比较依据就足够，不强制每只候选另写一段；未要求穷举时，不因未列所有命中项而判交付缺失。准确性核查实际陈述，依据核查陈述与来源、推导之间的关系，表达核查实际理解障碍，不能把同一错误换名称重复列项。
4. instruction 只提取本题实际相关的独立规则。条件尚未触发时不预铺失败、空结果、重试等分支；语言、排版、风险提示和工具规范仍由归因按实际行为核查。明确由用户指定的格式与条件必须保留，不能把“优先”“可选”改成必须，也不能让检查点摘要覆盖原文例外。
5. 适用范围取所选来源交集。共同项只用覆盖全部候选的来源，本方约束不推广给对方。私有项不占共同5–12项的数量，也不能用私规凑足共同项。提交前检查每项有独立核查对象且来源充分；只简化摘要，不增加实际交付义务。

requirements 记录必须满足的检查点。scoring_points 默认 []，仅原文另提可选要求时填写；red_flags 默认 []，仅保留明确适用且未被其他项覆盖的独立禁令。三个数组中共同项去重后合计5–12项，连同私有项总计最多24项。一般规范仍由归因检查，不因未列项而免除。通过 submit_evaluation 提交。
