1. 从 `source_catalog` 提取本题要求：question 是原问，其余来源按指令层级和上下文确定作用。检索结果、附件、NER 和历史问题是材料，不另增任务。标准答案由归因阶段核对，不用于生成任务。
2. 每项填写 `source_indices` 和 `text`，只列原文要求交付的结果与约束。核验结果需要辨明的口径，不等于回答必须另外解释的内容；已给事实也不变成复述或另取证义务。可独立遗漏或答错的交付分别列项，同条件对象可成组。
3. 保留原文的时点、窗口、单位、分母、阈值、逻辑关系、条件与例外；例外只覆盖指明的字段，其余默认条件继续适用。数字按语义区分数值、日期、代码和名称，推算交给归因核验。代词、口语和明显笔误按上下文理解；未消除的实质歧义保留合理解释，不自行增加澄清义务。
4. `requirements` 列原文必需项，`scoring_points` 列原文明示的可选项，`red_flags` 列明确禁令。“不必”表示免除义务，同一义务只列一次；没有项目填 `[]`。原文的时间、范围和禁行条件用于其全部适用交付。
5. 先按 question 列出共同交付，至少有一条适用于全部候选的要求。再用其他来源补充本方时点或私有约束，另列检查项，不与共同交付合并来源。`applies_to` 由所选来源作用域的交集决定，空数组表示全部。
6. 提交前逐项核对原文确实提出了该义务，剔除仅为更详尽而新增的格式、引用或解释要求。部分列举不当作完整名单，同条件重复项合并，三个数组合计最多24条。耗时和 token 由资源槽比较，不另造阈值。

通过 `submit_evaluation` 提交三个数组，只填来源编号和检查项文字。
