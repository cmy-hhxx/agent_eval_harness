先读 `items`、`library` 和 `budget`。O1、O2… 是观察编号，C1、C2… 是问题类编号，P1、P2… 是组件编号，A1、A2… 是回答编号；归入已有类时填写当前完整类名 class_label，编号只用于目录维护，不凭记忆猜选 C 编号。只以 established_answer_ids 中的编号计算已确认支持。引用沿用材料中的编号，component 填组件名称。

1. 每条 item 在 assignments 中恰好出现一次。相邻编号、相同名称前缀不代表同类；每条都依据自己的 definition 与 finding/reason 判断，提交前逐项核对选择，不能把连续编号成段套用同一个类。先固定 item.component，再从该观察的 definition 与 finding/reason 中找出属于该组件的直接错误动作。同一原发现可能同时描述工具返回问题与模型使用问题，各组件只按自己的责任片段归类。对照同一组件下最接近的类及其相邻类的定义、排除条件、别名与 examples。命中排除条件就改选相邻类，不只按标题中的相似词归类；有具体适用类时不放进宽泛事实类。日期问题先区分来源日期转述、查询窗口参数与日期关系判断，再匹配实际覆盖该动作的类；数值计算或内部矛盾优先核对计算类，引用指向错误不当作指标含义误读。示例来自已接受原归因，原文引文与引用只帮助追溯，不重做归因。现象及适用边界相同才选择该 class_label，组件别名视为同一组件。检查本次涉及的近义类；budget.consolidate=true 时检查整个同组件目录，收紧过宽定义并合并仅措辞不同的类。
   归入已有类必须满足定义中的触发条件，不能只匹配“遗漏”“筛选”“规范”等共用词。例如，筛选口径有歧义但按所述口径执行，不等于口径与执行不一致；已返回具体事实却未采用，应使用遗漏已检索事实类，不能放入普通交付缺项。不能把用户没有明确要求的内容推断成必须交付，也不能把缺少核验推断成事实已错。一个观察含多种现象时，选择其中有明确依据、符合定义且最具体的错误动作；只有日期/期间专类的定义确实包含来源期间转述时才优先使用；日历类若只收星期、先后、时区或开休市判断，就不能吸收把2025年报抄成2026年报的来源转述错误。没有任何类同时满足动作与触发条件时保留待观察。
   budget.assignment_only=true 时目录已固定：只提交 assignments，new_classes、merges、class_updates 均为空；依据当前完整目录重新匹配，不能沿用历史“支持不足”的理由跳过已有合适类。无适用类仍保留待观察，不为提高覆盖率强行归入宽泛类。
2. 没有合适类时考虑 new_classes。component 沿用观察所属组件，已有组件优先使用目录 label。label 用普通读者能懂的短句，直接说哪里出了什么问题；“事件回应”“回答质量”等主题或任务名不能充当问题类，须描述具体可观察的缺陷及对象，必要时说明后果，例如“遗漏事件时点，导致受益股判断错位”，示例不构成固定格式。definition 说明可复用的行为、触发范围、可见结果和不包括什么，不能把单题实体、日期、数值或未知成因写成新类别。有已有类时，closest_existing 选择最接近的 C 编号，novelty 说明实质差异；无已有类时省略或填 null，说明新现象边界。新建通用类时，逐一排除已有专类的范围；日期、阶段、数值、转写或查询条件已有专类时，通用的“误读”“推理错误”不能再次吸收这些样本。新类只概括排除这些范围后仍有共同错误动作的观察。
3. 遵守 budget：新增类数 ≤ max_new_classes，合并后活跃类数加新增类数 ≤ max_classes；新增组件数 ≤ max_new_components，组件总数 ≤ max_components。每个新类至少覆盖一条观察；将这些观察的 established_answer_ids 去重，独立已确认回答数须 ≥ min_support。同一回答多个 finding 只计一次，uncertain 不计支持。min_support 只限制新建类；已有合适类即使本批仅一条或只有疑似样本也应复用，并保留证据状态。低频或只有疑似样本且无适用现有类时，用 deferred_reason 说明待观察原因，不硬塞其他类别、不合并不同现象凑支持数。
4. 同组件近义类用 merges 合并，into 为保留类，from 为被合并类，写明理由。每个 from 只出现一次，与所有 into 分离；观察归入保留类。合并后仍遵守 max_new_classes。用 class_updates 修改保留类的名称、定义或主题，每类一次并说明 reason。
5. 目录固定为“责任组件 → 问题方向 → 具体问题”三层。category_paths 只填写一个方向，例如 `[["指令遵循"]]`，不重复组件、类名或再加子方向。方向用简短单行纯文本，禁用 `< > [ ] { }` 和控制字符。同一类只放一个方向；全目录整理时为所有保留类统一方向，已有多层路径用 class_updates 改成一个方向。
   - “模型自身推理”下优先复用：指令/计划遵循失败、意图—计划错位、无效调用、数据与工具输出误解、虚构或无依据的信息、计算与逻辑错误、结果表达与交付。指令/计划遵循失败指已明确的要求或计划未被执行，包括遗漏要求和越界增加操作；意图—计划错位须有理解用户目标或约束错误的依据，不能仅因结果不好倒推计划错。无效调用涵盖工具选错、参数格式或必填参数错误、查询范围不符、调用顺序或次数违反要求。数据与工具输出误解指可用信息正确而模型读错字段、日期、对象或含义。虚构或无依据的信息指引入、改写事实或作出可用材料不支持的断言与推断；明确的算术、比较与逻辑矛盾归计算与逻辑错误。已生成内容未正确展示、引用或交付归结果表达与交付。按直接错误动作选择一个方向，不因同时违反规范而重复挂类。
   - 区分模型不会使用工具与工具返回有问题：错误请求、自编代码或误读正确返回属于模型侧；请求正确但返回错误、缺少应有内容或连接不可达，沿用原归因的具体工具或执行组件责任，方向使用工具返回错误、工具返回不完整或系统故障。工具调用载体的名称不能证明工具自身出错；分别依据已有归因描述和示例，不在聚类中改变责任组件或补造根因。共同责任仍分别保留在各自组件下：工具类概括返回或执行本身的缺陷，模型未检查、未补取、计算错误或断言过强由模型侧类描述。正确请求却返回另一日期、对象或指标时，先匹配相应错误返回专类；成功返回但缺少所需字段或覆盖才归不完整类。超时、连接失败与成功返回部分内容分开；只沿用可见失败现象，不推测上游根因。
   - 只有“所需工具不存在或客户端不支持”的证据时，具体工具组件下可用“能力不可用”方向，不写成工具返回错误或系统故障。模型误称完成仍由原归因的模型侧问题单独归类。改变查询或筛选条件、绕过规定取数入口、未按要求原样发出首次查询分别核对：入口类只收路径错误，原问类只收语义未变但违反原样传入要求的行为，一般取数改变对象、时间或筛选条件放入条件类。已有图表专类时，生成图表所用的日期、序列或覆盖范围与要求不符优先归图表类，即使错误表现为生成请求参数不符，也不能仅凭“参数/时间范围”归入一般查询条件类；图表调用入口违规仍归入口类。
   - 用户意图欠明确、意图不受支持、护栏触发描述信息、能力或执行条件，本身不自动成为问题。只整理原归因已确认的不当处理：应澄清却擅自假设可归意图—计划错位，明知无工具仍宣称完成可归虚构或无依据的信息；正常拒绝或权限拦截不归工具故障。已有过程证据确认环境或权限异常时才沿用该责任组件整理，不为凑方向新增问题；没有样本的方向不建立空类。
   - 全目录整理不能只修改 category_paths。逐类检查名称与定义，仍有抽象名称时须在 class_updates 同步提交 label 和 definition：例如“汇总数据被用来推断具体参与者行为”可写成“仅凭成交或持仓汇总就断定谁在买卖”，“技术分析缺少要求的结构验证”可写成“技术判断缺少要求的多指标或跨周期核验”；实际用词须依据该类样本和边界。definition 用一个代表性短例解释边界，保留适用范围，不将示例限定成唯一场景。已经明确的名称可以保留。合并仅措辞不同的类；修复动作或适用条件不同的类保留，归入同一方向即可。
   - 相同直接错误在不同模型中采用相同方向。违反指定工具入口、查询参数、顺序或次数的调用归“无效调用”；缺少要求的分析步骤、应有内容或指定表达顺序归“指令/计划遵循失败”。“结果表达与交付”用于产物已经生成后的引用、呈现或文本破损，不作为所有格式要求遗漏的兜底方向。

本批归类依据 items 描述与示例，目录整理依据 library 定义、边界、别名和代表样本。count/established_count/uncertain_count 仍是发现次数，不是独立回答支持数；使用 established_answer_ids 的并集判断新类支持。待观察保留原发现及理由，后续增加独立已确认样本再归类。疑似与已确认可归入同一现象类，保留各自状态。label、definition 和主题用完整名称说明问题；业务型号和错误码按原文保留。

assignments.item_id 填 O 编号；每条在 class_label、new_class_index、deferred_reason 中只填一个。class_label 精确复制本条组件下已有类的 label，不填方向名、别名或编号。先核对所选类名和本条错误动作是否对应；例如图表参数错误不能归用户风险画像，免责声明不能归筛选口径。无适用类时明确延期，不将“不允许新增”理解成必须选一个已有类。new_class_index 是本次 new_classes 的零起始位置，多个观察可归入同一位置。closest_existing、merges.into/from、class_updates.class_id 填 C 编号。

通过 submit_evaluation 提交完整结果，按反馈修正后重新提交。
