1. 逐项比较。
- 使用共同 task_analysis 和双方已接受的 Attribution 结果；按 comparison_slots 的 accepted_assessments 和 observations 对照已有结论、问题及影响，保留归因和核心状态。总评、逐项点评和取舍依据的缺点只转述本方归因已确认的问题、逐项或核心结论；未确认的新疑点不写成缺点、不用于取舍，也不重开归因。
- 来源共同核心为未知时保留待核；共同核心已确认时，过程或责任未定位只在相关点评说明，不单独请求整场复核。
- 按 comparison_slots 的数量和顺序填写 `comparisons`，仅 optional=true 且无实质差异或无需展示时填 null。普通行只填 importance 和可选 better_candidate，双方点评由程序直接呈现本格本方已接受的逐项结论与关联观察；resource 行只填 importance，原始数值与优势方向由程序派生。
- scope=source_only 只写本方合规，better_candidate 省略或为 null；scope=pair 从 advantage_candidates 选择有事实支持的一方，无优势时省略或为 null。
- importance 衡量双方差异的实际影响，不沿用要求或共同优点的重要性：high 改变核心结果，medium 影响局部结果或实质修正成本，low 不改变结果或决策。
- 对已确认的缺口，核对用户还需补齐哪些所求结果、重算哪些内容或修正哪些结论；双方主要结果可用不代表这些差异都是 low。同一缺陷及后果合并考虑，多处小缺口合起来造成实质修正成本时按整体影响判断。
- 双方结果可用、精度达标且无实质修正成本时，措辞偏好、等价表达和额外解释按 low；判中高优势须说明用户因此少做了哪项必要操作、避免了什么错误或获得了什么所需结果。

2. 核对依据。
- 对齐对象、时点、单位、口径与条件。核对隐藏标准由评审负责；只有原题要求核实给定说法时，才评价回答的核验与解释。标准中的补充统计、示例和中间值不自动成为必答或加分项；附加信息须改善用户所求才构成优势。
- 原文和标准用于定位、解释已有归因，不从中追加缺点或把标准的补充描述变成新的回答缺口；归因没有认定的问题不因原文可见就视为已确认。评审从来源中发现的事实，不写成回答已经作出的解释。已展示原文可直接核对，缺失部分用 read_trace 补读，图片用 view_image 查看；引用按本方协议判断。
- numeric_checks.matches 不代替正确性；结合原条件、correctness_reason 和原始计算核对单位、精度、容差和区间。双方结果已确认等价且满足原题时，更接近标准答案的写法、更多小数位或解释不构成实质优势；判优须指出实际改善的结果或使用成本。
- 已接受归因标记 standard_conflict=true 时，在相关点评与取舍中写“标准答案待复核：大概率是标准答案错了”，保留具体来源或计算依据；标准不符不能单独证明回答错误。各方事实分别核验，不将本方标记推写给对方，不自行改判或声称停止计分。

3. 比较资源并作出取舍。
- 资源槽由程序同时呈现完成耗时与总 token，缺失或异常按记录标明；不影响胜负也保留本行。
- 资源优势仅在一方所有共同有效指标都不劣、且至少一项更少时成立；指标互相胜出、相等或没有共同有效指标时无单方优势，以资源槽的 advantage_candidates 为准。
- 按 resource_metrics 和 comparable_metrics 比较。直接上报的总 token 与输入加输出可以对比；缓存缺失或字段名不同不构成口径冲突，缓存量不重复相加。总量异常依据 original_answer_usage.issues。耗时表示本次等待，token 表示记录用量，不直接代表费用或长期性能。
- 取舍说明快慢与用量差异的实际影响，不抄写资源数值或另算节省百分比；各方原始耗时与用量由程序附在本方依据之后，两项优势相反时分别说明。仅陈述已记录的等待差距，没有证据不把耗时差归因于某段分析或工具动作。
- 资源差异默认 low。单纯 token 更少或短回答间几秒的等待差异，未影响任务使用时不决定胜负；等待差距确实明显改变本次使用体验，或题目明确要求时效、资源预算时，才可升为 medium，并在本方取舍依据写明实际影响。high 须影响明确的核心时限或交付条件。
- 核心可用者优先；双方核心不可用时判都差。双方核心可用时，根据共同适用方面已确认的中高重要性单方优势取舍；没有实质差距时 preference 省略或为 null。
- 双方核心可用时，整体胜出须显式填写 preference，并有该方中高重要性优势支持；仅有 low 差异时保留都好。提交前对齐 importance、better_candidate、preference 和双方取舍依据：理由认为差异不足以分胜负时，相应差异应为 low；确有决定性差异时，偏好和理由选择同一方。
- 都好、都差在 relative_preference 选择更倾向的 A 或 B，并在双方取舍依据中解释选择，仅使用共同适用且双方事实均已确认的比较项：先比较已确认问题的严重程度、影响范围和修正成本，再比较剩余可用交付；这些相当时，才比较同等核查范围内去重后的问题多少，再结合已记录的等待和用量。都好可依据低影响差异选择，都差说明哪方更接近所求交付，保留反向优势和共同失败边界。质量相当时如实说明，仅依据已确认的弱差异表达倾向，不编造质量差距。相对偏好不填成用于整体胜出的 preference；非平局时 relative_preference 沿用胜出方。
- 顶层 a_summary、b_summary 只概括本方已接受归因的结果、缺口及未核实范围。a_tradeoff、b_tradeoff 各用一句说明本方影响取舍的已确认事实、相反优势和必要修正，不提另一方、不写候选称谓或资源数值。程序分别补上双方主体与实际资源，平局再补所选相对偏好；正文不再写“无偏好”或重复表态。单方未关联观察留在本方总评。
