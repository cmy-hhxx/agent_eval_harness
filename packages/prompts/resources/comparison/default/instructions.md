1. 逐项比较。
- 每格只写该项已有的关键差异或等价结论，通常一句即可；不把双方完整归因再复制一遍，不为凑优缺点重复登记正常完成。保留来源的条件、确定性及实际修正成本。
- 使用共同 task_analysis 和双方已接受的 Attribution 结果；按 comparison_slots 的 accepted_assessments 和 observations 对照已有结论、问题及影响，保留归因和核心状态。总评、逐项点评和取舍依据的缺点只转述本方归因已确认的问题、逐项或核心结论；未确认的新疑点不写成缺点、不用于取舍，Comparison 不自行重做归因。
- 决定胜负前，仅对拟用的决定性中高优势或核心失败作一次成立核对：归因反驳的是回答实际命题吗，遗漏是否真是原问义务，双方是否按同一门槛比较？综合排名不能替换成各指标分别同序，表格已给出的依据不能再要求逐只正文，未选另一合理候选不能自动证明推荐错误。明确的数字错误、逐项全称断言和范围违背仍是有效依据，不因核对而一律待核。
- 已有归因的关键问题无法确认成立、且可能改变核心状态或正式胜负时，填 source_reviews：slot_index 选择现有槽，candidate 选该槽 reviewable_candidates，reason 写原文说法、归因解释及具体冲突。程序绑定原要求和 finding 并保留空排名，Comparison 不撤销、改写或新增归因。非空时 preference 省略或 null、relative_preference=null。只有非决定性的轻微疑点时，不把该格选为优势，保留限制并依据其他独立充分事实裁决；不将所有中高 finding 都送复核。不需要来源复核时省略该字段或填 []。
- 先核对双方上游是否按同一对象、范围、期间和完成门槛评审同一共同要求。scope_conflicts 只提交可能改变核心可用性、正式胜负或使主胜因失效的未解决口径冲突；选择 comparison_slots 已有的零起始 slot_index，reason 说明双方各自口径及受影响的结论。仅能选择 scope=pair 的 criterion 槽，不能选资源、私规或独立观察，不能自填 criterion_id。程序据此请求双方来源复核、保留空排名，Comparison 不自行修正归因。非空 scope_conflicts 时 preference 省略或为 null、relative_preference=null；其余字段仍按 Schema 填写。普通答案质量差距、不同已确认结果或单纯无法定位责任不等于口径冲突。局部轻微事项保留限制、该格不作优势；独立且充分的裁决依据仍成立时继续裁决，不提请整场待核。没有上述关键冲突时省略该字段或填 []。
- 来源共同核心为未知时保留待核；共同口径一致且核心已确认时，过程或责任未定位只在相关点评说明，不单独请求整场复核。已确认 core 布尔不能掩盖双方采用不同完成门槛的冲突。
- 按 comparison_slots 的数量和顺序填写 `comparisons`，仅 optional=true 且无实质差异或无需展示时填 null。普通行只填 importance 和可选 better_candidate，双方点评由程序直接呈现本格本方已接受的逐项结论与关联观察；resource 行只填 importance，原始数值与优势方向由程序派生。
- scope=source_only 只写本方合规，better_candidate 省略或为 null；scope=pair 从 advantage_candidates 选择有事实支持的一方，无优势时省略或为 null。
- 优势须比较同一对象、范围、期间和具体行为，不只比 met/partial 或 finding 数量。任务允许多种合理分析方法时，不把一方的指标权重或优先口径强加给另一方，再将方法差别改写成未确认的错误。同一事实挂在不同格时合并理解；一方已记录问题、另一方未核查该事实，不证明后者更好。缺乏同尺度依据的格不选 better_candidate，保留原状态和已确认归因，不补造对手问题；是否整场待核按上述关键冲突门槛判断。
- importance 衡量双方差异的实际影响，不沿用要求或共同优点的重要性：high 改变核心结果，medium 影响局部结果或实质修正成本，low 不改变结果或决策。判中高差异时，不得扩大来源已接受的影响范围或确定性，也不能把额外说法的可选查证变成完成原题必需的修正；潜在影响仍保留来源中的条件。
- 对已确认的缺口，核对用户还需补齐哪些所求结果、重算哪些内容或修正哪些结论；双方主要结果可用不代表这些差异都是 low。同一缺陷及后果合并考虑，多处小缺口合起来造成实质修正成本时按整体影响判断。
- 双方结果可用、精度达标且无实质修正成本时，措辞偏好、等价表达和额外解释按 low；判中高优势须说明用户因此少做了哪项必要操作、避免了什么错误或获得了什么所需结果。

2. 核对依据。
- 对齐对象、时点、单位、口径与条件。核对隐藏标准由评审负责；只有原题要求核实给定说法时，才评价回答的核验与解释。标准中的补充统计、示例和中间值不自动成为必答或加分项；附加信息须改善用户所求才构成优势。
- 原文和标准用于定位、解释已有归因，不从中追加缺点或把标准的补充描述变成新的回答缺口；归因没有认定的问题不因原文可见就视为已确认。评审从来源中发现的事实，不写成回答已经作出的解释。已展示原文可直接核对，缺失部分用 read_trace 补读，图片用 view_image 查看；引用按本方协议判断。
- numeric_checks.matches 不代替正确性；结合原条件、correctness_reason 和原始计算核对单位、精度、容差和区间。双方结果已确认等价且满足原题时，更接近标准答案的写法、更多小数位或解释不构成实质优势；判优须指出实际改善的结果或使用成本。
- 已接受归因标记 standard_conflict=true 时，沿用 correctness_reason 的确定性，保留“标准答案待复核”及具体反证、来源或计算；只有来源已明确“大概率是标准答案错了”时才保留该判断，不因布尔标记自行升级。标准不符不能单独证明回答错误；各方事实分别核验，不将本方标记推写给对方，不自行改判或声称停止计分。

3. 比较资源并作出取舍。
- 资源槽由程序同时呈现完成耗时与总 token，缺失或异常按记录标明；不影响胜负也保留本行。
- 资源优势仅在一方所有共同有效指标都不劣、且至少一项更少时成立；指标互相胜出、相等或没有共同有效指标时无单方优势，以资源槽的 advantage_candidates 为准。
- 按 resource_metrics 和 comparable_metrics 比较。直接上报的总 token 与输入加输出可以对比；缓存缺失或字段名不同不构成口径冲突，缓存量不重复相加。总量异常依据 original_answer_usage.issues。耗时表示本次等待，token 表示记录用量，不直接代表费用或长期性能。
- 取舍说明快慢与用量差异的实际影响，不抄写资源数值或另算节省百分比；各方原始耗时与用量由程序附在整场取舍之后，两项优势相反时分别说明。仅陈述已记录的等待差距，没有证据不把耗时差归因于某段分析或工具动作。
- 资源差异默认 low。单纯 token 更少或短回答间几秒的等待差异，未影响任务使用时不决定胜负；等待差距确实明显改变本次使用体验，或题目明确要求时效、资源预算时，才可升为 medium，并在 tradeoff 写明实际影响。high 须影响明确的核心时限或交付条件。
- 核心可用者优先；双方核心不可用时判都差。双方核心可用时，根据共同适用方面已确认的中高重要性单方优势取舍；没有实质差距时 preference 省略或为 null。
- 双方核心可用时，整体胜出须显式填写 preference，并有该方中高重要性优势支持；仅有 low 差异时保留都好。提交前对齐 importance、better_candidate、preference、relative_preference 和 tradeoff：理由认为差异不足以分胜负时，相应差异应为 low；确有决定性差异时，偏好和理由选择同一方。非平局时 relative_preference 必须为正式胜者。
- 都好、都差通常在 relative_preference 选择更倾向的 A 或 B，不能省略已有差异：先比较已确认问题的严重程度、影响范围和修正成本，再比较剩余可用交付；这些相当时，再结合已记录的等待和用量，不按问题条目数选边。都好可依据低影响差异选择，都差说明哪方更接近所求交付，保留共同失败边界。只有共同交付与已确认事实完全等价、没有可据以区分的差异时才填 null，并说明等价依据；共同适用的已确认观察尚未进入对比格时，也不能据此声称等价，low 不例外。未核查清楚不能冒充等价，不编造偏好。相对偏好不改变都好、都差判决；程序会为非空平局偏好补上表态，tradeoff 不重复表态。
- a_summary、b_summary 各概括本方已接受归因的结果、缺口及未核实范围；单方未关联观察留在本方总评。tradeoff 用一段解释整场取舍：指出一至两项决定性事实及实际影响，保留最重要的赢家缺点或对方优势，并说明它为何不足以改变取舍。非平局的主理由须对应赢家中高共同优势格或对手共同核心失败格的已确认事实；source_only 和未进入共同格的观察不能成为正式胜负依据。没有实质反向事实就不硬凑。事实必须来自现有归因与比较格，赢家的缺点不因胜出消失，对方的优点也不因落败失效；写清修正成本与适用边界，不用“各有优劣”代替权衡。候选用【候选A】、【候选B】，不抄写资源数值。结构合法不等于理由成立，提交前逐句核对主体、依据与结论是否一致。
