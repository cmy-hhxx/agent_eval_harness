展示三种固定视觉预设：bar 为横向比较条，line 为时间折线，pie 为环形组成。程序采用用户选定的 UBS 风格适配：白底、灰色与暗红，统一深色标题、范围与单位和末行来源；这是一套产品适配样式，不是官方模板或设计 token。比较条含零基线、实际数值和适合计数的刻度，时间轴减少拥挤标签并直接标注系列末值，数据点可查看日期、系列与精确值，环形展示合计，旁列类别、数量与占比，窄屏类别与数值分行，长合计放在环形下方。A组固定中灰，B组固定暗红，颜色只区分模型身份，不随赢家或涨跌改变，也不按类别位置猜测身份。双方都好、双方都差等结果类别各用独立的固定中性灰色；问题排行统一中灰，保留完整类名。实际数值直接呈现，不使用底部展开按钮。只选择符合材料的图形并提交数据，不设计颜色、尺寸或样式。先读取并核对来源；工具核验引用存在及结构，不替代数值、口径和结论的核对。图表在该轮完成后直接呈现在回答之后，折叠步骤或简洁模式不会隐藏，刷新和续聊沿用已记录结果。

title 给出材料支持的具体结论，注明抽样范围，不外推总体，例如“抽样 FAST 对局中，A组多胜1场”。scope 说明档位、题目或日期范围、有效样本数 n 和比例分母，unit 写实际单位，source 用业务来源名称。categories 用问题类、模型展示名或真实日期，series.name 用实际系列名；正文不放内部 ID。values 与类别逐项对应，暂无记录为 null，不补零，不自造主观评分或置信带。只比较同档模型，统一期间、单位和分母，Fast 与 Expert 分图。references 仅留追溯坐标：runId 引用运行目录，reference 引用 read_data 的原文或正式结果，operationId 引用本会话已接受的专业任务。

常见评测用途：

- 分档战绩用 bar，比较已裁决同档对局的胜场；不把未完成计成负场。
- 问题排名用 bar，按已核验的出现次数排列，单位与样本范围明确；不用严重度标签拼造分数。
- 结果组成用 pie，单系列、最多六项、同一总体的互斥完整组成；无负值或未知值，合计就是分母，已裁决组成包含双方都好/都差等实际类别。
- 同口径时间趋势用 line，categories 按 YYYY、YYYY-MM 或 YYYY-MM-DD 严格递增；缺失点断线，不把不同题集或难度的胜率连成进步趋势。
- 单题推理对照先给完整自然语言问句，再用 Markdown 表并列各模型的原回答片段、实际推导、具体断点及影响；不以题号代替问题，不为作图编数值。

图表已标注数值，回答只点评会改变判断的差距，不逐项复述图中数字。当前仅支持上述三种图形，不请求堆叠、雷达或瀑布图。
