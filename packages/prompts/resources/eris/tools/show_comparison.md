先读 reference 对应的正式点评与归因；补充责任定位或引用原文时读详情与来源。candidates 的 model 使用 comparisonScope 中的真实模型标识。
整图按“用户问了什么→回答给了什么→对用户有什么用”组织。顶层 title 保留用户问题的核心诉求，不用分析诊断替代问句；核心问题只在图顶显示一次，卡片不重复问句。

reason 在顶部一次说清决定胜负的差异及其对任务可用性的影响，不按问题数量投票。只支持相对优势时写相对胜出，不写预测可靠。每方 summary 用一句概括实际给出的答案，不写好坏评价；paths 再解释对用户的具体帮助与影响，包括缺陷和限制。不强制好坏平衡或先夸后反转。

paths 选择1–3项，每项围绕一个用户用途，重复内容合并。title 点明具体帮助或障碍，最多16字。evidence 写一句依据，可合并相关核验事实或原题明确要求与回答实际做法，尽量40字内、最多60字；impact 只写一个明确影响：用户能完成什么，或哪个判断受多大影响，尽量24字内、最多36字。保留改变结论的关键事实，不为缩短而失真。

依据与影响自然承接，不同义复述或重复 summary，不加抽象栏目标签。依据为用途判断提供支撑，不强行建立因果，不堆无关事实。给出时间窗不证明预测可靠。不能编造过程或未查明的外部事实；缺材料先读详情，仍未查清就保留缺口，不猜模型或工具责任。

例如，材料已核实时，evidence 写“实际只有5个交易日，B却按8个来推算。”，impact 写“企稳日期的推算依据出错。”

assessment 按正式归因选择 strength（优点）、problem（已确认问题）、uncertain（尚未核实），不按总胜负替每项定好坏，也不把专属要求当成另一方优势。

默认省略 highlights 和 reasonHighlight，仅在必要时突出决定性差异。可选 path.highlights 从 evidence、impact 至多选择1个字段；reasonHighlight 从 reason 选取。每处必须是对应原文中唯一出现的连续短语，最多16字；整图含 reasonHighlight 合计最多2处。不要每项高亮、整段高亮或自动高亮全部数字，不写 HTML 或 Markdown 样式。

caveat 仅放日期、档位、比较范围或标准答案口径，不放新的负面判词；无标准答案不占用分支，图与正文合计至多简提一次。

顶部显示正式判定与 reason；其下依次为共享核心问题、并列双方 summary、并列双方 paths 三层，底部仅口径。答案等高，用途面板按内容自然展开，不为对齐补字。组名、胜负和判词由正式结果绑定，程序控制布局与配色。正文不重复图中句子，不凑分支。
