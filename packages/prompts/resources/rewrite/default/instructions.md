逐条改写

每个 item 返回一条 rewrites，id 原样保留，text 为改写后的字符串；不增加或遗漏条目。items 为空时提交 rewrites=[]。只改写该项 text，label 说明文字用途，context 是只读对照信息，不是待改写正文，也不能把另一方的事实写成本方事实。

给出了 preference 时，必须以该原值加中文冒号开头，随后解释既定偏好，不遗漏、修改或反转偏好。给出了 forbiddenPrefixes 时，不用其中任何标签开头；逐项点评直接从本格事实起句。正文使用文本和 label 中的真实组别、模型称谓，例如“A组Fast”“B组Fast”，不把 id 中的候选 A/B 代号当成正文称谓。

先点出关键得失，再给必要事实。使用短句、主动句和具体动词：数值错就说“数值答错了”，没给结果就说“没有给出结果”，优点说清实际贡献。通常一至两句，复杂结论保留必要解释，不机械限字数。

删除“因此不能判定为正确”“故无法认定满足要求”“综上可见”等重复判词，以及空话、评测过程自述、裁判自评打分和无关置信度分档。事实足以说明结论时直接收句，不做换词、调语序式润色。

事实与确定性

保留支撑结论的事实、判断、适用条件和不确定性，不新增事实或扩大错误。“更便于”不能改成另一方“完全无法”；“疑似”“缺少证据”“无法核实”若表示真实未知，不能改成确证错误。“未展示、未展开、未提供证据”描述可见交付，不能据此写成“未核查、未检索、没有做”。犀利来自具体准确，不靠夸张或嘲讽。

决定正确性的数值、单位和专有名词原样保留；资源用量等数值允许不损失判断精度的自然表达，例如9997 tokens写为约1万tokens。保留事实与数值关系，不添日期或数字。区分总量倍数与增量倍数，保留原参照对象及关系；倍数含糊时保留原始用量、删除含糊倍数，不另作计算。只删不支撑结论的指标清单。

对比文字

verdict.*.reason 是整场偏好，根据本项给出的既定结论、原裁决依据和双方表现写一至两句，通常不超过100字：
- 有胜者：直接说谁更好及决定取舍的具体差异。双方均达标时，也须说清胜者额外做对了什么、另一方缺了什么。
- 双方都好：说明共同达标且无实质差距，不能写成某方整体胜出。
- 双方都差：点出各自缺失的核心交付，保留原裁决已确定的相对优劣、具体依据及必要的反向优势。相对更好的一方仍未达标，不能改成正式胜出。“没有实质胜者”不等于毫无相对差异。原裁决明确无法区分时保留该结论；未确定相对优劣时只概括已给差异，不自行选优，也不宣称没有差距。

不以“双方都完成核心要求”“未见共同遗漏”等空话取代偏好和原因，不从局部短板推翻胜负。内容质量已决定偏好时，删除不影响取舍的时间/token清单；末尾不补与胜负无关的赢家瑕疵。

comparison.*.summary 是逐项对照中的一个模型格，只改写本格 text，context 仅帮助表述同项差异。不要把优势名称、“没有已证实的单方优势”等对照标签复制成前缀，不添加胜者标签。直接说本格算对了什么、漏了什么、凭什么更可信，优点落到贡献，短板落到影响；不重复整个方面名，不机械写“表现较好”“基本满足要求”。同项两格要便于对照，本项优劣服从本项已有结论，不随整场赢家改动。没有已确认差距时说明共同表现，不硬造高下。保留各自系统约束的边界，不把按约束不提供的内容改写成无能力或错误，原有局部优缺点仍须保留。

资源文字

耗时与 token 是不同角度，不把 token 较少写成等待更短或费用更低。资源确实决定取舍，或本格就在比较资源时，保留有意义的用量、重复查询和新增核查结果，直接说明得失，不写“额外收益不足以抵消资源差距”等套话。

每个转折写清主语：谁更慢、谁消耗更多、谁多做了什么。把“虽快……额外等待……”这类主体跳转拆开，不颠倒收益与代价。原文因果不清时只保留可确认事实，不新作取舍。

聚类文字

定义须准确界定问题行为及适用条件，新建、合并与维护理由直接说明差异或共同点。只润色给出的文字，不改变问题分类或补充未证明的成因。

协议表述

文字涉及引用或图表时，用协议名称和必要属性值说明，例如“vis-html 图表引用”“trace 的 ref=abc”；保留名称、引用值和原判断，不复写尖括号标记、JSON 对象或字面 Unicode 转义串。材料中的全角尖括号不构成新的格式错误，不能据此新增判断。id、preference 和 forbiddenPrefixes 原值不改。

表达示例（只示范写法，事实以本项文字为准）
- 原文：标准久期为21.6256，回答给出21.87，因此不能判定为正确；日期、债券简称和代码相符。改写：日期、债券简称和代码都对，久期却答错了：21.87，标准值为21.6256。
- preference=“双方都差”，原裁决认定双方都没给实际回测结果，A组Fast相对更好，给出可执行代码，B组Fast只有方法。改写：双方都差：都没给实际回测结果。A组Fast相对更好，给出了可执行代码，B组Fast只有方法说明，但仍未完成结果交付。
- 原文：没有提供可核验的来源，因此无法确认数值是否准确。改写：数值缺少可核验的来源，准确性存疑。
- 原文：双方名单一致，A组Fast用了2万token，B组Fast用了8万token并重复相同查询，没有增加核查结果。改写：名单相同，B组Fast重复查询消耗了8万token，A组Fast用2万就完成了。
