逐条润色 `items` 中的点评文字：

1. 每个 `id` 返回一条 `rewrites`，沿用原 `id`。只填写对应文字，不增加点评条目。
2. 先点破关键得失，再给必要事实。使用短句、主动句和具体动词：数字错就说“数值答错了”，没给结果就说“没有给出结果”。优点也落到具体贡献，不写泛泛表扬。通常一至两句；复杂结论按必要事实展开，不机械限字数。
3. 删去绕弯的重复判词，如“因此不能判定为正确”“故无法认定满足要求”“综上可见”。事实已经说明问题，就直接收句。不要仅把“为”换成“是”、调换语序，或保留整段裁判推导。删除空话、重复、评测过程自述、裁判自评打分和无关置信度分档（如“6/10 置信度”）。
4. 保留支撑结论的事实、判断、限制条件和不确定性，不补事实、不改结论。犀利来自具体准确，不靠夸张、嘲讽或扩大错误；“更便于”不能夸大成另一方“完全无法”。必要的数字、单位和专有名词原样保留，无关指标按第7条删除，不要求逐个保留原文出现过的数字。“疑似”“缺少证据”“无法核实”若代表真实不确定性，必须保留，不能写成已证实错误。
5. 使用文本和槽位名称中的真实组别与模型称谓（如“A组Fast”“AA组Fast”），不要使用候选 A / B 等盲测代号。槽位 `id` 只用于回填，不是正文称谓。
6. 聚类的定义仍须准确界定问题及适用条件；新建理由与合并理由直接说清差异或共同点，不更改类名、类 ID 或归类关系。items 为空时提交空的 rewrites。
7. 对比的 `tradeoff` 是裁决短评：保留谁更好、凭什么胜出的立场，通常两句、40—80字，最多160字；把清单压成关键结果，不再重复逐项比较；共同做到的内容不重复，工具名称清单压成具体比较项，直接点出另一方缺少什么。不会改变裁决、且已在其他槽位保留的局部瑕疵不在末尾再追加一遍；真实影响取舍的限制不能删，必要时先交代取舍、最后落定结论。`comparison.*.summary` 是一格表现：保留该方面的具体事实、差距及必要限制，通常一句，最多160字；不要跨槽位搬运事实，不自行替另一方下结论。其他 comparison 结论槽位也最多160字。不要用“能帮助用户形成更具体的风险清单”“可操作信息较少”等空泛影响代替具体差距。来源和脚注展示瑕疵不升级措辞、不渲染为严重错误。
8. 体验点评围绕额外等待是否换来更好结果，通常只留一组支撑判断的完成耗时；删去不影响结论的首 token、首段及 token 枚举。只有原判断确实依赖这些指标时才保留相应值与限制条件。保留的数字与单位不得改动，不把 token 较少写成等待更短或价格更便宜。不能删掉独立优势对应的另一方短板，也不能把未核实写成没有。

写法示例（只示范表达，事实以各槽位文本为准）：
- 原文：标准久期为21.6256，而最终回答给出21.87，数值不一致，因此不能判定为正确。最终回答中的日期、债券简称和代码与问题及查询结果相符，但核心指标值错误。
  改写：日期、债券简称和代码都对，久期却答错了：21.87，标准值为21.6256。
- 原文：回答没有提供可核验的来源，因此无法确认该数值是否准确。
  改写：数值缺少可核验的来源，准确性存疑。
- 裁决短评原文：A组Fast比较了远期、期权和债务币种置换，AA组Fast只说明汇兑方向并提到人民币融资，因此A组Fast提供的可操作信息更多。
  改写：A组Fast更好：对冲方案比较到位，AA组Fast只讲汇兑方向，缺少方案比较。
- 原文：两者答案质量相当，A组Fast首token为0.5秒、首段1秒、完成8秒，输入100 token、输出20 token；AA组Fast首token为10秒、首段20秒、完成40秒，输入1000 token、输出20 token。额外等待未带来更好的答案，A组Fast体验更好。
  改写：两者答案质量相当，A组Fast用8秒完成，AA组Fast用40秒。AA组Fast多等的时间没有换来更好的结果，A组Fast体验更好。
