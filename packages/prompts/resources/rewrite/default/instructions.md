逐条改写

按 items 原顺序返回 texts 字符串数组，一项对应一条；items 为空时 texts=[]。只改写本项 text，label 说明用途，context 用于理解对照。

给出 preference 时，以其原值加中文冒号开头。给出 forbiddenPrefixes 时，避开这些前缀。正文沿用文本和 label 中的真实组别、模型称谓，例如“A组Fast”“B组Fast”。

写法

- 用短句和具体动词写清做对了什么、错在哪里、影响什么。通常一至两句，保留理解结论必需的解释。
- 回答结论只留主要完成情况和缺口。数值全部一致时概括为“四项数值与标准答案一致”；差值影响判断时保留回答值和标准答案中的数值。
- 所有点评字段提及评测依据中的答案时统一称“标准答案”。原文的“标准结果”“导入结果”“导入标准”等同指称谓改为“标准答案”；有差异时写清“回答为X，标准答案为Y”。只统一称谓，保留原判决和限定；工具返回、实际计算结果或其他参考材料保留真实身份，不能改称标准答案。
- 判对理由保留必要口径、计算和依据。删去不影响判断的指标清单、格式描述、内部字段名、评测过程和重复判词。
- 原文的“已核对”“疑似”“未提供来源”等限定词原样保留。
- 决定正确性的数值、单位和专有名词原样保留。资源数值可在保持判断精度的前提下自然表达，例如9997 tokens写为约1万tokens。倍数关系含糊时保留原始用量。
- 引用或图表用协议名称及必要属性值表述，例如“vis-html 图表引用”“trace 的 ref=abc”。

对比文字

整场偏好用一至两句，目标60—100字；必要的事实与限定优先于字数。选决定取舍的一至两项事实，保留有意义的反向优势：
- 有胜者：写谁更好，以及多做对了什么、对方缺了什么。
- 双方都好：写共同达标且无实质差距。
- 双方都差：写各自缺失的核心交付，保留原裁决已确定的相对优劣和依据。相对优势仍服从“双方未达标”的结论。

逐项对照直接从本格事实起句，优点落到贡献，短板落到影响，便于与另一格比较。本项优劣沿用本项结论，没有已确认差距时说明共同表现。保留各自系统约束的适用范围。

资源文字

耗时写等待，token 写用量。专门比较资源的格子同时保留本方完成耗时和总 token，以及原文中的具体缺失或异常说明；两项优势方向不同时保留各自得失。整场偏好只保留影响取舍的资源事实。说明谁消耗更多、额外核查带来了什么结果；因果不明时只保留已确认事实。

聚类文字

定义写清问题行为和适用条件；新建、合并与维护理由说明实质差异或共同点，沿用原分类与归因。

示例（只示范表达）

- “标准答案中的久期为21.6256，回答为21.87，因此不能判定为正确；日期和代码相符。” → “日期和代码都对，久期却答错了：回答为21.87，标准答案为21.6256。”
- 已判双方都差、A组Fast相对更好 → “双方都差：都没给实际回测结果。A组Fast给了可执行代码，B组Fast只有方法说明，但两方仍未完成结果交付。”
- “没有提供可核验来源，因此无法确认数值是否准确。” → “数值缺少可核验来源，准确性存疑。”

按 Schema 调用 submit_evaluation；收到反馈后修正所指 texts 位置或结构。
