逐条润色 `items` 中的点评文字：

1. 每个 `id` 返回一条 `rewrites`，沿用原 `id`。只填写对应文字，不增加点评条目。
   `constraint="no_winner"` 是已确定的裁决限制：该槽位只写共同失败的具体事实，不写任何一方相对更好、更可用、居前或建议选谁；局部差异已在别的比较格中展示。
2. 先点破关键得失，再给必要事实。使用短句、主动句和具体动词：数字错就说“数值答错了”，没给结果就说“没有给出结果”。优点也落到具体贡献，不写泛泛表扬。通常一至两句；复杂结论按必要事实展开，不机械限字数。
3. 删去绕弯的重复判词，如“因此不能判定为正确”“故无法认定满足要求”“综上可见”。事实已经说明问题，就直接收句。不要仅把“为”换成“是”、调换语序，或保留整段裁判推导。删除空话、重复、评测过程自述、裁判自评打分和无关置信度分档（如“6/10 置信度”）。
4. 保留支撑结论的事实、判断、限制条件和不确定性，不补事实、不改结论。犀利来自具体准确，不靠夸张、嘲讽或扩大错误；“更便于”不能夸大成另一方“完全无法”。必要的数字、单位和专有名词原样保留，无关指标按第7条删除，不要求逐个保留原文出现过的数字。“疑似”“缺少证据”“无法核实”若代表真实不确定性，必须保留，不能写成已证实错误。
5. 使用文本和槽位名称中的真实组别与模型称谓（如“A组Fast”“AA组Fast”），不要使用候选 A / B 等盲测代号。槽位 `id` 只用于回填，不是正文称谓。
6. 聚类的定义仍须准确界定问题及适用条件；新建理由与合并理由直接说清差异或共同点，不更改类名、类 ID 或归类关系。items 为空时提交空的 rewrites。
7. 对比的 `tradeoff` 保留整体裁决和决定性事实，通常一至两句，最多100字，不凑字数、不固定句型。全部未达标时保留共同失败结论，不把局部优势润色成整体胜出；“相对/局部”不能删成无条件的“更好”。共同做到的内容不重复，直接点出关键结果或另一方缺少什么。不会改变裁决的局部瑕疵不在末尾再追加；真实影响取舍的限制不能删。`comparison.*.summary` 是一格表现：保留该方面的具体事实、差距及必要限制，通常一句，最多160字；不跨槽位搬运事实。其他 comparison 结论槽位也最多160字。删去“按规则同层”“非核心的反向优势”等评测术语。删除“核验价值”“可操作信息较少”“更稳”“额外等待未换来同等价值”等抽象套话，原文有具体事实就直接写事实，没有就不补。来源和脚注瑕疵不升级措辞。
8. 耗时与 token 是不同的评估角度，原文已用具体事实证明资源差异时必须保留，不能一律压成时间比较。只删不支撑判断的指标清单；有意义的 token 用量、重复查询或新增核查结果不能丢。每个转折都写清主语：谁更慢、谁消耗更多、谁多做了什么。把“虽快……额外等待……”这类主体跳转拆开，不能颠倒收益和代价；因果不清时只保留原文能确认的事实，不替裁判新作取舍。保留事实与数值关系，允许不损失判断精度的自然表达，例如9997 tokens写为约1万tokens；不要无依据补入日期、数字或改动主体。总量“是3倍”和增量“多2倍”不能混写；原文关系不清时保留原始用量，删掉含糊的倍数表达，不另算数字。不把 token 较少写成等待更短或价格更便宜。

写法示例（只示范表达，事实以各槽位文本为准）：
- 原文：标准久期为21.6256，而最终回答给出21.87，数值不一致，因此不能判定为正确。最终回答中的日期、债券简称和代码与问题及查询结果相符，但核心指标值错误。
  改写：日期、债券简称和代码都对，久期却答错了：21.87，标准值为21.6256。
- 原文：回答没有提供可核验的来源，因此无法确认该数值是否准确。
  改写：数值缺少可核验的来源，准确性存疑。
- 裁决短评原文：A组Fast比较了远期、期权和债务币种置换，AA组Fast只说明汇兑方向并提到人民币融资，因此A组Fast提供的可操作信息更多。
  改写：A组Fast更好：对冲方案比较到位，AA组Fast只讲汇兑方向，缺少方案比较。
- 原文：A组Expert完成了结果交付，而AA组Expert在交付相同结果的基础上还核对了八个落选候选的原因。AA组Expert因此更好，但需要比A组Expert多等待100秒。
  改写：AA组Expert多查清了八个候选为何落选，选它更有依据，但要多等100秒。A组Expert只给出入选名单。
- 原文：两方交付的名单一致，A组Fast用了2万token，AA组Fast用了8万token并重复执行相同查询，未增加核查结果。
  改写：名单相同，AA组Fast重复查询消耗了8万token，A组Fast用2万就完成了。
