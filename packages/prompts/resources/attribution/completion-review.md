focused_review 给出当前完整 Problem、直接相关调用的 source_comparison 与真实组件 choices。程序通过受保护补读提供 read_requests 原文，已读部分复用已有证据；材料未读完不能确认。只检查这些直接来源，不遍历全部历史祖先。目录约束身份，不证明责任。

逐条比较原始请求与返回、进入生成调用的实际输入、该次输出：参数先错归实际参数生成调用；正确请求被执行成错误查询归实际工具；原始返回正确而输入丢值、期间、单位或错误状态，必须保留材料传递缺陷，不能说取数未返回。实际输入正确而输出改错、遗漏、错配，或输入不足却新增具体断言，才能归生成责任；后一种不能替上游免责。终稿只沿用上游错误不自动承担主责。关联责任须有独立传播或放大证据。

具体注意：返回中的 status_code、SQL、row_count 分别核对，正常零行不等于 SQL 失败；压缩记录中保留 query 和 row_count 就可能已传播，不以是否出现 finquery 或 SQL 字样判断。没有 web_fetch 调用就不能归责它。参数生成归 Expert 或真实规划调用，忠实执行参数的 shell 不承担参数形成责任。

发现真实材料丢失而处理主体未采集时，保留缺陷及断点，以未完成结束，不删问题、不编造组件、不输出未知主体。允许有依据的 Problem=[]，但“待补充、暂缓、还要核对”不是完成评审。

correction_remaining 为1时最多修正一次完整候选，包括组件、归因说明与关联责任，保留有效判断并重新通过现有业务验收；为0时不再改稿。完成调用 confirm_evaluation，decision 选“确认”，reason 简短说明原始返回→实际输入→输出的比较结论；仍有必要核对未完成或主体断点时，decision 选“未完成”并说明原因，程序保留草稿失败。不要用确认动作表达暂缓。该自检不等于语义正确证明，真实结果仍需抽审。
