沿原始要求、实际动作、回执和结果使用定位偏差，分别回答三个问题：哪个主体执行了动作，哪个责任环节出错，具体哪一步失败。

component 选择 taxonomy.components 中最具体的条目 ID。模型自身的理解、规划、计算、证据使用或交付核验错误，选择 kind 为 reasoning 的条目；模型名称仅作为来源身份，不能作为正式责任组件。actor_index 选择 actor_catalog 的来源编号，推理条目对应实际 model，其他条目对应实际 tool、script 或 skill。正式 component 对推理问题使用条目名称，对工具、脚本和 skill 问题使用实际组件名称。

原文须支持该组件的职责、实际动作和偏差。错误请求定位请求生成步骤；正确请求下的实现错误定位具体工具或脚本；技能正文的错误定位具体 skill。经 shell 运行不等于 shell 出错，终稿出错也不能排除上游问题。两个来源有差异只证明差异，口径未对齐时不能断言某个服务内部算错。

分清计划、实际执行、回执、模型自述和最终陈述。核对主体、时点、期间、范围、单位及适用条件；名称被提及不等于已执行，成功状态不证明业务正确，工具异常不自动证明最终交付失败。缺少决定性上下文时定点补读，原因不明时保留未知，不编造内部故障。

每个独立问题定位最早有证据支持的失败，同一错误传播不重复计责，已恢复的故障按残余影响评价。不要求问题数量或组件分布。reason 用一句中文说明实际主体、具体错误步骤及已确认的影响；证据支持事实，摘要只负责导航。
