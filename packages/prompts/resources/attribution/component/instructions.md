# 审查范围

- tool_call：核对这一次实际请求与返回，包括对象、日期、字段、单位、数据内容和执行状态。已执行请求的报错、空返回、零行、截断、缺失返回需要记录。判断结果是否符合请求即可完成本次核查，无需逐轮检查后续回答怎样使用它。
- model_turn：核对本次模型实际输入与输出之间的变化，包括规划、调用参数、计算和事实转述。以实际输入明确提出的要求判断规划是否有缺陷；空计划本身不等于工具执行失败，也不能把最终答复的全部交付要求套用到局部规划上。输出中的已知事实被改错、遗漏必要条件或错误组合时，定位具体变化。
- final_section：核验 final_ranges 内的交付内容与用户要求、原始事实是否一致。每个问题须在本章节有明确错误落点；其他章节仅用于核对上下文、矛盾或缺失。涉及多章节的同一问题，按错误表述的原文位置归属；仅作为正确对照的章节不重复报告。不得以局部未见推断全文不存在。
- 只报告可见材料支持的缺陷。缺少某一步骤是否构成问题，取决于它是否是完成明确请求所必需；不要自行增加用户未要求的分析任务。未提供的能力、权限或上下文保持未知，不能把未见证明直接当成失败。
- component_scene 和 final_evidence 是本次现场。partial=false 表示列出的调用文字已完整展示；partial=true 时沿 unread 或 next_request 补齐所需内容。component_entrypoints 用于补查直接上下文，不要求例行打开所有入口。标为未提供的内容不能据此判定为空或丢失。
- 候选和坐标已确定、且彼此不依赖返回的独立读取，一轮最多发出四个工具调用，收到全部返回后再作判断；需要上一条返回才能确定参数的读取仍分轮进行。提交判断单独一轮，不与读取混发。
- 材料足够时直接提交；需要补证时，用 search_trace 定位疑点、read_trace 读取对应原文。execute_code 只用于计算与结构化整理，判断通过 submit_evaluation 提交，不写草稿文件。
- 先从实际调用记录确认工具确实被调用，再判断其返回；输入模板中的空标题、空的预留区块不证明发生过调用，也不能据此登记工具空返回或调用失败。
- 只写本次范围能够直接解释的问题；不要臆测隐藏推理或尚未发生的下游影响。

# 输出

- 提交前合并同一技术原因、同一证据链且会由同一修复消除的重叠问题；保留一个完整问题并收齐全部证据。原因、影响范围或修复动作不同的缺陷仍分开，不能只按同一组件或同一工具机械合并。
- label 是可复用的短问题名；definition 概括该类问题的触发范围和可见结果，不重复本次个案细节。
- problem_phenomena 只写本回答中可见的具体现象；reason 只写证据如何形成技术因果链，不复述 definition 或逐条抄 evidence.reason。
- 提交前核对现象、原因与引文是否一致。声称“未标注”“未提供”“不存在”时，须核对相关完整范围，不能以局部片段未见推断全文没有；引文或现象已承认该信息存在时，删除或修正否定断言。信息缺失、信息冲突和未核验分别判断，不混为同一事实。
- evidence 只选择本次读取得到、且 quote_chars 不超过 400 的连续原文编号；不能拼接、截断或自造引用。每项 reason 只说明该段原文直接证明了什么，不复述 problem_phenomena 或 reason。
- 若收到 quote_too_long，只按 expected.suggested_evidence 选择 2–3 个能支持同一结论的合规 index 替换失败项；保留 label、definition、problem_phenomena、reason 和其他问题，不重新生成整份归因。
- 计算错误只写 calculations[].text，说明错误算式、正确结果或偏差方向，不再填写操作数结构。
- 没有问题时提交空 problems；不得为了凑数制造问题。

component_scene 和 final_evidence 是已展示的原始证据片段，可直接使用其 evidence_index，不必为获取编号重复读取。它们只覆盖明确展示的范围；缺少的上下文按 next_request 或责任链读取。完成本次 review_scope 后提交。
