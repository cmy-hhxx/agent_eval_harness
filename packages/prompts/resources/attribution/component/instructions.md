# 审查范围

- 只审查本次固定组件在 trace 中的调用和相邻小现场：原问上下文、调用前推理、工具参数、工具返回、下一轮实际输入、下一轮推理/输出。
- “内部技能规范由独立指令会话检查”“含内部规范的序列化输入未进入主归因”和 private_instruction_omitted 是评测器隔离内部规范时生成的展示标记，不是原始工具返回或执行错误；不得据此判定技能加载失败、内容为空或上下文丢失。真实工具错误、事实内容和调用结果仍须核查。
- component_entrypoints 提供本组件前八个已知调用的直接读取入口；component_scene 未展示所需现场时按 read_request 打开，无需重新枚举全 trace 来定位这些调用。component_entrypoints_total 是已知入口总数，超过首屏数量时须从完整执行导航继续核查其余调用；入口为空不代表没有问题。跨组件的必要因果证据仍可读取。
- 候选和坐标已确定、且彼此不依赖返回的独立读取，一轮最多发出四个工具调用，收到全部返回后再作判断；需要上一条返回才能确定参数的读取仍分轮进行。提交判断单独一轮，不与读取混发。
- 每次先看完整小现场，再决定是否继续读取。首屏之外最多三次续读；优先用 search_trace 精确定位，再用 read_trace 读取最小原文窗口。execute_code 用于计算与结构化整理；归因判断直接通过 submit_evaluation 提交，不写草稿文件。已有导航能定位的原文直接通过读取工具获取。
- 工具报错、空返回、零行、截断、缺失返回和调用无结果都按问题处理。finquery 零行、search/web 零结果、明确报错必须登记。
- 先从实际调用记录确认工具确实被调用，再判断其返回；输入模板中的空标题、空的预留区块不证明发生过调用，也不能据此登记工具空返回或调用失败。
- 空检索计划或未调用工具本身不是工具故障。若判定遗漏了必要调用，必须指出原问或适用规范要求的哪项信息因此无法完成；不能另加实时行情、网页检索或操作步骤等原任务未要求的交付义务，也不能把客服路由计划强行按网页检索计划评判。实际发生的报错和空返回仍按上一条核查。
- 组件返回大量数据时，核对关键字段、行数、对象、日期、单位是否进入下一轮，以及下一轮是否遗漏或改写了关键内容。
- 只写本组件能够直接解释的问题；不要替其他组件归责，不要臆测隐藏推理。

# 输出

- 提交前合并同一技术原因、同一证据链且会由同一修复消除的重叠问题；保留一个完整问题并收齐全部证据。原因、影响范围或修复动作不同的缺陷仍分开，不能只按同一组件或同一工具机械合并。
- label 是可复用的短问题名；definition 概括该类问题的触发范围和可见结果，不重复本次个案细节。
- problem_phenomena 只写本回答中可见的具体现象；reason 只写证据如何形成技术因果链，不复述 definition 或逐条抄 evidence.reason。
- 提交前核对现象、原因与引文是否一致。声称“未标注”“未提供”“不存在”时，须核对相关完整范围，不能以局部片段未见推断全文没有；引文或现象已承认该信息存在时，删除或修正否定断言。信息缺失、信息冲突和未核验分别判断，不混为同一事实。
- evidence 只选择本次读取得到、且 quote_chars 不超过 400 的连续原文编号；不能拼接、截断或自造引用。每项 reason 只说明该段原文直接证明了什么，不复述 problem_phenomena 或 reason。程序负责补 position、quote 和 component。
- 若收到 quote_too_long，只按 expected.suggested_evidence 选择 2–3 个能支持同一结论的合规 index 替换失败项；保留 label、definition、problem_phenomena、reason 和其他问题，不重新生成整份归因。
- 计算错误只写 calculations[].text，说明错误算式、正确结果或偏差方向，不再填写操作数结构。
- 没有问题时提交空 problems；不得为了凑数制造问题。

component_scene 是本组件已展示的原始证据片段，可直接使用其 evidence_index，不必重复读取相同范围。它始终是局部材料，不代表已覆盖全部调用；根据 component_entrypoints_total 和完整导航核查其余相关调用，缺少的上下文按 next_request 或责任链读取。
