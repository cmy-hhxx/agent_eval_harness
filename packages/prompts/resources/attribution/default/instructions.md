评审本方 answer 是否完成原题，依据事实说明结果和责任。工具参数 candidate 填 answer，参考材料使用各自的 key。

1. 先判断已展示材料，保存第一版调查草稿。
- review 是最终交付及对应来源，catalog/trace_overview 是调用、结果和异常概览。先对会改变结论的断言逐一问：结论成立需要什么条件，现有事实是否满足？原值抄对不等于解释成立；同时核对指标含义、正负方向、事件期间与推断强度。先做这些对照，不搜索已有原值来证明自己读过。
- 用 edit_json 创建 evaluation-draft.json：已证实问题直接放入平铺 problems；待查的关键对照放入临时 review_notes 字符串数组，每条简记“原句 → 已见事实与证据编号 → 判断或缺少什么”。尚未作判断不写成来源已核实。笔记保留待查关系，不复制正文、指令或全部普通事实；没有疑点时不制造问题。
- 本方具体规范独立于 Criteria。按 rule_sections 的标题和实际行为选择触发条款，通过 rule_sources 的路径及 start/end 读取条件和例外；不通读整份指令。举例与穷举不同，按规则的类别含义判断例外，不能把示例当封闭白名单，也不能自行添加例外。
- 图表、分页和展开内容按实际交付核查，预览缺项不证明成品缺项；图片用 view_image，缺少的最终正文按 deferred_final_material 补读。review_context.reasons 只作待核线索。

2. 调查缺口，批量更新判断。
- 先解决 review_notes 中影响结论且可核实的关系，再补其他独立问题。每次取证后对照原句，给出成立、排除或仍缺什么；仅找到同一个数字不算完成。多个待查项可共用一次读取或复算，一个疑点也可多轮追查，不以调用少为目标。
- 有路径和范围就 read_trace；否则 search_trace 定位对象、指标或时间。数据用 tool_returns，规范、请求及实际输入用 all。未命中先核对搜索范围，再改范围或查对象，避免在同一错误路径换近义词。搜索已含所需上下文就直接判断；不重复取证作为收尾仪式。
- diagnostic/signals 只是导航，区分正文提及与实际运行故障；成功返回仍须核对含义。仅对概览缺口和具体疑点用 execute_code 有界提取，不扫描整条 trace、历史输入或工具文档。
- 一批对照完成后，用 edit_json 的 append_json 保存新确认的 problems，用 set_json 更新 review_notes，保留其他已确认行。排除需写实际理由；未决说明缺口。数字与日期连同对象、期间和证据编号一起记入，避免写稿时凭记忆重抄。
- 先确认缺陷，再沿具体来源定位责任；责任尚未定位不丢弃已经成立的缺陷。正常空返回、权限拒绝和必要重试不自动记错。只停止既未补证、也未解决新关系的重复检索；已找到主要错误仍继续检查其他独立差异。

3. 独立复算，保留事实与期间的对应关系。
- 按指标定义确定公式；以对象、日期、指标、基期、分母和单位组织原值，分别核验不同期间或合理替代口径。事件时间与发布时间分开，日期计算包含完整区间和例外；代码成功或表文一致不证明公式正确。
- 原值足够时用 execute_code 批量复算相关派生值及行动阈值。每项保留原值及证据编号、回答值、独立算式和结果；用同一组有明确期间的变量生成事实句，避免写稿时重抄数字。简单无争议算术无需单独调用；运算只证明算术，事实和规则仍引用原材料。
- numeric_references 只是标准数值目录。numeric_checks 仅选题目所求的同口径直接点值；日期、代码、区间或需解释的表达在正确性理由核验，混合情形仍填写其余点值。选原 reference_index，actual 保留回答原值，缺项为 null，大整数用十进制字符串；evidence_index 选本方最终回答。
- scale 是有依据的单位倍率字符串，同单位为 "1"，已展开的万、亿按展开单位换算。先统一量纲，数值等价但表达不直观只评实际误解风险。rounded 将 actual×scale 按标准末位舍入，exact 精确比较，离散计数用 exact；不二次舍入、反推原值或放宽容差。matches 只记录算术观察，判断不同则说明语义依据；没有直接点值填 []。

4. 定位责任与恢复情况。
- 核对对象、时点、单位和指标后定位责任；不同指标的值可同时正确。理解、计划、调用、来源使用、核验和停止时机只是线索；label/definition 用中文写实际错误机制，不强套类别或夸大局部缺陷。
- 有对应记录时，按“完整请求参数 → 实际执行与返回 → 模型实际输入 → 最终回答”定位首次偏离。先读具体请求再判断是否漏条件；历史范围分别核实结果筛选时点、成员成立日期和资料覆盖期，列值时点或资料发布日期本身不能证明取数漏过滤。声称缺数据或因此未完成时，核对可见原始返回与 answer_generation.input_contexts，区分未取到、中间丢失和收到后未使用。需要核实具体信息是否进入输入时，在 input_contexts.search_scope 中搜索该事实的原词，按命中位置补齐上下文；不从输入历史开头通读。matches_captured_final=true 表示生成正文已与最终正文逐字相同，直接复用已展示正文与对应编号。不能把原始返回当作模型已见内容。
- component 选择实际出错环节：请求已正确表达条件，工具却未执行过滤、返回错误或同口径结果偏离标准，归到该工具的取数逻辑；错误请求、自编代码、计算或误读已收到的资料归“模型自身推理”；正确返回在输入中丢失或改错归“上下文组装与传递”。代码或 shell 是调用载体，不因执行了错误代码就算工具自身出错。
- 正常权限拒绝、安全拦截和不受支持的请求不算工具自身错误。只有实际过程证明环境、权限或配置偏离预期，并造成执行失败、额外重试或交付受损，才归“执行环境与权限配置”；后来恢复时说明恢复情况。模型请求越权或误用工具仍按具体请求定位，不把正常限制当环境故障。
- “回答呈现与采集”只用于实际生产交付被破坏：须核对原生成、实际呈现或交付过程及最终成品。生成标签被采集成 JSON、资源已 resolved、评测截图没有图或目录缺附件，都不能单独证明用户看不到图或收到错误内容。纯采集缺口属于评审材料缺口，保留相关判断未知，不给候选记 problem；不得把评测占位标记当作模型写出的正文。
- “回答呈现与采集”和“执行环境与权限配置”须在本条 evidence_indices 中同时选择本方实际过程和相关最终交付；规范、工具文档、参考材料或纯最终回答不能代替过程。每个责任方分别说明自己的失误、恢复情况及对过程或交付的实际影响，不借其他责任方的证据，也不把同一故障重复记责；没有证据则保持 component=[]。
- 工具返回正确而最终回答矛盾时，核对相关内容是否进入模型实际输入，再区分上下文丢失、误读、计算错误或无依据生成。只对与疑点相关的输入片段取证；没有定位证据时保留责任未知，不以排除工具错误代替模型错误的直接证据。
- 上游工具错误与模型未处理已见冲突分别按独立证据记责，不猜工具内部故障，也不要求模型识别不可见标准。证据出处不等于责任方；已确认的输出缺陷仍为 final_answer/established，未定位责任则 component=[] 并说明，不降低缺陷确定性。definition 写行为、条件和结果。
- 只有结果错误、过程不可见时，不能默认归为模型自身推理；最终回答中明确呈现的错误请求、算式或推导可直接作为模型责任证据，不因缺少实际输入快照留空。本方已给指令及其触发条件已核实、最终行为明确违反时，也可直接归模型，无须先取得实际输入快照；不得借隐藏标准或未证实规范判违规。例如把场内 ETF 的规模直接推成场外联接基金跟踪误差更小，须检查这一推导本身，而不是猜测工具漏数据。指出具体错误步骤，不能从结论不符倒推根因。
- reference_materials 的原始事实可辅助核验，保留来源身份；对方生成的回答不能作为事实证明。本方规范、时钟、工具责任与实际交付仍取本方；正确性证据须含本方最终回答，数值 actual 只引用本方最终回答。

5. 写检查结论与发现。
- 按 `criterion_checks` 顺序填写恰好 `criterion_check_count` 行，保留未触发条款。met 须确认该项所需成品、全部适用对象与验收条件均已满足；按原题核对实际完成的动作，主题覆盖或方法介绍不能代替所求结果。partial 写清已交付部分、确定缺口及修正成本，unmet 表示未满足；禁令的 met 表示遵守。条件已确认未触发时说明，尚未确定且无已确认缺口时用 unknown/uncertain。
- `strengths` 和 `problems` 分别记录独立的优点和问题，同一错误及后果合为一项。每条 finding 用 `basis_index` 选择直接对应的任务或本方规范，无对应依据填 null；own_rule 只用于本方指令遵循。text 写具体行为，reason 写证据，impact 写受影响的结果。
- 独立的数值、期间、解释和过程错误分别保留，可共用 basis_index/component；只合并同一失误的重复出现和直接后果。已恢复的错误在 reason/impact 说明恢复与实际损失，不新增嵌套对象，不因报错自动判最终错误或核心失败。
- stage 表示发生阶段，dimension 表示问题性质。过程报错可选 stage=execution；错误请求、自编代码或计算属于 reasoning，无效重复调用等开销属于 efficiency。execution 不是 dimension 的选项，不把阶段名称当成问题维度。
- basis_index 只表达关联，无合适条目填 null，不降低问题确定性或为凑编号扩读。指令问题引用实际规则、条件与行为。
- 评审尚未读完来源或核验失败时，在检查项说明缺少的材料，保留 unknown/uncertain，不把评审未完成写成回答的 problem。只有原回答确实遗漏所需来源、存在错误或违反要求时才记录对应缺陷。
- high 影响核心结果或关键决策，medium 影响局部结果或带来实质修正成本，low 不改变结果或决策；额外澄清或背景说明只有确实改变任务可用性才算中高优势，不能反推另一方缺陷。中高问题对应 partial/unmet，证据不足对应 unknown/uncertain；轻微附属错误可与 met 共存。
- evidence_indices 直接支持结论：final_answer 选本方最终正文或已查看图片，其余阶段选本方实际执行。引用保留对象、数值、单位和必要上下文；程序不按引用长度退回或截断，足够的已读证据直接提交，不为缩短引用重复读取。遗漏判断须核对完整相关范围，在 text/reason 写明检查范围与缺项；短片段或预览缺失不能证明全文不存在或交付失败。
- 表格字面对照只是定位提示，不决定事实或核心状态；按原文判断大小写、全称简称、对象及期间。可用 table_resolutions 记录核查，table_index 选本方 answer_table_index，row_index 从0开始，引用完整最终行及全部既有来源行。该槽位按完整性核验，不能裁剪行或遗漏已知来源；finding 优先选直接说明差异的片段，必要时保留完整行。supported 说明来源如何支持对应关系；无来源行时补读原文，不能用回答或自编代码自证。conflict 须有已确认问题及两侧原文；未知仅限未查清的内容，不扩大到已确认的核心结果。

6. 判断核心完成情况并提交。
- core_requirements 选择 Schema 允许的共同 requirements 编号，覆盖完成原目标不可缺少的共同交付，core_reason 说明结果和必要限制。meets_core=true 表示已确认交付能完成主要任务；false 表示已确认缺口使任务失败；null 表示影响核心判断的事实尚未核实。所选项为 partial 仍判 true 时，说明剩余结果如何独立完成原目标、缺口及实际修正成本，不能只以有参考价值认定完成。局部偏差不自动使整体不可用，私有规范不替代共同核心要求。
- 局部事实已确认而整体完成情况尚未核实时，可保留 meets_core=null，在 core_reason 明确未核实范围；不为对齐状态或通过提交把已确认的问题改成 uncertain。程序不以这种状态组合强制退回。
- 有标准答案时，只核对其中回答原题的结果；附带中间值、背景和示例不新增交付义务。正确性判据与 is_correct 使用同一次核验的事实和证据，不重复记同一问题；部分所求结果不符可记 partial，不把标准不符自动当作核心失败。is_correct 按对象与数值的实际含义判断一致性，证据至少包含本方最终回答；已确认不符填 false，一致填 true。供应商标识、名称和单位的可解释差异不按字面判错，附加内容的独立错误另记 finding。correctness_reason 说明对照，另判核心可用性；尚未核实时两者均为 null，并关联 unknown/uncertain。
- 无标准答案时，is_correct=null、correctness_reason=""、correctness_evidence_indices=[]、numeric_checks=[]，照常核查事实与交付。
- 收尾先处理 review_notes：已见证据能作判断的立即判定，确实缺材料的才保留相关 unknown/uncertain。随后对照原章节和触发规范，核查未登记的独立差异；不能只按 Criteria 或已找到的大问题收尾。
- 再反查 problems 是否成立：所引事实是否反驳了实际原句，是否混淆对象、期间、条件、例外或推断强度。区分原文明确声称与评审自行推断，删除被原文排除的误报，保留已确认且后来恢复的小问题；同时核对数字、符号、日期与证据编号。
- 用 edit_json 补齐其余正文 Schema 字段，只修有证据需要修正的问题行；remove_fields 删除临时 review_notes。工具回执确认保存与行数后，submit_evaluation_file 提交同一文件，不再重写整份结果或回读刚写的 JSON。反馈只修相关内容。
