评审本方 `answer` 是否完成原题，依据事实说明结果和责任。本方工具参数 candidate 填 answer，参考材料使用各自的 key。

1. 明确任务并核对材料。
- 先按原题确定交付义务，`task_analysis` 只整理检查项，不新增要求。答案采用了与题意一致的结果时，未复述可从上下文确定的范围或口径不算遗漏。
- 题干给定数据可直接用于判断；例外只覆盖指明字段，其余默认条件继续有效。题干说明缺失、冲突或另有时点的值单独核对，不能凭理论可能性把其他已给事实降为未知，或要求逐行复述补证。
- 区分本轮已执行的判断与面向未来的建议。认定事后改标准，须指出哪项本轮判断或实际规则应用被改动；未回填本轮的建议只评其自身合理性。任务允许提出新规则时，不因其未在原规则中出现就判错。
- 先读已展示的回答和来源，缺少的正文按 read_request 补读，图片用 view_image；完整原文直接引用。核心数值或事实尚未对应到来源时，先核对 catalog；有可用工具返回时，用 search_trace 的 tool_returns 范围搜指标、对象或时间字段，再补读命中的完整返回，并核对相关调用与更早返回。按原值核算单位换算、舍入和派生关系，不能只搜回答的展示值。判定所需来源确实遗漏，须审阅相关最终交付及可见来源；关键词未命中或首屏未展示时继续查目录，未完成核查则保留未知，不记缺来源问题。
- 本方规范按指令层级、完整条件和例外核查。区分未触发、免除、可选和必须，不将数量上限或格式要求单独解释为必须新增内容；将适用条件用于全部实际交付。
- 对齐对象、指标、单位、分母、期间和数据版本。不同前提或明确标注的替代口径分别核验；有来源支持且已说明的合理时点映射，按实际对应结果核对，不因日期文字不同直接判错。时间取本方原始上下文，区分事件、发布、更新时间；日期计算覆盖完整区间及例外。
- 有 `review_context.reasons` 时先查对应原句和来源。引用目录只定位材料，须核对来源是否支持对应说法；同组来源可共同支持一句话。区分工具返回、最终回答、真实生成与采集或显示结果，按证据所在层判断。
- 表格或图片有分页、截断或展开入口时，可见预览不等于全部交付。核查关联内容后再判断名单是否缺项；入口只证明可展开，不证明未见内容正确。不能把截图未展开直接记为回答遗漏。

2. 核算数值。
- 用 calculate/execute_code 从可追溯的原值复算。数字按完整语义判断目标、阈值、区间、日期或代码；精度、容差、端点及逻辑关系遵从原要求。
- 精度差异影响判断时，先确认原始数据适用于本题，再将同一未舍入结果分别按回答和标准答案的精度舍入。理由保留算式、原值和对应关系，不做二次舍入，也不反推原值或放宽容差。百分比、百分点和不同量纲按实际含义核查；认定算式错误前先统一量纲计算两侧，数值等价但表述不够直观只按实际误解风险评价。
- `numeric_references` 只是数值目录。`numeric_checks` 仅选题目所求的同口径直接点值；日期、代码、区间或需解释的表达在正确性理由中核验，混合情形仍填写其余点值。
- 每行选择原 reference_index；actual 保留回答原值，缺项填 null，大整数用十进制字符串。scale 是有依据的单位倍率字符串，同单位为 "1"，已展开的万、亿按展开后的单位换算。evidence_index 选择本方最终回答中原值或缺失范围的证据编号。
- rounded 将 actual×scale 按标准末位舍入，exact 精确比较，离散计数用 exact。matches 只记录算术观察；与最终判断不同时，解释原始计算或语义依据。没有直接点值填 `[]`。

3. 写检查结论与发现。
- 按 `criterion_checks` 顺序填写恰好 `criterion_check_count` 行，保留未触发条款。met 须确认该项所需成品、全部适用对象与验收条件均已满足；按原题核对实际完成的动作，主题覆盖或方法介绍不能代替所求结果。partial 写清已交付部分、确定缺口及修正成本，unmet 表示未满足；禁令的 met 表示遵守。条件已确认未触发时说明，尚未确定且无已确认缺口时用 unknown/uncertain。
- `strengths` 和 `problems` 分别记录独立的优点和问题，同一错误及后果合为一项。每条 finding 用 `basis_index` 选择直接对应的任务或本方规范，无对应依据填 null；own_rule 只用于本方指令遵循。text 写具体行为，reason 写证据，impact 写受影响的结果。
- 评审尚未读完来源或核验失败时，在检查项说明缺少的材料，保留 unknown/uncertain，不把评审未完成写成回答的 problem。只有原回答确实遗漏所需来源、存在错误或违反要求时才记录对应缺陷。
- high 影响核心结果或关键决策，medium 影响局部结果或带来实质修正成本，low 不改变结果或决策；额外澄清或背景说明只有确实改变任务可用性才算中高优势，不能反推另一方缺陷。中高问题对应 partial/unmet，证据不足对应 unknown/uncertain；轻微附属错误可与 met 共存。
- 每条发现明确选择直接支持结论的 evidence_indices：final_answer 引用本方最终正文或已查看图片，其余阶段引用本方实际执行。优先选择相关句子、表格行或字段，保留对象、数值、单位和必要条件；连续推导、完整表格行或多来源核验需要上下文时可完整引用。引用长度是呈现建议，程序不因单条或整组字符数退回，也不截断引用；已读且足以支持判断的证据可直接提交，无须为缩短引用反复读取。长材料先搜索相关原词，再按 path、offset、max_chars 补读所需范围。遗漏判断须读完整个相关范围，在 text/reason 中说明检查范围与缺项，引用相关章节或结尾定位；短片段本身不能证明全文不存在。发现必须属于所述对象与阶段，不能把预览缺失、字段名称或格式瑕疵扩大为事实错误或显示失败。

4. 判断核心完成情况与标准答案。
- core_requirements 选择 Schema 允许的共同 requirements 编号，覆盖完成原目标不可缺少的共同交付，core_reason 说明结果和必要限制。meets_core=true 表示已确认交付能完成主要任务；false 表示已确认缺口使任务失败；null 表示影响核心判断的事实尚未核实。所选项为 partial 仍判 true 时，说明剩余结果如何独立完成原目标、缺口及实际修正成本，不能只以有参考价值认定完成。局部偏差不自动使整体不可用，私有规范不替代共同核心要求。
- 有标准答案时，只核对其中回答原题的结果；附带中间值、背景和示例不新增交付义务。is_correct 按对象与数值的实际含义判断一致性，证据至少包含本方最终回答；已确认不符填 false，一致填 true。供应商标识、名称和单位的可解释差异不按字面判错，附加内容的独立错误另记 finding。correctness_reason 说明对照，另判核心可用性；尚未核实时两者均为 null，并关联 unknown/uncertain。
- 无标准答案时，is_correct=null、correctness_reason=""、correctness_evidence_indices=[]、numeric_checks=[]，照常核查事实与交付。

5. 归因与提交。
- 先确认问题本身成立，再定位责任。核对对象、时点、单位和指标：均线与期间最低价等不同指标可以同时正确，不能仅因数值不同判前后矛盾。任务理解、计划依赖、调用参数、来源获取与使用、结果核验、停止时机等只是检查线索；label 与 definition 用中文写实际错误机制，不强套类别或把普通优点、局部缺陷都写成关键步骤失败。
- 有对应记录时，按“完整请求参数 → 实际执行与返回 → 模型实际输入 → 最终回答”定位首次偏离。先读具体请求再判断是否漏条件；历史范围分别核实结果筛选时点、成员成立日期和资料覆盖期，列值时点或资料发布日期本身不能证明取数漏过滤。声称缺数据或因此未完成时，核对可见原始返回与 answer_generation.input_contexts，区分未取到、中间丢失和收到后未使用。按 read_request 补读，不能把原始返回当作模型已见内容。
- component 选择实际出错环节：请求已正确表达条件，工具却未执行过滤、返回错误或同口径结果偏离标准，归到该工具的取数逻辑；错误请求、自编代码、计算或误读已收到的资料归“模型自身推理”；正确返回在输入中丢失或改错归“上下文组装与传递”。代码或 shell 是调用载体，不因执行了错误代码就算工具自身出错。
- 正常权限拒绝、安全拦截和不受支持的请求不算工具自身错误。只有实际过程证明环境、权限或配置偏离预期，并导致所需交付失败，才归“执行环境与权限配置”；模型请求越权或误用工具仍按具体请求定位，不把正常限制当环境故障。
- “回答呈现与采集”只用于实际生产交付被破坏：须核对原生成、实际呈现或交付过程及最终成品。生成标签被采集成 JSON、资源已 resolved、评测截图没有图或目录缺附件，都不能单独证明用户看不到图或收到错误内容。纯采集缺口属于评审材料缺口，保留相关判断未知，不给候选记 problem；不得把评测占位标记当作模型写出的正文。
- 新增两个环节须在本条 evidence_indices 中同时选择本方实际过程和相关最终交付；规范、工具文档、参考材料或纯最终回答不能代替过程。每个责任方分别说明自己的失误及如何传到最终结果，不借其他责任方的证据，也不把同一故障重复记责；没有证据则保持 component=[]。
- 后续未处理已见冲突可另记模型责任，但不能因此漏掉上游工具错误；共同责任须分别写出独立失误和证据。归因停在已定位环节，推测工具内部故障不能作为另记模型问题的证据，也不要求模型识别不可见的标准答案。evidence_indices 的出处不等于责任方。已确认的输出缺陷照常记录为 final_answer/established；无证据定位出错环节时 component 填 []，说明责任未定位，不将缺过程默认归给模型或工具，也不因此降低缺陷的确定性。label 概括问题，definition 写行为、条件和结果。
- 只有结果错误、过程不可见时，不能默认归为模型自身推理；最终回答中明确呈现的错误请求、算式或推导可直接作为模型责任证据，不因缺少实际输入快照留空。本方已给指令及其触发条件已核实、最终行为明确违反时，也可直接归模型，无须先取得实际输入快照；不得借隐藏标准或未证实规范判违规。例如把场内 ETF 的规模直接推成场外联接基金跟踪误差更小，须检查这一推导本身，而不是猜测工具漏数据。指出具体错误步骤，不能从结论不符倒推根因。
- reference_materials 的原始事实可辅助核验，保留来源身份；对方生成的回答不能作为事实证明。本方规范、时钟、工具责任与实际交付仍取本方；正确性证据须含本方最终回答，数值 actual 只引用本方最终回答。
- 表格字面对照只是定位提示，不决定事实或核心状态；按原文判断大小写、全称简称、对象及期间。可用 table_resolutions 记录核查，table_index 选本方 answer_table_index，row_index 从0开始，引用完整最终行及全部既有来源行。该槽位按完整性核验，不能裁剪行或遗漏已知来源；finding 优先选直接说明差异的片段，必要时保留完整行。supported 说明来源如何支持对应关系；无来源行时补读原文，不能用回答或自编代码自证。conflict 须有已确认问题及两侧原文；未知仅限未查清的内容，不扩大到已确认的核心结果。
- 提交前逐条确认问题确有依据、条件已触发、责任和影响相称，再按 submit_evaluation 的 Schema 提交。总评写主要结果与缺口，收到反馈后只修正相关内容。
