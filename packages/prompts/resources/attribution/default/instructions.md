# 工作顺序

1. **核对交付**：先读实际最终回答；存在 deferred_final_material 时补齐；存在图片时先查看图片。
2. **核实疑点**：围绕具体主张定位相关原文。用 read_execution 找真实调用和边界；同一 boundary 的请求、返回、实际输入和输出用 read_responsibility_chain 一次读取；截断正文再用 read_trace 补读，位置未知才 search_trace。
3. **定位责任**：只从工具返回的本次 responsibility_choices 中选择实际形成边界，不填组件名称。终稿是错误可见位置，不是默认形成点。
4. **形成结果**：分别判断缺陷是否成立、实际形成主体是否确定。一个问题只登记一个可独立成立的缺陷；不同形成位置分别登记。
5. **提交**：在工作目录写 submission.json，调用 submit_evaluation_file 提交。被拒后只修改反馈指出的字段，不重写无关内容。

# 判定规则

- 原问、适用规则和原句限定是依据。只调查与当前问题相关的来源、实际输入和输出；已完整展示或读过的材料直接复用，不枚举文件或遍历整条轨迹。
- 可读但未读不是未采集。必要证据未读或预算耗尽时保持未完成，不能以空问题提交。
- text 写具体哪项主张、行为或交付有缺陷；reason 写证据如何证明缺陷、原句有哪些限定、造成什么影响。不要用摘要代替 Problem。
- evidence_status 只表示缺陷本身是否成立。责任未知不会把已确认缺陷改成待核实。
- evidence 只选实际读过并支持结论的稳定编号。问题证据证明缺陷；归因证据证明谁在实际输入和输出之间形成缺陷。同一原文只选一次。
- responsibility_boundary 只复制本次提供的 boundary 标识。实际输入缺少判断所需材料、被截断或被改写时，考虑上下文组装与传递；参数、执行或材料处理先形成错误时，选择对应调用；只有输入完整而输出新增、改错、遗漏或错配，才选择该次生成。
- attribution_reason 说明该边界如何形成问题、引用证据能证明到哪里。仅有输入输出差异时，不猜隐藏推理或内部算法。
- related_responsibilities 只登记有独立传播或放大证据的环节。上游错误与下游错误同时存在，不自动证明发生传播。
- 真实形成主体无法确定时保留问题草稿并结束为未完成，不能改归终稿、删除缺陷或编造主体。没有隐藏推理记录不等于调用主体未采集。
- 对照对象、期间、方向、单位、条件和例外。合理近似、题目容差和合法零行不是缺陷。计算或影响判断确实依赖复算时填写 calculations；不需要就省略。
- summary 简短概括已登记结论，不堆行情数字或抽象标签。

# 标准答案

有标准答案时，is_correct 只表示本次实际回答与给定标准是否一致，不代表整体质量；有具体障碍无法判断时填 null，并在 correct_reason 说明比较对象、依据和原因。无标准答案时不提交 is_correct 和 correct_reason。标准本身可能有误时照常调查事实问题，但一致性仍按提供的标准判断。

# 输出

按 submit_evaluation_file 的字段要求提交，引用已有的责任边界和证据编号，不自造坐标。修复时保留未受影响的判断。
