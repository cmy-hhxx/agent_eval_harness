# 问题表达与严重程度

- 所有生成的描述使用简洁、精确的中文，尤其 label、definition、problem_phenomena、reason、severity_reason 和证据 reason；真实名称、代码和原文引文保留原样，写清具体对象、应有情况与实际表现的偏差。保留决定问题性质的年份、数值、单位和条件；删除套话和重复，不为缩句删掉关键对照。
- problem_phenomena 用一两句写清对象、应有情况和实际偏差，保留决定问题性质的数据；不复述整场过程。例如：“用户问2024年营收，回答却将2023年的100亿元作为2024年数值。”
- label 是可复用的短问题名；definition 提炼同类偏差及适用条件，不带仅属于本次个案的名称、年份和数值。例如：“将其他年份的数据当作目标年份的数据使用。”
- reason 用一句话说明有证据支持的原因及责任动作，不复述现象或逐条抄引文。上述例子可写：“引用来源明确标注2023年，终稿模型将其当成2024年使用。”未查明内部原因时不猜测。
- evidence 的每项 reason 只说明该段原文直接证明了什么。依据错配、缺乏依据与数值错误分别表达；“没查到”不能写成“数据错误”或“造假”。
- 完成原始请求且未违反明确范围或格式约束时，合理的解释、类比、补充应用场景不因“用户未点名要求”就成为偏题或身份错误。未采集到用户画像也不能证明当时模型没有画像；只凭语气、篇幅或个人偏好不能报问题，须有可对照的事实或约束冲突及已确认的交付影响。
- 按原文的实际约束判断，不自行强化条件。相对位置“下方/之后”不自动等于“紧接/必须位于某两节之间”；存在满足原文的合理解释时，不把偏好的版面顺序判成实现故障。引文必须包含声称违规的字段、数值或代码行；仅文件名、标题或代码前半段不能支撑未出现在引文里的后半段结论。
- 每条问题独立填写 severity 和 severity_reason。同类问题在不同回答中可有不同等级，只按本次已确认的影响分级，不按工具异常类型、修复难度或发生次数分级：
  - P0：核心结论错误或关键依据虚构，整份回答不可采信。
  - P1：重要内容错误或缺失，需要实质修改才能使用。
  - P2：局部错误，修正后不改变主要结论。
  - P3：已确认对用户交付有轻微影响的表达或展示偏差。
  - P4：过程缺陷，已恢复或未影响最终交付，例如前几次调用报错或取错、之后修正成功，以及冗余调用、盲目重试。
- severity_reason 用一句话说明具体影响及其为何属于该等级，不重复问题描述。结合已提供的最终回答判断；已补救的问题按残余影响分级，无残余影响的记 P4 并写明如何恢复或为何未影响交付。未确认的影响须如实说明，不能把局部异常写成整份回答失败，也不能把未查证写成已补救。
