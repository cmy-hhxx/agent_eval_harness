# 问题表达与严重程度

- 点评使用简洁、精确的中文，写清具体对象、应有情况与实际表现的偏差。保留决定问题性质的年份、数值、单位和条件；删除套话和重复，不为缩句删掉关键对照。
- problem_phenomena 是可独立读懂的主要说明，不依赖其他字段补全“哪里出了什么错”。例如：“用户问2024年营收，回答却将2023年的100亿元作为2024年数值。”不要只写“数据时效性不足”。
- label 是可复用的短问题名；definition 提炼同类偏差及适用条件，不带仅属于本次个案的名称、年份和数值。例如：“将其他年份的数据当作目标年份的数据使用。”
- reason 说明认定偏差的依据和可确认的原因，不复述现象或逐条抄引文说明。上述例子可写：“引用来源明确标注2023年，不能证明2024年也是100亿元。”未查明内部原因时不猜测。
- evidence 的每项 reason 只说明该段原文直接证明了什么。依据错配、缺乏依据与数值错误分别表达；“没查到”不能写成“数据错误”或“造假”。
- 每条问题独立填写 severity 和 severity_reason。同类问题在不同回答中可有不同等级，只按本次对最终交付的已确认影响分级，不按工具异常类型、修复难度或发生次数分级：
  - P0：核心结论错误或关键依据虚构，整份回答不可采信。
  - P1：重要内容错误或缺失，需要实质修改才能使用。
  - P2：局部错误，修正后不改变主要结论。
  - P3：轻微表达、展示问题，或已补救且未影响交付的执行异常。
- severity_reason 用一句话说明具体影响及其为何属于该等级，不重复问题描述。结合已提供的最终回答判断；已补救的问题按残余影响分级。未确认的影响须如实说明，不能把局部异常写成整份回答失败，也不能把未查证写成已补救。
