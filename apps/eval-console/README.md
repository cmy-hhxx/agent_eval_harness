# 评测控制台

[返回首页](../../README.md) · [部署](../../docs/deployment.md) · [运行与产物](../../docs/usage.md)

一个独立操作页，问财执行对比，AIME 执行归因。用户可修改评测输入、评测输出、并发和缺省批次；启动前预览配置与只读日志位置，可以下载同样的业务配置。模型、双渠道、各阶段推理配置、超时与业务规则均来自服务器预设，不在页面提供调整入口。Eris 保持只读。

## 模块边界

页面在 `web/`；HTTP、任务管理、文件查询与评测适配在 `src/`；测试和配置样例也在本目录。模块单向使用 Host 的公开配置、预检、组装入口与通用 Workflow/Runtime/Data 能力，原 CLI、Worker 和 Eris 不依赖控制台。已有 case 跳过与动态模型请求额度属于评测底层能力，两种入口共用。

## 操作

1. 登录后选择问财或 AIME，点击顶部“新建评测”。
2. 在抽屉中选预设，填写一个输入父目录、输出位置、并发和必填的缺省批次。每次新建或切换预设时批次框均为空，必须自行填写，不继承预设批次。原始输入已有 `batch_id` 时沿用原值，缺失时才使用缺省批次。父目录下按预设模型 ID、名称或同名 JSONL 文件识别输入，递归读取匹配模型的 JSONL；隐藏目录、归档目录及符号链接不递归进入。不匹配模型的文件会提示数量，不会混入评测。
3. 点击“Check data”即保存任务并返回任务列表，服务器继续统计，离开或刷新页面不会丢失。检查中显示已读条数和文件进度；检查完成后点击“预览”，查看将读入、可评测、已有结果跳过、预计待评的数量，以及输入、预计主要结果文件、并发、日志位置；确认后“启动评测”。AIME 按回答计数，问财按对局计数，无效输入和无法配对单独展示。重复提交同一个预览不会重复创建运行。
4. 任务列表直接提供暂停、继续、调整并发、日志、配置和删除；完整路径与错误堆栈按需展开。删除需确认，仅移除工作台任务记录与配置，保留原始输入、正式评测结果、运行恢复状态和日志。运行中或暂停中的任务须等待暂停并保存完成；检查中的草稿可直接删除并中止检查。

并发是单个任务两条内部渠道合计的真实模型请求上限。两条等价渠道可以借用空闲额度；多个任务的上限各自独立。提高并发同时扩大模型请求额度与调度容量。降低并发不取消在途请求，待它们完成后回落到新上限。

暂停停止派发新工作，已派发的评测工作完成并保存，期间显示“暂停中”。继续使用同一个任务，解除阶段暂停，并在剩余预算内重试失败或阻塞的工作；控制服务重启后不会自动发出模型请求，任务显示“已暂停”，由用户继续。

已有最终输出按模型（或模型对）、业务批次与 case 跳过，不要求旧 run、旧收据、原输入正文、配置或评测器版本匹配。Compact 等中间文件不算完成。若要对同 case 重新评测，选择另一个输出目录。旧结果保持原样，不补字段，不重新署名，也不伪造历史收据。

输出由用户指定，没有固定根目录限制。输入必须在该预设登记的输入范围内；输入输出不可重叠。预览检查文件存在与目录可写，并去掉目录名的数字前缀及 input/output/eval 等标记，轻量比对业务名称。名字未对应仅提示确认，不自动改路径。父目录输入读取本次发现的全部匹配文件，清除预设中旧的 records、limit、batches、case_ids 与 dataset_id 选择，不继承原任务的局部数据范围。脚本也可显式指定各模型路径；这种方式只有路径变更时清除旧 records。

Check data 不构建评测任务图、不启动 Worker、不调用模型，不复制输入正文。单次流式读取输入，复用当前适配器核对回答，按同一套最终输出身份计算预计跳过数；只保留统计值和少量异常示例，完整错误进入统一日志。问财仅扫描对局最终结果，AIME 仅扫描归因最终结果。检查不使用哈希或持久化输入缓存，同一服务一次只执行一个检查。大目录统计持续返回进度；完成前不能启动该预览。计数是检查时快照，检查期间变动的输入需重查，启动仍读取最新正式结果决定实际跳过量。关闭服务会中止检查，重启后任务仍在列表中，可点击“重新检查”；已完成的检查直接恢复，无须重扫。

进度显示当前已规划步骤的完成数量，后续输入尚未发现时不伪造全量百分比。加载首批输入时显示“加载输入”；暂停后保留进度，完成后显示完成状态。

控制台的常规问财对比按业务批次与 case 对齐各模型，首个 case 就绪即开始执行。读取窗口沿用预设 sessionWindow；完整输入不需要先扫描到底，只保存薄索引、未对齐的 case 和字节读取位置，正文按需读取。乱序记录继续匹配，缺失或无效回答记录原因，独立 case 继续；已读位置在暂停后保留，续跑不从头扫描。输入 limit 限制首先就绪的 case 数，不使用它估计全量启动速度。显式聚类与 prediction 分析仍使用其整批规划器；已有固定运行与维护范围保持原任务范围。AIME 沿用其分批归因加载。

## 部署

仅在服务器运行真实评测。本地可以构建与模拟测试。控制台使用独立 checkout，沿用已有 `config.ini`；新环境先完成 [Host 安装构建](../../docs/deployment.md#评测-host)。

复制 [config.example.json](config.example.json) 到外部配置目录，填写实际路径。`presets[].configs` 顺序与原评测的配置链一致，各文件相对路径按自身位置解析；输入白名单 `inputRoots`、管理员密码文件及状态/日志目录相对控制台配置文件解析。`concurrency` 是预设初始值。

管理员密码文件只保存密码，至少 16 位，限制文件权限为 `600`。文件不得提交到 Git。启动：

```bash
EVAL_CONFIG_FILE=/absolute/runtime/config/config.ini \
  npm run console -- --config /absolute/runtime/config/console.json
```

服务器入口为 `http://117.50.195.94:3928`，映射后端 `5004`；样例监听 `0.0.0.0:5004`。需要仅内网访问时改为本机监听并使用 SSH 转发。控制台页与 API 使用同一管理员身份，不修改旧评测进程。服务退出时等待自己管理的任务排空。

批次命名、安全限制和正式文件名见[目录约定](../../docs/usage.md#目录约定)。

每个预览在 `stateDirectory/<任务ID>/` 保存完整的解析配置与任务元数据，不复制输入正文。日志只写 `logDirectory/runtime.log` 与 `logDirectory/evaluation.log`，Worker 沿用同一目录；两者仍由 Data 统一处理脱敏与写锁。隔离验证应使用独立状态目录和日志目录、低并发，以及独立测试输出。生产切换前由操作者停止旧任务；控制台不会代为接管。

## API

浏览器登录使用 HttpOnly、SameSite=Strict 会话 Cookie；写请求携带 `X-Console-Request: 1`。脚本可使用 `Authorization: Bearer <管理员密码>`。密码不放 URL。所有业务 API 均需认证。

| 方法与路径 | 用途 |
|---|---|
| `POST /api/login` | `{ "password": "…" }` 登录 |
| `POST /api/logout` | 退出 |
| `GET /api/presets` | 读取业务预设及输入、输出、并发和日志 |
| `POST /api/previews` | 校验必填 batchId、解析父目录、固定配置并启动 Check data；立即返回草稿与检查状态 |
| `POST /api/tasks` | `{ "previewId": "…" }` 启动已预览的配置 |
| `GET /api/tasks` | 全部任务（含检查中、待启动、检查失败）、状态、在途数量及输出位置 |
| `GET /api/tasks/:id` | 单个任务，含 dataCheck 检查进度、预计计数、输出文件与错误 |
| `POST /api/tasks/:id/check` | 在原待启动任务上重新检查，保留任务 ID 和配置 |
| `POST /api/tasks/:id/pause` | 排空在途工作后暂停 |
| `POST /api/tasks/:id/resume` | 继续缺失工作 |
| `POST /api/tasks/:id/concurrency` | `{ "concurrency": 8 }` 动态调整请求上限 |
| `POST /api/tasks/:id/delete` | 删除任务记录与配置；运行中返回 409，检查中的草稿中止检查；保留输入、评测结果、运行恢复状态与日志 |
| `GET /api/tasks/:id/configuration` | 下载业务配置与只读日志位置，可再次预览，不含模型参数或密钥 |
| `GET /api/tasks/:id/logs` | `kind=runtime\|evaluation`、`errors=1`、`cursor=字节位置` |

预览请求：

```json
{
  "preset": "aime-daily",
  "inputDirectory": "/absolute/aime/input",
  "output": "/absolute/aime/output/daily",
  "concurrency": 2,
  "batchId": "search_eval"
}
```

轮询 `GET /api/tasks/:id`，待 `dataCheck.status` 为 `ready` 再启动任务；`failed` 时查看 `dataCheck.error`。脚本可改用 `inputs: { "模型ID": ["绝对路径"] }`，但不能同时传 inputDirectory；模型 ID 由预设返回，不由调用方猜测。日志按任务隔离展示，每次读取最多 1 MiB，返回 cursor 可继续查找更早记录；错误保留时间、阶段、任务/调用定位、原因和堆栈等现有字段。输入、启动、执行、持久化错误都会返回明确错误或进入运行日志；“部分完成”不冒充成功。
