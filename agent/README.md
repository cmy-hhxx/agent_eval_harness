# Eris

Eris 是通过浏览器使用的 Web Agent，交付 Web 界面与 Node 服务端。启动与维护使用项目的 POSIX 工具链，不提供桌面应用、独立客户端安装或 Windows 启动适配。

在项目根目录启动：

```bash
bash agent/run.sh
```

脚本使用 `lsof` 检查目标端口，启动准备前及构建完成后都会停止占用该端口的旧进程：先发送 TERM，等待最多 5 秒，仍未退出则发送 KILL；端口无法释放时停止启动。其他端口的副本不受影响，`--port 0` 使用动态端口并跳过清理。随后读取根目录 `config.ini`，检查依赖和两套 SDK 构建，构建独立 Web 应用，等服务监听成功后打开浏览器。正常启动显示清理、准备状态和访问地址；准备失败会输出完整错误并退出，`--debug` 显示全部安装与构建诊断。对话运行时只使用 Pi。首次安装沿用项目的 Node/npm/uv/Python 工具链，见根目录 [README](../README.md)。

```bash
bash agent/run.sh --port 4181 --user alice --no-open
```

默认端口 `4180`、用户 `local`。入口 `/u/alice/` 或 `/?user=alice` 可指定用户；不同端口的本机副本共享 `data/assistant`。只监听 `127.0.0.1`。`userId` 是可信本机环境下的数据归属标志，不是登录或鉴权。按 Ctrl+C 停止服务。

## 模型与设置

Eris 与评测共用 `config.ini` 中的全部渠道，格式见[配置说明](../docs/usage.md#环境与配置)。每个渠道使用自己的地址、密钥与 API 读取模型列表和发起请求；同名模型按渠道区分，专业调用使用评测阶段绑定。

默认继承 Attribution 的渠道、模型和推理等级。可在 INI 的 `[agent]` 中指定 `channel`、`model`、`thinking`、`context_window`、`max_output_tokens`；默认模型须为 GPT Luna。每次模型请求前（包括同轮工具返回后）检查上下文，超过80%自动压缩；压缩摘要和保留边界落盘后才继续，刷新或续聊沿用该边界。所有渠道统一使用 `[agent].context_window`，默认 1048576（1M），不被网关缺失或偏小的容量覆盖。输出容量仍沿用渠道配置和模型目录，未配置为8192；设置 `models` 白名单的渠道另受配置输出上限约束。

模型选择器按渠道只列出 GPT Luna 系列（包含渠道提供的 Luna 变体），常用模型在所属渠道内优先排列。未保存常用模型时，初始模型与各渠道配置的默认模型作为常用项。保存后，以首个仍可用的常用模型作为新会话默认；已有会话保留自己的渠道和模型。模型目录读取失败或白名单中缺少模型时明确报错。

外部搜索使用 Serper。在根目录 `.env` 或 `config.ini` 的 `[environment]` 设置 `SEARCH_API_KEY`，再重启 Eris；启动时 `.env` 只补充尚未设置的进程变量，INI 显式配置随后覆盖，运行中的服务不热读密钥。此 `.env` 加载仅限 Eris 入口，不改变评测启动。搜索请求由服务端发送到 `https://google.serper.dev/search` 或 `/news`，密钥不发送给浏览器。未配置密钥或服务请求失败时直接报告搜索错误，不降级为未经检索的答案。

点击左下角“设置”→“常用模型”→“勾选常用模型”，服务端使用 `config.ini` 中各网关的独立地址和密钥读取 `/models`。输入框右下角可直接切换各渠道的 Luna 模型与推理等级；常用选择只影响排序与新会话默认。`/model` 也使用同一选择器，支持模糊搜索与服务商分组。思考等级使用滑杆，只呈现当前模型实际支持的档位；普通档为朱红色，仅最高档显示深红至暖金渐变和粒子特效；拖动预览，松手或方向键调整后保存，右上角恢复模型默认档位。保存期间禁用调整，失败沿用当前选择并显示错误；滑杆支持键盘与减少动态效果偏好。常用模型按用户保存，当前模型、服务商与推理等级写入会话追加记录，刷新、续聊和本机副本转发后保持一致。切换不打断正在执行的轮次，下次用户请求使用新选择；空闲时切换立即更新上下文容量显示。取消当前轮次或关闭服务时，即使模型目录或会话仍在准备，也不会在准备完成后发起该轮模型调用；已发送消息在模型准备、压缩、取消和重连期间均保留在对话中，后续请求可继续。密钥不会发送给浏览器。

设置直接复用上游面板。通用设置包含语言、会话字号、工作步骤展示、性能与用量和繁忙时的发送行为（排队 / 插话），按用户保存，刷新和本机副本间保持同步。默认详细展示工作步骤，字号范围为 10–22 px。排队消息在服务端接收后可编辑、移除或在运行时转为插话；已提交的插话不能再编辑或移除。会话菜单沿用上游的分组、快捷键提示与键盘操作。外观固定浅色；运行状态显示“正在分析”和已用时间。

## 下一问补全

回答完成且输入框为空时，Eris 结合当前问题与最近对话补全一句简短、口语化的用户追问，以灰色文字显示。追问侧重具体归因：错误或遗漏怎样形成，回答的哪个环节出了问题，原文有什么依据；胜负与统计作为背景，不主动安排下一步任务、改进计划或验证方案。模型沿尚未讲清的原因自由发挥，不划分阶段或预设责任；已讲清的内容和已知缺失的信息不用重问，用户换题时跟随新意图。按 Tab 填入草稿，按 Enter 发送；Esc 隐藏建议，Shift+Tab 保留焦点导航。沿着建议输入时可补全剩余文字；改写为其他内容、使用中文输入法、打开命令菜单或切换会话时不会误采纳。

预测复用当前会话的渠道与模型，关闭推理，无工具调用，单次最多256输出token、8秒超时，每轮只尝试一次。材料分别标出最初请求与最新请求，以最新明确意图为先，并保留最近10条可见对话或成功的图表回执，每条最多2400字符；不重新读取证据、不写入会话或正式评测结果。预测在已完成的会话材料之后单独接收起草下一问的任务，直接输出一句用户请求；近期已展示的建议用于避免语义重复，程序只校验问句格式、长度与重复原句，不分类对话阶段或限制下一步方向。没有有用的下一步时不显示，失败不阻塞正常输入。提示词维护在[下一问预测](../packages/prompts/resources/eris/prediction.md)，浏览器回归可单独运行 `node agent/tests/browser-prediction.mjs`。

## 能力与数据

可查询已登记的本地评测运行，分页读消息和正式判词、搜索本地文本、查看图片、定位证据、做十进制计算，按需搜索外部网页和新闻、读取网页和PDF原文，独立调用 Attribution / Comparison，并在对话内呈现有正式结果依据的总结。专业任务先固定共同 Criteria；Comparison 支持二至三同档模型，Fast 只与 Fast 比、Expert 只与 Expert 比，并按需归因后两两裁决。输入目录返回模型展示名、声明档位和运行配置的比较组；未声明档位或混档的专业比较直接拒绝。已有归因仅在共同标准完全一致且通过当前校验时复用，否则独立重评并保留原收据。三模型返回 `result.comparisons`，每场都有正式结果与真实引用；首次对比前的归因补查完成后，返回主线对比的正式引用；可选事后核验不替换该引用。看板和批量 Workflow 仍由原入口启动。

比较图展示前，使用本会话当前网关、模型和推理等级独立检查当前对战的已读原文、反证与结论；按解析后的正式引用和双方回答引用筛选材料，续聊和恢复后保留此前轮次属于该对战的全部已读证据，不发送其他题目的评语或链路，不携带此前推理，也不调用工具。常规解读核对转述与已知反证，不因未重读长链路而要求重新评测。核对结果使用 Schema 约束；检查发现漏反证或将待核验写成排除时，返回具体问题供修正，检查通过后才展示和结束。未通过的草稿保留失败回执，工作步骤显示“草稿待修订”及逐条核对意见；模型修订后重新提交，未通过的草稿不展示。网关或核对格式错误仍作为执行失败呈现。额外模型耗时、用量和核对意见保存在该工具回执的 `consistencyCheck`，不创建额外会话、不修改正式评测结果。这项检查用于结论与证据的一致性，不代替原始取证。

## 自主代码核验

`execute_code` 复用通用 Python / Shell 执行器，可在会话独立工作目录中复算公式、筛选数据、编写断言与生成中间文件。使用根 `.venv` 的 Python 标准库环境，单次最多60秒，取消会回收本次进程组；脚本环境不继承网关密钥。工作目录用于归属与整理，不是操作系统沙箱，原始输入与正式结果仍遵守只读规则。

代码回执只展示 stdout / stderr 各前4000字符；完整脚本、输出及显式产物属于当前会话，通过 `read_code_output` 分页读取。正式判词与专业结果默认返回过滤 evidence 字段后的完整结论，保留润色点评、判决和问题归因；需要核查证据时显式用 `view:"details"` 读取原结果，默认8000字符、最多16000，按 `hasMore` / `nextOffset` 续读。过滤只作用于模型读取，不改正式结果；不会为了翻页重新执行代码或专业任务。

### 外部查证

`search_web` 用于金融事实核对与评测点评、总结的交叉查证，`search_data` 只搜索本地原始输入；空格分隔的关键词在同一节点做全部匹配，返回各词位置，数组表示多个独立查询；默认 scope:evidence 只搜原始工具返回；查回答、推理、指令或请求快照时用 scope:all，返回值明确标明范围，完整原文和分页仍保留。查询工具接受1–4个明确查询计划，最多两路并发；每项可指定最多5个域名、地区、语言和第1–3页，每次取最多10条，合并默认10条、最多20条。支持网页 / 新闻、相对时间范围或包含端点的绝对日期范围。实际请求、耗时、可用credits、失败与合并命中位置均返回；按倒数排名融合排序，规范化URL去重，不改变业务查询参数，没有自动重试或跨会话缓存。每个子请求结束都会释放请求资源；失败HTTP响应不读取正文，只取消响应体，清理不阻塞错误返回。查询Schema是当前唯一入口，见[工具Schema](../schemas/eris/tools.json)及[Contracts](../packages/contracts/src/assistant.ts)。

`read_web` 读取公开HTML、PDF和纯文本，返回实际原文、行号及PDF页码。默认80行、最多200行，每个窗口最多20000字符、标题最多500字符，可用字面词及匹配行预览定位、按返回起点续页或指定PDF页；HTML还返回实际正文附件链接。页面含未加载占位时明确标注内容缺口；解析最多200页，目标文件上限15MiB，超时30秒。PDF不做OCR，表格抽取会丢失版式；必须核对相邻表头、单位与脚注。网页仅提取正文，不执行脚本。页面访问限制、无正文、无可抽取文字或截断均明确报告；HTML页面声明发布与修改日期分列，PDF创建时间和财年截止日不充当发布时间。

日期检索条件只是候选过滤：`dateAssessment.within_range`表示搜索或页面声明日期在范围内，不证明当时已公开或未被修订；日期未知的候选需继续核验。历史审查先确定截至日期，再核对首次发布及当时版本，不能用后来的镜像、修订值倒推过去错误。外部事实与原始材料、正式判词和Eris分析分别说明；外部查证不能写回或改变正式判决。精确数字、冲突与否定结论读取原文，联读季度/全年、财年/自然年、经营利润/净利润、百分比/百分点等口径；引用给实际最终链接、PDF页码或必要行号、页面声明日期或检索时点。没有命中不是反证，摘要不足以确认精确数字。查询与原文结果一次性记入会话，刷新、展开及恢复不重新联网；Key仅发送给Serper，原文请求逐跳验证公共地址并固定DNS连接，阻止内网读取。

点评口吻、篇幅、图表使用门槛、查询策略和金融推理规则统一维护在 [Eris 系统提示](../packages/prompts/resources/eris/system.md)及[各工具说明](../packages/prompts/resources/eris/tools/)。修改这些规则时直接更新提示词与对应验证，不在使用文档复制一份。

Eris 向模型开启并行工具调用；评测 Worker 仍按自己的串行协议执行。同一模型响应中的独立只读工具最多4路并行，包含专业调用的批次按声明顺序执行。取消后排队的读取不再启动；每个结果（包括失败）均持久化后才进入下一轮模型请求。多个外部搜索计划应合在一次 `search_web` 内，维持每次最多两路 Serper 请求。具体来源与分页存在依赖时仍需等待前一轮真实引用；并发不替代证据核验，也不增加自动重试或结果缓存。复核与深查用 `read_case(review:true)`，模型保留完整问题与答案，用 originalVerdicts 保留原胜负身份，先按实体检索，不预载节点地图、旧评语及其证据筛选清单；用户展开界面仍可查看完整地图与原评语，正式数据不改写。`show_comparison` 必须显式填写 `complete`；在证据已核对且图已完整回答请求时使用 `complete:true`，成功即结束当前回复，省去图后空转；确有后续任务填 `complete:false`；混合读取、参数错误或未完成请求仍继续。正式结果、图表与引用先持久化再结束，刷新后可恢复。

Eris 的 Responses 函数工具显式设置 `strict: false`，保留 Schema 中的可选参数语义，避免网关自动将其变成必填。工具仍在 SDK 转换参数前校验原始值，拒绝类型强转、空值代替省略和无效运行标识；错误包含字段路径与约束，不静默修正请求。搜索全部子请求失败、专业执行失败或取消会标为工具错误并保留原回执；搜索部分成功和成功但零命中分别保留，不伪装成同一种失败。单轮同一工具与参数失败3次时停止工具调用，保留已落盘结果，并给模型一次禁用工具的最终总结请求；总结使用已成功的结果并交代缺口。下一条用户请求重新计数。有效调查不设固定轮数，用户可随时取消。恢复时，已压缩掉的原始材料不重读；仍需读取但已不可用的材料作为证据错误返回模型，其他会话内容保持可续聊。

### 图表与来源

统计图只显示被评数据的日期/批次与分档场数，如“2026-10-11 · Fast 278场、Expert 270场”。已保存回复也去掉评测起止、截止与阶段状态长句；原始统计来源保留在工具记录，不重复展示。

轨迹的 Schema 面板读取会话中的 `request/header` 工具目录；目录或模型变动才追加快照，不逐步重复保存。面板完整展示工具说明和参数 JSON（含嵌套字段、必填项、枚举与约束），可一键复制完整调用时定义；概述仍用紧凑树形预览。这里展示发给模型的参数定义，不是严格输出模式开关。工具仍在执行前按 Schema 校验；历史会话未记录的 Schema 不补写。

战绩作图用运行与档位组成的 `statistics` 引用，服务端一次读取并核验该档完整正式统计，把全部结果坐标保存为图表来源；模型无需逐条复制任务清单。单个案例仍用具体 `reference`，普通运行统计用 `runId`；外部网页、研报、行情等材料作图不传 references，来源名称和日期写 `source`，回复不附第三方链接，不为凑引用去读无关运行。

单组环形组成图使用 `pie`（一个 series），多层环形对照使用 `concentric`（2–4个 series）。`show_chart` 的当前图形类型与参数直接见[工具 Schema](../schemas/eris/tools.json)，服务端及展示数据校验分别在 [chart.ts](src/core/chart.ts) 和 [charts.js](src/client/charts.js)。缺失值保持未知，零值保留；分箱、累计、四分位数等派生显示由程序计算，区间必须来自真实上下界，不生成置信度或显著性结论。

绘图代码随页面入口一起加载，显示回执时不再请求额外脚本；页面就绪后，即使重新构建清除了旧资源，也可继续绘图。绘图不依赖外部 CDN。加载回归使用 `node agent/tests/chart-loading.mjs`，逐张验证全部模板在后续脚本请求均返回404时仍能绘制与重新挂载。

前后端文字限制均按 Unicode 字符计数。极小数值仅在绘图坐标中按科学计数尺度换算，并显示倍率和单位；回执与辅助阅读保留原始值。零面积气泡显示明确的零值标签，不放大为非零面积。成功回执损坏时明确显示图表数据错误；每张图的渲染异常独立处理，自动重新挂载一次，仍失败则显示错误并允许重试，不隐藏正文或其他图表。异常、隐藏容器恢复及实例释放回归使用 `node agent/tests/chart-resilience.mjs`。

频数图的中位数与四分位区间放在绘图区上方的独立数据行，图内参考线和阴影不叠加文字。鼠标点击图形不显示矩形焦点外框，键盘导航保留焦点提示；所有统计图不显示 hover 提示框或点击悬浮文字，扇区、色块、点位与线条等内部图形共用轻微提亮、放大与淡阴影，统一以240ms自然缓出；放大不超过4%，边缘外扩不超过2px，数字与标签周围保留3px保护区，放大和阴影都不得遮住文字；画布、文字、原始命中区域与布局占位保持不动；完整读数通过辅助阅读与键盘获得。

坡度图的数值位于两端独立标签列，相近或相同值按最小行距避让，连接线保留实际数据坐标；阶段名与数值分区。其余统计图的标签、刻度与注释也须保留间距，不允许文字重叠。

矩阵按实际行数保留可读色块高度，列名贴近绘图区。单位为“场”、包含完整四类对战结果且各档计数均为非负整数时，标题右侧显示合计，Fast / Expert 行或列标明本档场次；未知值、缺少结果类别、百分比或可能重叠的数据不推算总场次。热力矩阵直接显示实际数值；悬浮使用统一的内部元素效果，文字保护区内保持颜色与文字对比度，不出现额外文字。方向键辅助阅读包含对象、精确数值及本档占比，Escape 或失焦清除选择。

结构图包括面积玫瑰 `rose`、多层环形 `concentric`、多环进度 `radial_progress`（至少两个独立指标）、统一量纲雷达 `radar`、原始计数华夫 `waffle`、两层旭日 `sunburst` 与矩形树 `treemap`、守恒无环流向 `sankey`、对称共现弦图 `chord`、经验累积分布 `ecdf` 与统一带宽山脊 `ridgeline`，总计24种图形。环形分类集中展示玫瑰、环形、多环进度与旭日；小图直接标记数据，完整观测保留辅助阅读。数据要求由工具契约校验，不能用花样替代真实流向、完整组成或原始观测。

统计图直接读取本轮成功的 `show_chart` 回执，自动在最终回答开头显示一次，无需正文引用。同一轮内相同统计来源（运行与档位）、图形类型、单位、类别和系列只展示最新成功版本；标题、数值与场数更新替换旧图，失败或损坏的修订不覆盖已有图，不同统计视图独立保留。刷新后沿用同一规则；中断或失败后没有最终正文时，图保留在本轮末尾。正文中的 `chart` 围栏统一不显示，不承载图表数据或位置。批量分析优先用紧凑表格或短段落归纳跨题共性、差异、影响及改进重点，汇总图按需使用，避免因读取多个案例而逐题铺大图。`show_comparison` 更适合用户明确要求的单例详析或案例图，重点画一张；批量任务确需图解时挑最有解释力的一例，普通追问通常用文字，由模型按当前问题选择。`show_comparison` 使用固定的三层案例对比模板：共享问题层、双方实际答案层、双方用途层，分别对应“用户问了什么→回答给了什么→对用户有什么用”。问题保留核心诉求且只显示一次，原评测判定与当前分析结论放在三层之前；复核按原文纠正或限定旧结论，不必维护原胜负。答案层双方外框等宽等高，用途层等宽顶对齐、按内容自然收尾；每方保留1–3条独立论证，证据状态不同的对象分别列项，每项只填 evidence 一句依据和 impact 一个明确影响，不按条目序号强行配对。桌面在答案与用途之间使用短直箭头，窄屏按层序阅读；不重复原问或猜测模型内部过程。底部只放比较口径，不再追加结论或新问题。路径分别标明优点、问题或待核实，正式胜负不替代逐项评价。模型概括材料中的具体事实和影响，组名、胜负状态和正式判词由引用对应的已决结果填入，连线、顺序与样式由程序固定。正文只补充图中没有的关键证据、责任定位或判断边界，不重列表格或复述图中结论。“不适用”只用于要求不约束该候选；没有同类错误写“未见同类问题”，材料不足写“待核验”。必要核验和计算在作图前完成，作图成功后直接收尾。每项依据最多60字，counterEvidence 必填（没有反证填 null），非空最多80字并入同一卡片，原文反证不再靠正文补充；影响最多36字，不截断原文以凑版面；高亮默认省略，每项 highlights 最多选择一处原文短语，连同 reasonHighlight 整图最多两处、每处最多16字。字段长度、整图数量与唯一子串关系均校验，不接受任意富文本。工具不接受自定义节点、连线、判词或绘图代码。图形独立于工作步骤，折叠步骤不会隐藏，刷新使用已保存结果。布局、配色、标签与辅助阅读要求统一见 [PRODUCT.md](../PRODUCT.md#eris-评测助手)；选图、篇幅与证据规则见[作图说明](../packages/prompts/resources/eris/tools/show_chart.md)。总结、报告和表格只在对话内展示，不提供文件下载链接；仅图片允许下载。Eris 回复不附第三方链接，必要来源只写名称和日期；历史与流式回复中的网页链接显示为普通文字，工具详情保留取证来源。

本地模板库：启动后打开 `/u/local/chart-gallery.html`，按分析类型筛选并复制数据载荷。模板清单以 [chart-templates.js](src/client/chart-templates.js) 为准，复用正式渲染器与校验；预览使用固定示例，不是评测结果。

### 本地运行与结果

目录通过 Workflow 的进度投影，按登记输入与任务标识统计回答数、去重题数、模型覆盖和各阶段状态。输入的关联任务在单次读取中统一索引；同一图表的各档统计共享本次运行读取，不跨调用缓存。首次 `list_data({})` 只给数量与战绩，指定 `runId` 后仍只返回统计计数；逐场记录通过 `view:"comparisons"` 分页读取，避免基础概览混入整批案例叙述；批量总结加 `includeAnalysis:true`，同页返回完整原问、双方评测摘要、问题维度、判决理由与取舍，不读取原始答案和链路，也无需逐场再调用 `read_data`。来源数据保持完整。默认 `currentRun` 优先选有输入且正在运行的记录，否则选最近开始的有输入记录；零输入维护运行不抢占范围，历史试跑不重复累加。同 case 跨批次分别计题，同题 Fast / Expert 仍计一道题。

`list_data({view:"statistics"})` 通过自动化发布状态选择最近完整完成且日志上传成功的累计快照，按冻结统计契约校验后读取；只返回汇总，不扫描旧运行结果。历史保留快照时间和被评数据日期，运行中批次在 `currentRuns` 单列，两者可能重叠，不能相加。快照缺失、非法或尚无成功发布时明确返回不可用，运行中批次仍可读取。

单运行读取正式结果生成 `formalComparisonStats`；失败时返回 `null` 和 `statisticsError`，保留输入目录及进度，不静默把失败转成零。比较目录需要有效正式统计，失败会明确报错，不通过换分页或筛选重试。结果份数与对局场数分列：三模型形成三份两两结果、三场对局。各档战绩按保存配置与正式 `verdicts` 计算，提供各档完整计数；对战目录按页给原问预览、模型展示名、结果类别、正式结果引用及双方原文引用；核验、草稿和待核结果不算正式对局。`read_data` 保留完整结果，并为已裁决比较补充 `comparisonScope`。

按用户请求区分总览、批量归纳和单例详析。常规总结与胜负解释先读评测结论；案例图按需补读双方答案，复核、追问错误来源或关键依据缺失才定向读取原始链路。全局概览使用同档完整统计，说明总体战绩、主要问题维度、分母与覆盖范围；全统计引用的图表由程序用一行显示被评数据日期和分档场数，模型可省略 scope；不展示评测起止、截止或未知日期说明，不加载或展示链路地图。`tiers.models` 同时提供达成核心要求的 `meetsCoreCount` 与各维度问题场数 `problemDimensions`：以该模型正式参战 `comparisonCount` 为分母，同场同维度同证据状态只计一次，已确认与待核验分别计数且可重叠。多模型两两对局会重复覆盖同一回答，不能当成独立样本；这些计数是正式结果记录的问题频次，不是客观错误率，也不证明输赢原因。案例用 `read_case` 一次读取用户原问、双方最终回答、过滤证据正文后的正式评价与判决，以及每个回答的轻量链路地图；单条回答也可用 `inputId` 读取。正式结果的各项 `evidence_references`（或 `*_evidence_references`）保留证据节点的直接引用，同一项同一节点去重，不携带引文。地图只给步骤类型、工具名、调用关联和短预览；关联来自调用 ID 或全链路唯一的工具名与完成时间配对，遇到冲突不猜测；模型的调用预览优先显示源 description，仅作导航，核验仍读实际参数；模型读取时用回答的 reference 加节点 messageIndex 定位，界面仍保留各节点完整引用，不重复模型请求里的历史输入，也不把顺序当因果。有具体证据缺口时，同一回答的必要节点合成一次 `read_evidence`（图像用 `view_image`），无需先补读正式结果目录；跨回答的独立读取同轮并行。批量每次1–12个节点，仅解析一次原始输入，同节点同格式多页复用本次材料提取；各节点独立返回引文坐标、分页和错误。format 默认 text 提取字符串，json 保留完整结构与原生数字、布尔值；偏移只属于当前格式。搜索优先匹配文本，未命中再搜索原 JSON，返回 format 和可直接续读的 readOffset。模型上下文保留完整 text 正文与节点 reference、format、offset，不重复逐片段引文坐标；工具详情、链路现场与复制仍保留所有原始引文和坐标；批量取证默认及最多16000字符，单节点读取默认8000字符，截断处按 `nextOffset` 续读，对材料作全量否定前须读完相关节点，或明确限定已读范围；不省略决定性证据，也不缓存跨请求结果。超过16000字符的最终回答显式标记未完整加载，并给原文引用。区分原材料、正式判词和助手分析。目录筛选为空或缺少结果只表示当前查询范围没有对应记录；未记录的指标保持未知。措辞、抽样边界和金融分析要求统一见 [Eris 系统提示](../packages/prompts/resources/eris/system.md)。

单场回复下方直接显示“链路小现场”，节点使用 System prompt、User input、Reasoning、Model call、Assistant message、Tool call、Tool result 和 Final answer 标签；工具节点标题直接附工具名，节点不显示字符数或副标题；展开后按模型分别折叠流程图，灰色竖向实线和清晰的实心箭头表示执行顺序，选中节点时才显示来源确认的低饱和青色调用关联虚线，沿节点外侧的固定竖线作圆角转折，端点与节点中线对齐并留出边框间隙；节点以深色文字呈现，用少量低饱和色标区分输入、推理、工具与回答，图面去除背景、阴影与外层卡片框，收紧节点高度、间距与两栏留白，节点正文保持13px；流程图区最高560px且不超过视口高度65%，短链路按实际高度展示；同一现场一次展开一个模型，长链路在图内滚动，流程图和证据区到顶或到底后将纵向滚动交给外层对话，两区可聚焦后用键盘翻页，跳到原调用时自动定位，切换节点重置证据滚动；右侧证据区与流程图自动等高，内容超出同高区域时才滚动，显示源文件实际提供的推理正文或摘要、模型请求输出、调用或返回预览、最终回答和证据位置，工具返回可跳到已确认的原调用。证据正文解开 JSON 文本块包装，保留来源标识，按段落、换行和表格展示；表格按内容分配列宽，代码、数字和日期保持完整，长文字自然换行，宽表仅在证据区内横向滚动，字号不缩小；以代码、名称（或简称）开头的宽表固定这两列，第二列偏移随第一列实际宽度更新；长名称按可视宽度完整换行，为右侧数据留出空间，不缩小字号、不截断名称，固定区以细线和8px间距分隔，横向滚动停止时按整列对齐，末尾保留必要余量，避免表头和正文停在固定区下方；未知结构和附加字段保留可见，未闭合的截断 JSON 不猜测修复；原始数据默认折叠且逐字符保留当前载入内容，截断提示仍然有效，复制给 Eris 继续使用原证据坐标。“复制给 Eris”复制模型、节点、完整业务引用和已确认的相关调用／返回节点，可直接粘贴追问；复制失败明确提示。推理节点完整显示源文本，有正文时优先显示正文；源数据仅有摘要时全文展示，不加来源提示、不做二次摘要。未提供可展示内容时直接标明；不把模型请求的历史输入或加密内容当推理。推理文本不截断；其他节点的界面预览最多2000字符，超出标明已显示长度；模型读取与恢复仍使用160字符的工具预览，不加载推理正文。深查追问按本轮批量或单节点取证的回答引用匹配本会话此前读取的案例，不凭最近一场猜测。入口折叠时不读原材料，展开后通过本会话已记录的调用引用只读恢复，不触发模型调用或专业重评。全局回复没有链路入口。“读取案例”工作步骤仍可展开共享原问、各模型最终回答和完整节点目录。

原始数据由 `AnalysisDataSource` 访问：业务 ID 先定位本地源文件，再读取正文。对原始消息的读取，会话工具记录只保存定位引用，恢复时重新读取；不会把原始输入文件复制进会话。展开读取、搜索或图片工具时，服务端根据当前用户、Session 和已记录的 callId 解析引用，使用只读工具返回材料；前端继续使用上游 ToolDetails、代码块、图片画廊和大图预览，原始消息详情可展开对应证据 ID 与引文。浏览器不能自填工具参数或执行专业任务；读取失败直接显示错误，重新展开可重试。

`list_data` 不传 `runId` 时列运行及默认 currentRun 的统计计数；提供时默认列回答输入与任务引用，`view:"comparisons"` 列已接受正式对战（默认5场、最多20场），用 `comparisonTier` 和 `outcome` 精确筛选档位与结果，避免中文标签字面差异导致空查。默认排除双方都好；显式 `outcome:"both_good"` 查看好例，`outcome:"all"` 查看全部。批量总结使用 `includeAnalysis:true` 并按 `nextOffset` 续页。目录 summary 不携带全量判词或来源数组。`query` 是字面文本筛选：默认输入目录搜标识与模型名，对战目录搜原问与判词，查看完整目录时省略。summaryScope 为 run 的统计覆盖整个运行，不受目录筛选或分页影响。筛选为空先取消筛选复查，再核对正式结果入口。数据目录返回可直接使用的 `reference`，读取时保持字段原样：原始材料为 `runId + inputId`，正式结果为 `runId + taskId`；两者不能混用。本会话独立任务使用 `operationId`。输入目录每项还给 `modelName`、`comparisonTier`，未声明档位时为 `null`；顶层 `comparisonGroups` 给运行配置中的档位及模型组，配置组不表示已完成对局。目录、搜索与原始消息的分页结果标明单位、`hasMore` 和 `nextOffset`：消息目录默认 30 条，正文默认 8000 个 UTF-16 字符；无下一页时 `nextOffset` 为 `null`。正式结果的精简结论与证据详情读取方式见[自主代码核验](#自主代码核验)；缺少结果时错误会指明其他读取入口。

`search_data` 的 `query` 接受单个查询或1–8个独立查询；空格分隔词要求同一节点全部包含，每词按原文精确匹配，不要求相邻。组合查询返回各词的 termLocations，零命中不等于事实不存在。批量搜索只加载、提取一次原始回答；每词单列总命中数（含零命中），每个节点保留该词首次命中的格式、源角色与续读偏移；system / developer 指令命中排在业务材料之后，仍计入总数并可续页读取。分页按合并后的命中条目计，不能将命中片段当成完整节点。

定向复核围绕用户疑点和会改变结论的反证取证；对应双方表述、调用和返回后，只为尚未闭合的关键缺口继续读取。作图使用已核验事实，通常每方1–2项；不在排版阶段重新扩展为整题评分，保留必要的第三项、判断边界及原证据入口。筛选保留被排除项的相关能力，区分未证实适用于目标场景与根本不具备该能力。

随机选例用 `list_data({runId,view:"comparisons",sample:true,limit:1,excludeCases:[...]})`。服务端先按档位与结果筛选（默认排除双方都好），再按 `batchId + caseId` 排除已展示题目的全部档位，最后等概率抽题并随机选其一场对战；一次抽取中题目不重复。随机模式不传 offset；返回 selection 的可选和剩余题数，抽尽时返回空目录。普通目录分页与明确读取同题另一档仍保留。

`read_case` 和 `show_comparison` 优先使用 `reference:{runId,query,comparisonTier}`，按原问连续关键词和档位定位唯一正式对战，避免模型抄写 `taskId`；零匹配或多匹配要求调整关键词，不能猜选。已有精确引用仍可直接读取，未登记的 ID 与尚无正式结果分开报错。页面恢复与证据链保存解析后的真实引用，后续新增同名对战不影响原记录。

### 会话与恢复

会话头遵守上游线协议：无工具时省略 `tools`，有工具时记录名称、说明和参数 Schema，确保历史加载与实时事件使用同一契约。

会话的权威记录为 `data/assistant/users/<user>/sessions/<id>/events.jsonl`；`state.json` 只存列表索引、进度和请求状态。Pi 使用内存 Session，并从追加记录重建消息与压缩边界。模型请求、工具执行前等待相关记录持久化。总结作为助手正文随会话记录保存。工具步骤摘要呈现业务动作、状态与数量；调用参数不完整或校验失败时仍可呈现动作与状态，不中断页面。技术引用在主动展开详情时可核对。专业任务位于 `operations/<operationId>/execution/`，通过现有 Host 校验和 JSONL 结果提交路径写入。专业任务的过程预览每秒合并一次，仍沿用上游工具事件与序号，完成时写入完整过程；重复的同一预览不再追加。总 Agent 自身的 token 流不受此合并影响。工具的业务 JSON 只保存一份，元数据仅保留读取定位信息。

同一 Session 仅一个进程持锁，其他副本转发请求及原始 Deepseek 多路流；锁 token 与 PID 同时匹配，确认进程退出后才接管。已接收用户请求及专业任务使用 UUID 去重，冲突内容拒绝。失败或中断时，缺失的工具结果和步骤结束记录由上游恢复逻辑补齐：未记录执行开始的调用可按需要重试，已开始但未持久化结果的调用标为结果未知，已记录结果保持原样。明确失败的原始材料读取保留错误正文与失败状态，恢复和展开不重新执行该次失败读取；成功读取仍按定位引用重建。结果未知时，只读或幂等调用可重试，有副作用的调用须先核对外部状态；专业任务按原 operationId 读取已接受结果后再决定继续。排队消息会恢复，已发送的请求不盲目重放。

日志仍写入根 `log/runtime.log`、`log/evaluation.log`。`--debug` 才保存专业 Worker 排查材料。

## 模块与上游

- `src/core`：`createEris` 统一装配提示词、Schema、工具和依赖，只依赖公共接口。
- `src/server`：Session / Workspace 产品操作，将 HTTP 和 WebSocket 交给 Runtime。
- `src/client`：原组件装配与分析图表；聊天布局继续使用上游样式。
- `packages/runtime`：Pi、会话执行者、Deepseek Connection/Gateway 接入。
- `packages/data`：追加记录、文件锁、数据与产物 IO。
- `apps/host`：配置、本地数据和专业 Agent 的具体组装。
- `packages/prompts/resources/eris`：总 Agent 提示词和工具文案。
- `schemas/eris`：分析工具输入约束。

界面固定浅色，直接使用 Deepseek 的布局、输入、消息、工具树、Markdown 和代码块源码。相邻正文分片共用一个 Markdown 文档，保留原文换行，在流式、结束与刷新后均正确呈现跨分片的加粗、链接和表格。非 ASCII 标点结尾的加粗可直接连接英文或数字，如 `**Fast：**B组`，纯 ASCII 边界保持 CommonMark 规则。长会话沿用上游分页、增量渲染与折叠过程分组；运行计时在独立组件内刷新，避免触发历史正文重绘。MiniMax 等网关的正文 `<think>` 包装在服务端转换为 reasoning 流，分片标签不会混入正文；原始会话仍保留用于 Pi 恢复的消息。思考和工具过程沿用上游折叠组件；没有可展示文字的思考块在流式、结束与刷新后均不创建折叠项，后续收到正文才显示。业务结果使用上游 ToolDetails 卡片，统计沿用上游 Session / Token 投影。

上游 Logo 图形源码与默认引用已移除，官方品牌插件不装配。同花顺官方标识通过品牌插槽显示在侧栏、欢迎页与运行状态，同一透明 PNG 用作浏览器图标；发送与主操作、链接、焦点和选中态通过主题 token 统一为朱红、深红与淡红，状态语义色和图表数据配色保留。标识与配色维护见[品牌模块](src/client/brand/README.md)。页面标题和品牌名称统一为 Eris。不提供主题切换、第三方模型市场或工作目录管理界面；代码核验通过对话工具完成。

来源基线和变更见 [upstream.json](../vendor/upstream.json)、[源码映射](../vendor/deepseek/sources.json)、[局部补丁](../vendor/deepseek/local.patch)及 [MIT 许可证](../vendor/deepseek/LICENSE)。普通构建完全使用本仓库源码，只构建 Web 资源与共享 Runtime；只有维护命令 `node scripts/vendor-deepseek.mjs <上游仓库>` 才读取外部仓库，并重新应用已登记补丁。维护时替换所选包的源码与测试，删除上游已移除的文件，不引入桌面或客户端构建入口。

### 外部搜索查证基准

先构建应用，再显式运行联网基准：

```bash
npm run build:app
node scripts/search-audit.mjs --live --output .artifacts/search-audit
```

基准使用[预声明的金融文档与口径](../tests/fixtures/search-audit.json)，对比单个自然查询和预声明的互补查询计划，记录Hit@k、空结果/失败、实际耗时与credits，并从已检索命中的URL读取原文。原文字面锚点覆盖用于检查提取，不能代替口径审查或最终事实判断。候选相关性、口径是否支持主张和历史公开证据需逐条人工审查；已知文档Hit@k不等于开放互联网召回率，预声明查询不代表Eris自主查询质量。基准会使用真实Serper额度，不纳入默认离线测试；结果写入指定产物目录，不作为运行缓存。Eris是否实际读原文、引用和保留历史未知状态，还须用真实模型完整会话复核。

正式比较的 `read_data` summary 只呈现一次 `comparisonScope`，附状态、标准答案和去重证据坐标；逐项底层评语与完整证据通过 details 分页读取，不改变落盘结果。事实复核直接使用 `read_case(review:true)` 与原文取证，避免为作图回读旧评语。

组合关键词检索直接展示各词附近的原文：相邻窗口合并，远处窗口放在 `contexts` 并给精确 `readOffset`，不把同节点共现视作同句关系。

原始检索结果中带标题和正文的记录分别匹配，优先标题命中的来源，并展示来源路径；重复的 query 元数据不作为证据命中。未识别为文章的字符串继续可搜，原始字段和快照可用 scope:all 核对，原文读取与复制坐标不变。

事实复核先按争议实体检索原始证据；搜索结果按文章定位，同一原文合并保留全部 matchedQueries 与词位置后分页；短篇保留正文，`source.read` 可直接用于批量取证，`endOffset` 限定文章边界。`scope:all` 也保持文章归属，模型自述不作为能力证据。结论分清已确认能力与目标用途：用途未证实只能待核验，不能据此排除；不同证据状态的实体分别列项。
复核的模型材料不预载节点清单，先按争议实体定位；用户展开仍读取全部节点、原始证据和复制坐标。
