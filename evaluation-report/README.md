## 当前数据

案例按一个不同问题计一个 case，每题只选一场同档 A/B 正式对比，共 60 个不同问题、120 份完整回答，Fast / Expert 各 30 场。40 个主观问题先覆盖 `daily-2026-10-13` 全部 22 题，每题保留一个档位（Fast / Expert 各 11 题），再从 `daily-2026-10-12` 补 18 题（各 9 题）。20 个客观问题取自最近带标准答案的 `daily-2026-10-09` 批次（各 10 题）。不重复计入同题的不同档位或跨日结果，更新器检查问题 ID 和规范化问句均唯一。覆盖筛选、归因、估值、客服、财报、宏观、基金、期权、复算及不同判决，不作为总体分布估计。选择清单、分类与比较 ID 在 `src/data/case-selection.json`。

60 场含 36 场胜负、15 场都好、9 场都差，无待核。真实 Comparison 来源为 r195（32 场）、r194（2 场）、r192（6 场）、r186（10 场）、r185（10 场），不以配置版本覆盖已接受记录。提示词仍独立保存 r153 历史快照；实验页使用同一批 60 题冻结上游材料，仅比较阶段以 r196 和 GPT-6 Luna 重跑三轮，不覆盖现有评测方案中的原判。

题型严格读取 `has_standard_answer` 及实际导入标准，不按题目表面性质推断。标准冲突、核心未知和待核保留源状态；待核不计平局或胜负。每个选中 case 保留对应档位的完整回答、标准、归因和判词。输入文件可能在运行后重排，更新器按 trace ID 定位，再核对 case、批次、题目和标准；同时保存当前物理行号与 state 原记录行号，拒绝缺失或重复匹配。

## 页面与交互

- **行业对标**：默认展示美团，按方案切换独立流程图；简短字段与来源链接随图展示，完整说明收在来源页。
- **现有评测方案**：先展示 Pi 与我们自己的分工，再按 60 个不同问题逐个查看，选择项同时标明 Fast / Expert。模型档位（Fast / Expert）与题型（主观题 / 客观题）组合筛选，默认 Fast 主观题，不提供混合题型选项；每个档位各有主观题 20 个、客观题 10 个。案例选项、计数、前后翻页及 Home/End 均限制在当前组合内，切换一个筛选时保留另一个筛选条件。输入与回答卡片使用固定尺寸，绘制比例只随窗口宽度变化，底部问题按内容自然向下展开；长问句、标准答案和取舍点评在卡内截断，点击各自入口查看完整内容。回答卡片保留完整最终回答。归因卡片呈现关键核验、验收状态和优点/问题数量，详情显示全部真实输出。逐项对照与裁决取舍共同标在同一个对比 Agent 下，流程页不显示版本角标，版本来源保留在数据快照中。对比 Agent、逐项对照与原文入口排在同一行。宽屏下，对照表与裁决卡片共同居中对齐两份匿名结果，证据汇合后水平进入表格；窄屏放在下一层，两框仍保持同一中线。连接线采用细线、圆角转折和开放箭头。各 Agent 用简洁文字标识，标准、归因、对比三个角色标题分别使用蓝色、青绿色、紫色流光，统一采用稍加粗的文字、窄高光芯与轻光晕，提亮三色底字并增强高光，按 3.2 秒周期扫过，实色底字始终保留；减少动态效果偏好及打印时移除光效，显示各自的静态深色。鼠标悬停不弹提示文字或改变卡片边框，键盘焦点与点击操作保留。判决卡片上半部揭示模型身份，下半部单独打开完整点评，两个操作互不触发。
- **Agent 协作**：用短句说明谁定清单、谁核对回答、谁比较、谁复核、谁归类和改写；任务协调负责分派与传递结果。
- **判决规则**：比较前至多补查一轮归因，每场比较一次。未对齐、核心未知或材料冲突按当前契约保留待核。可选核验后置记录，不覆盖原判、不自动再做归因、不阻塞正式交付。
- **提示词**：r153 的 34 份完整评测资源，通过七个入口查看各自的“材料 → 处理步骤 → 产出”流程。黑白节点与箭头表达顺序，关键规则贴在对应步骤旁，可展开核对原文；职责边界及全部原文保留在下方“完整提示词”中。沿用原有配色与字阶，关键语句加粗，窄屏纵向排列。页面不显示版本说明，来源信息保留在快照中。
- **实验**：与现有方案使用相同的 60 个不同问题，GPT-6 Luna / r196 运行同序首判、同序复判和换位复判三轮。Fast / Expert 与主观／客观联动筛选，默认 Fast 主观题，不提供全部题型。独立的“汇总”按钮展示全部 60 题和四组统计；再次点击恢复之前的分组，选择筛选也返回分组。覆盖、配对分母、一致率、三轮一致题数、分歧案例、逐题结果和取舍详情均随范围更新；匿名位置还原为真实 A组 / B组。

换位时，原回答①②连同归因、证据包、比较列、问题条目及详情顺序整体交换，并更新匿名映射；各项数据始终绑定原始回答，真实赢家不变。它是展示换位，不会触发模型调用或重算归因。

对照表只有对照项与两份回答。✓ / × 表示原判相对较优 / 较弱；— 未判优劣，∅ 不适用，? 待核实。不将符号解释为绝对正确或错误，也不按符号数量投票。绿色、红色、灰色和琥珀色只强调状态。双方问题归因完整列出，含责任未定位和待核实问题；未发现归类记录不等于未发现问题。

归因详情保留核心理由、原始总结、标准核对、数值核对、全部逐项评审、优点与问题、责任组件及证据。完整判据目录同时包含 requirements、scoring_points 和 red_flags；主图验收清单与计数只使用共同 requirements，不把私有要求或红线混入共同交付。

完整最终回答取源消息的全部文本块，按原顺序连接；回答中的图片、可视化和网页引用只保留文本，不在离线报告中请求外网或执行源 HTML。证据 ≤1600 个 Unicode 字符时完整保留，超长证据显示前 1200＋后 400 字符并明确标注省略数；所有摘录保存原结果文件、LF 物理行号和 JSON 指针。

## 真实对照实验

固定当前 60 个不同问题，冻结原 Criteria / Attribution 的已接受材料和原始输入引用，使用 r196、GPT-6 Luna、medium 思考强度、Pi 和相同预算运行三个独立 run：原位一、原位二、A/B 换位，共 180 场新 Comparison。三轮同时启动，每轮 8 路、总并发 24；网关触发 token 限流后降至每轮 2 路、总并发 6，沿用原任务和剩余内容预算续跑，过程记录在协议中。所有任务与比较 ID 独立；换位轮只交换匿名位置，不重做标准和归因、不润色判词。上游材料保留实际评测器和模型来源。本实验只测比较阶段稳定性，不能宣称全链路 r196 或人工准确率。

180 / 180 场均已决，最终 0 失败、0 待核、0 缺失。同位重复一致 56 / 60（93.3%，Wilson 95% 区间 84.1%–97.4%）；换位一致 55 / 60（91.7%，区间 81.9%–96.4%）；53 / 60 题三轮结论一致。两组对照中双方核心可用性均为 120 / 120 一致。

页面将“原位一”标为同序首判、“原位二”标为同序复判：材料、匿名 A/B 顺序和配置相同，第二次是独立判决，不读取首判结论；第三轮交换匿名位置再独立评判。各案例显示本轮匿名身份与真实组名的对应关系。

逐题结果位于统计指标之后，汇总与分组视图均直接展开表格。汇总表中未达全一致的配对数和非零分歧题数用橙色加粗标出。其后单列 7 个三轮不一致案例（Fast 主观 6 题、客观 1 题，Expert 0 题），每个案例默认折叠，点击标题展开三轮正式判决、完整取舍、报告分析、比较项、引用归因与结果来源。7 题均在“都好”和“单方胜”之间变化；主要是优势、错误影响与胜负门槛的权衡变化。博敏电子换位轮另有未被所引归因发现支持的减持指控，单独标为依据待核。3 处判词混用匿名字母与真实组名，展示原文并标注映射，不修改正式记录。报告分析维护在 `src/data/experiment-analysis.json`，由 `snapshot` 校验分歧案例及三轮比较 ID 后附入快照；比较项、归因摘录与匿名原文直接读取已保存收据。

一致率按结果类型与还原到真实模型的胜者共同匹配，只计双方已决的样本；待核、失败、未完成与缺失配对单列，Wilson 95% 区间按当前筛选重算。原位重复也存在采样差异，换位分歧不能单独归因为位置偏差。目的性选样不代表总体分布；稳定不等于正确。未执行提示词消融，没有人工审定金标。

协议位于 `.artifacts/report-experiments-20261013/protocol.json`，真实运行保存在同目录 `runs/report-r196-luna-{original-1,original-2,swapped}-20261013/`。协议记录 60 题来源、固定依赖、原始输入坐标、三轮映射、模型和执行预算。新旧材料逐条核验；运行结果独立保存，不覆盖原每日 run。网页展示使用离线快照，不在展示时读目录或调用模型。

`scripts/experiments.mjs` 只在显式调用时执行实验。`prepare` 创建一次固定协议和新 run，拒绝覆盖已有目录；`run` 使用同一 UUID 续跑未完成任务，保留已接受结果与已花费预算；`snapshot` 读取已保存结果生成快照。步骤如下（模型调用发生在 `run`）：

```bash
npm run build:app
node evaluation-report/scripts/experiments.mjs prepare
node evaluation-report/scripts/experiments.mjs run
node evaluation-report/scripts/experiments.mjs snapshot
node evaluation-report/scripts/build.mjs
```

## 维护与构建

目录按用途收纳，根目录只有一个可交付 HTML：

```text
evaluation-report/
├── report.html             # 唯一交付物，构建生成
├── README.md               # 数据来源与维护说明
├── agent-evaluation-research-2026.md # 评测流程与来源说明
├── src/
│   ├── template.html       # 页面骨架、唯一资源清单与装配顺序
│   ├── app.js              # 行业对标与五个证据主题的导航与挂载
│   ├── shared/             # 字体、全局样式、图标和动效
│   ├── data/               # 研究全文与来源、案例、摘要、提示词、实验快照
│   └── pages/              # research / flow / architecture / rules / prompts / experiments
│       └── <主题>/         # index.js 与 styles.css；flow 另含回答和归因详情
├── scripts/                # build 构建；snapshot 更新案例；research 研究全文；experiments 真实实验
├── tests/                  # 构建、数据与交互回归
└── licenses/               # 图标许可，亦内嵌于成品
```

修改 `src/` 后重新构建，不直接编辑 `report.html`。页面骨架可用于开发预览；对外只交付根目录的 `report.html`。构建器只使用 Node.js 内置模块，读取本目录的静态源码，不读取原始业务数据、不调用模型、不请求网络。

```bash
node evaluation-report/scripts/build.mjs
node --test evaluation-report/tests/*.test.mjs
```

`src/template.html` 是资源清单的唯一来源；新增或调整样式、脚本，只改模板中的引用即可，无需修改构建器。成品按样式、页面骨架、数据快照、展示逻辑和启动代码分区，每段保留 `data-source` 指向源码。标记 `data-snapshot` 的 JSON 快照仅在构建时去掉格式化空白，数据值逐项保留；源码、展示逻辑和样式保持易读。成品体积主要来自完整案例数据，不能用生成文件的行数衡量展示代码的复杂度。

构建拒绝重复资源、越出 `src/` 的引用与残留的外部资源；`--output /任意目录/汇报.html` 可指定单文件输出位置。数据快照只在显式运行下更新：

```bash
node evaluation-report/scripts/snapshot.mjs --selection evaluation-report/src/data/case-selection.json
```

字体层级统一由 `src/shared/tokens.css` 管理：分区标题 20px、卡片标题 16px、流程正文 16px、表格与阅读正文 15px、辅助信息 14px；来源和紧凑标签使用 12px。标题统一为 600 字重，统计大数单独保留强调层级。流程图换行与标题间距直接读取这些字号，流光底字和高光层共用字号及字重。

选中文字的前景色同时设置 `color` 与 SVG 的 `fill`，保证正文与流程图的选区均为白字深底。行业图统一使用中性灰连线与无描边文字，鼠标点击不显示整图焦点框，键盘焦点保留；分支标签与布局坐标分开保存，标签在连线上避让节点、其他标签和连接线。回归检查标签原文、图的边界与连接关系。修改选区样式后需在真实浏览器选中流程图文字检查可读性与选中文本；JSDOM 不验证 SVG 选区的实际绘制。

显式更新案例后需同步主图短摘要、选择清单与来源核验；实验快照独立维护，只有重新执行对应实验后才更新其结果。来源核验在本地原始记录齐备时执行，缺失时明确跳过，展示与构建不依赖其存在。报告内容不修改原始输入、正式结果、生产统计结构或评测器标识。
