## 行业对标研究

默认首页以“四个知道”组织领导汇报，资料获取日为 2026-10-13。六个章节分别呈现汇报摘要、美团与字节精读、轻量方案、横纵八维判断、建设路线、来源与完整研究。正文只呈现结论、数据、对标动作与验收，使用 16px 正文；日期、研究口径、置信度和证据限制集中到“来源与全文”，不添加解释性角标或重复小字。已有实现、已验证范围和拟建能力分别标明；28 条外部来源保留日期及证据限制。市场规模、行业排名与统一最高分缺乏可比证据，不填写猜测值。研究不代表已实施路线图或已达到行业领先。

本轮建议复用现有金标、校准、换位和成簇统计入口，优先开展人工审定、分层实验与修复回归。外部框架仅做文档研究，没有安装或执行。报告不改变生产评测逻辑、评测器标识、原始数据或冻结统计契约。

## 当前数据

案例来源为 `data/runs/comparison/eval-20261006-215149`：30 个业务案例、84 份完整回答、42 场同档对局，37 场正式判决、5 场待核。正式结果含 19 场胜负、8 场都好、10 场都差；14 题带标准答案。真实 Comparison 来源为 r151（35 场）和 r152（2 场），不以配置版本覆盖已接受记录的版本。当前提示词独立保存 r153 快照，不冒充这些历史案例的实际执行提示词。

题型严格读取 `has_standard_answer` 及实际导入标准，不按题目表面性质推断。标准冲突、核心未知和待核保留源状态；待核不计平局或胜负。每题保留全部 Fast / Expert 对局，未完成正式判决的题也可查看源回答和归因。

## 页面与交互

- **行业对标**：默认首先显示决策摘要，章节标签支持方向键及 Home/End；重点材料按“做法 → 我们已有 → 动作 → 验收”对照。完整八维研究在来源页展开，窄屏表格在各自容器内横向滚动，打印展开全部研究章节。
- **流程**：30 题逐个查看，题内切换模型组。输入与回答卡片使用固定尺寸，绘制比例只随窗口宽度变化，底部问题按内容自然向下展开；长问句、标准答案和取舍点评在卡内截断，点击各自入口查看完整内容。回答卡片保留完整最终回答。归因卡片呈现关键核验、验收状态和优点/问题数量，详情显示全部真实输出。逐项对照与裁决取舍共同标在同一个对比 Agent 下，流程页不显示版本角标，版本来源保留在数据快照中。对比 Agent、逐项对照与原文入口排在同一行。宽屏下，对照表与裁决卡片共同居中对齐两份匿名结果，证据汇合后水平进入表格；窄屏放在下一层，两框仍保持同一中线。连接线采用细线、圆角转折和开放箭头。各 Agent 用简洁文字标识，标准、归因、对比三个角色标题分别使用蓝色、青绿色、紫色流光，统一采用稍加粗的文字、窄高光芯与轻光晕，提亮三色底字并增强高光，按 3.2 秒周期扫过，实色底字始终保留；减少动态效果偏好及打印时移除光效，显示各自的静态深色。鼠标悬停不弹提示文字或改变卡片边框，键盘焦点与点击操作保留。判决卡片上半部揭示模型身份，下半部单独打开完整点评，两个操作互不触发。
- **Agent 协作**：用短句说明谁定清单、谁核对回答、谁比较、谁复核、谁归类和改写；任务协调负责分派与传递结果。
- **判决规则**：比较前至多补查一轮归因，每场比较一次。未对齐、核心未知或材料冲突按当前契约保留待核。可选核验后置记录，不覆盖原判、不自动再做归因、不阻塞正式交付。
- **提示词**：r153 的 34 份完整评测资源，通过七个入口查看各自的“材料 → 处理步骤 → 产出”流程。黑白节点与箭头表达顺序，关键规则贴在对应步骤旁，可展开核对原文；职责边界及全部原文保留在下方“完整提示词”中。沿用原有配色与字阶，关键语句加粗，窄屏纵向排列。页面不显示版本说明，来源信息保留在快照中。
- **实验**：题目标签显示“有答案／没答案”，仍由 hasStandardAnswer 判断是否存在导入的标准答案。真实 MiniMax 固定材料对照，显示覆盖、配对分母、逐题三轮结论、差异取舍及来源。

换位时，原回答①②连同归因、证据包、比较列、问题条目及详情顺序整体交换，并更新匿名映射；各项数据始终绑定原始回答，真实赢家不变。它是展示换位，不会触发模型调用或重算归因。

对照表只有对照项与两份回答。✓ / × 表示原判相对较优 / 较弱；— 未判优劣，∅ 不适用，? 待核实。不将符号解释为绝对正确或错误，也不按符号数量投票。绿色、红色、灰色和琥珀色只强调状态。双方问题归因完整列出，含责任未定位和待核实问题；未发现归类记录不等于未发现问题。

归因详情保留核心理由、原始总结、标准核对、数值核对、全部逐项评审、优点与问题、责任组件及证据。完整判据目录同时包含 requirements、scoring_points 和 red_flags；主图验收清单与计数只使用共同 requirements，不把私有要求或红线混入共同交付。

完整最终回答取源消息的全部文本块，按原顺序连接；回答中的图片、可视化和网页引用只保留文本，不在离线报告中请求外网或执行源 HTML。证据 ≤1600 个 Unicode 字符时完整保留，超长证据显示前 1200＋后 400 字符并明确标注省略数；所有摘录保存原结果文件、LF 物理行号和 JSON 指针。

## 真实对照实验

固定 6 场对局，冻结原 Criteria / Attribution 的已接受材料，使用 r153、MiniMax-M3、Pi 和相同预算运行三个独立 run：原位一、原位二、A/B 换位，共 18 次新 Comparison。上游材料仍保留 r151/r152 来源。本实验只测比较阶段稳定性，不能宣称全链路 r153 或人工准确率。

18/18 正式完成，0 失败、0 待核、0 缺失。同位重复与换位均为 5/6（83.3%）一致；按结果类型与还原到真实模型的胜者共同匹配，Wilson 95% 区间均为 43.6%–97.0%。中谷物流一题原位一判 A组Fast 胜，原位二和换位判都好；同位重复也变化，不能单独归因为位置偏差。六题是固定诊断样本，不代表总体分布；稳定性不等于正确率。未执行单因素提示词消融，没有人工审定金标。

协议及核验结果在 `.artifacts/report-experiments-20261007/`，真实新运行位于 `data/runs/comparison/report-r153-original-1`、`report-r153-original-2`、`report-r153-swapped`。三组生产校验通过，冻结依赖与原 run 逐条核对；生产 benchmark compare 与页面的配对结果一致。页面静态快照保留每条记录来源，不在展示时读取这些目录。

## 维护与构建

目录按用途收纳，根目录只有一个可交付 HTML：

```text
evaluation-report/
├── report.html             # 唯一交付物，构建生成
├── README.md               # 数据来源与维护说明
├── agent-evaluation-research-2026.md # 四个知道研究源稿
├── src/
│   ├── template.html       # 页面骨架、唯一资源清单与装配顺序
│   ├── app.js              # 行业对标与五个证据主题的导航与挂载
│   ├── shared/             # 字体、全局样式、图标和动效
│   ├── data/               # 研究全文与来源、案例、摘要、提示词、实验快照
│   └── pages/              # research / flow / architecture / rules / prompts / experiments
│       └── <主题>/         # index.js 与 styles.css；flow 另含回答和归因详情
├── scripts/                # build 构建；snapshot 更新案例；research 嵌入研究全文
├── tests/                  # 构建、数据与交互回归
└── licenses/               # 图标许可，亦内嵌于成品
```

修改 `src/` 后重新构建，不直接编辑 `report.html`。页面骨架可用于开发预览；对外只交付根目录的 `report.html`。构建器只使用 Node.js 内置模块，读取本目录的静态源码，不读取原始业务数据、不调用模型、不请求网络。

```bash
node evaluation-report/scripts/build.mjs
node --test evaluation-report/tests/*.test.mjs
```

`src/template.html` 是资源清单的唯一来源；新增或调整样式、脚本，只改模板中的引用即可，无需修改构建器。成品按样式、页面骨架、数据快照、展示逻辑和启动代码分区，每段保留 `data-source` 指向源码。标记 `data-snapshot` 的 JSON 快照仅在构建时去掉格式化空白，数据值逐项保留；源码、展示逻辑和样式保持易读。成品体积主要来自完整案例数据，不能用生成文件的行数衡量展示代码的复杂度。

构建拒绝重复资源、越出 `src/` 的引用与残留的外部资源；`--output /任意目录/汇报.html` 可指定单文件输出位置。数据快照只在显式运行下更新：

```bash
node evaluation-report/scripts/snapshot.mjs --run data/runs/comparison/eval-20261006-215149
```

字体层级统一由 `src/shared/tokens.css` 管理：分区标题 20px、卡片标题 16px、流程正文 16px、表格与阅读正文 15px、辅助信息 14px；来源和紧凑标签使用 12px。标题统一为 600 字重，统计大数单独保留强调层级。流程图换行与标题间距直接读取这些字号，流光底字和高光层共用字号及字重。

选中文字的前景色同时设置 `color` 与 SVG 的 `fill`，保证正文与流程图的选区均为白字深底。修改选区样式后需在真实浏览器选中流程图文字检查可读性与选中文本；JSDOM 不验证 SVG 选区的实际绘制。

显式更新数据后需同步主图短摘要、来源核验与实验快照；不兼容旧案例字段。来源核验在本地原始记录齐备时执行，缺失时明确跳过，展示与构建不依赖其存在。报告内容不修改原始输入、正式结果、生产统计结构或评测器标识。

AstraDraw 仅作机制表达参考，未导入代码。换位符号使用 Phosphor Icons，MIT 许可保留在 `licenses/PHOSPHOR-LICENSE.txt` 并内嵌于最终 HTML。用户明确要求浅色及无导出/下载/页脚，因此不采用通用模板的深色切换和页脚。
