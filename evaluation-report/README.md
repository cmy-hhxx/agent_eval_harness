# 评测汇报

独立的离线前端。源码、样式和内容在本目录维护，构建为一个 HTML 文件；页面与构建器不导入业务代码，不运行评测，也不访问模型、数据库或网络。

## 页面

| 主题 | 当前内容 |
|---|---|
| 流程 | 10 个真实案例，3 道客观题、7 道主观题；同一机制图展示完整问句、验收清单、独立核验、比较摘要、原判与 A/B 问题归因 |
| 判决规则 | 完整决策树：依据是否明确、有限复核、核心可用性、实质差距，以及胜负、都好、都差和不交付 |
| 提示词 | r74 历史快照的五个 Agent、共用材料、工具说明，共七个入口；关键规则原文摘录、输入与产出结构，以及 28 份完整原文 |
| 实验 | 评测器版本、实验结果和逐轮对比的空结构；`experiments.versions` 与 `experiments.results` 均为空，未启动新实验 |

流程图采用“输入 → 标准与核验 → 匿名 → 逐项对照 → 判决”的五列 SVG 构图，下方保留条件复核和 A/B 问题归因。1080px 及以下将比较与判决移至第二层，画布高度按问句、清单、矩阵和问题归因内容调整，并根据窗口可用高度约束显示；清单、对照项优先单行，长内容保留必要换行。全部可见内容直接位于图内，没有缩放、浮层或图后正文；悬停只突出相关连线。通过下拉列表、前后按钮切换案例，前后翻页循环；按钮支持 Home、End、左右方向键。匿名换位支持鼠标、Enter 和空格，仅改变展示代号，原始回答、归因、判决和获胜来源保持不变，不代表重新执行过盲测实验。

验收清单按原问句及适用判据拆分为 3–5 项；候选专属要求标明回答序号。清单垂直接入共享核验框，框内两行分别核验回答①、②，回答与匿名证据保持各自水平连接。69 条正式比较归并为 60 行图内摘要，最多每例 7 行，每行保留所对应的原始比较索引与来源。原始比较、原回答摘录、原判与后处理来源仍保存在离线数据快照中。

对照表只有对照项、A、B 三列，优劣符号直接放在各回答的值旁，依据正式比较的 `betterIndices`：✓ 表示原判相对较优，× 表示相对较弱，— 表示未判优劣；不等同于正确、错误或完全相同。合并行只在部分子项占优时加 *，不扩大为整行全部子项的结论。专属要求的未适用方显示 ∅，证据不确定显示 ?，不误标为较弱。判决框直接显示带来源的取舍摘要与已知疑点；不以符号数量计票，不重新判决。A/B 换位只更新代号，符号、取舍和最终结果始终绑定原回答。

问题归因沿用现有看板问题库的“模型 → 组件 → 问题名称”层级，按图中的匿名 A/B 代号分别列出。内容取每条回答的 Attribution `findings`，只显示 `type=problem` 且责任组件非空的 27 条问题；同组件分组，完整保留原问题名称，`uncertain` 标为待核实。未记录这类问题的回答直接显示“未记录问题”，不将缺少 Clustering 记录误当成没有问题。流程图不展示评语润色；问题条目始终绑定原回答，匿名换位同步更新标签。

机制图的判决框与对照表底边对齐；复核后的可裁决支路在二者下方连接，仍未决支路水平连接不交付。判决树默认全部可见，结果节点支持路径高亮。一次独立归因复核后仍未决的案例不交付正式判决；双方不可用时仍判都差，不因相对优劣变成正式胜者。提示词阅读器先呈现关键规则的连续原文摘录和输入、执行、产出，再按规则分组展示完整原文，保留字符、段落和缩进，不提供下载入口。浏览器打印仅输出当前主题。

题型严格依据正式评测记录的 `has_standard_answer`：`true` 显示客观题，`false` 显示主观题，不按问句性质另行分类。快照中的 `hasStandardAnswer` 保留该字段，必须与 `groundTruth.available` 一致。三道客观题在完整问句下方显示真实标准答案并用蓝色强调；主观题不显示标准答案区域或缺失占位。来源校验同时检查输入的 `meta.ground_truth` / `meta.std_answer`、`has_standard_answer` 与正式结果，不从候选回答或判决推导答案。输入框高度随问句与标准答案换行调整。

## 维护与构建

| 文件 | 职责 |
|---|---|

| `src/diagram-interaction.js` | 机制图连线高亮与匿名换位交互 |
| `src/rules.js`、`src/rules.css` | 判决决策树、路径交互与样式 |
| `src/prompts.js`、`src/prompts.css` | 28 份提示词原文快照、七个入口及阅读排版 |
| `src/icons.js` | 内嵌图形符号与许可 |
| `src/motion.js`、`src/app.js` | 原生转场、主题导航与模块装配 |
| `build.mjs` | 合并 4 份 CSS 和 8 份 JS，检查外部资源 |
| `report.html` | 单文件构建产物，不直接编辑 |

双击 `index.html` 预览源码版本。修改后构建并检查：

```bash
node evaluation-report/build.mjs
node evaluation-report/build.mjs --output /tmp/evaluation-briefing.html
node --test evaluation-report/build.test.mjs evaluation-report/interaction.test.mjs
```

`report.html` 可直接复制到其他电脑离线展示。页面没有导出按钮；所有内容与展示资源由构建器内联。来源文件只用于人工更新快照与本地核查，不会在打开页面或构建时读取。快照与交互测试不依赖本地业务数据；来源核对用例在原始输入和结果齐备时执行，缺失时明确跳过。

输入位于 `data/sources/model-answers/`；表中输入行号按本地 JSONL 的 LF 分行计算，Comparison 行号指同 run 的 `results/comparison.jsonl`，均从 1 开始。Criteria、Attribution、Clustering 及 Rewrite 的来源路径、行号、字段指针与收据保存在各案例的 `provenance` 中；来源核对同时验证记录身份与行号，问题归因直接展示正式 Attribution 记录，不补造问题或归类。

华润啤酒销量、银河证券利率、三季报披露家数的 `has_standard_answer=true`，属于客观题；其余 7 例为 `false`，属于主观题，且 `is_correct=null`。标准及裁判结果均未据此得到独立外部验证。阅读原判时保留以下具体限制：

- **上证区间涨跌幅**：两方都给出 −16.89% 与 −22.31% 两种口径，不能解读成单一数值对错对照。回答①的标题编号 finding 同时承认 `###` 是 H3、`1.` 不含右括号，该条低等级归类存在解释争议。
- **MACD双波峰筛选**：回答①前文把大富科技列为严格命中，后文却给出两峰间最低 DIF 为 0.011、未跌破零轴。正式裁判未识别这处矛盾；3 只与 16 只不是已独立验证的准确数量，两方筛选池与口径不同，也不是同条件召回率实验。
- **政策支持与竞争**：原判取舍将回答①专属的风险提示要求列为横向胜因，但该比较项明确对回答②不适用。页面保留原判，并显示这一口径疑点，不将其作为已验证的公平判断。
- **多条件技术筛选**：原问句中的“‡2%”与“当日涨跌幅 2%”原样保留，不补比较符。双方原条件结果均为 0，57 条是放宽条件后的参考候选；回答②两条相关归类均为 `uncertain`，不作为已证实错误展示。
- **掉期交割日期**：归因阶段认可双方核心交付，比较阶段指出回答①的日元年末假期与远端日期问题。页面保留正式阶段分歧，不把日期标为独立核验结论。
- **三季报披露家数**：回答中的 17 时 1844 家与导入标准的 18 时 1828 家存在口径冲突。页面展示本次“都差”原判，不证明两种时点的数据可直接比较。
- **交易口诀、上涨归因与政策分析**：口诀的覆盖度不证明盈利效果；上涨归因材料不证明各因素的因果贡献；政策支持的分析不证明未来竞争判断。

多条件技术筛选的标准答案已向本地源记录回查：`a_fast`、`b_fast` 的 `2026-09-23.jsonl` 第 17 行及 `a_expert`、`b_expert` 同日第 18 行，均为 `has_standard_answer=false`、`meta.std_answer=null`，没有 `meta.ground_truth`。`_source` 指向 `eval_input/ce38db181cee482e_{A-fast,B-fast,A-expert,B-expert}.jsonl` 第 18 行，该上游原始文件不在本仓库。模型回答中的 0 只和放宽后的 57 条不是标准答案；本地记录核对不能替代对上游原始题库的确认。

判决规则的源码入口为 `packages/workflows/src/comparison/verdicts.ts`、`review.ts` 与 `docs/contract.md`。提示词阅读器保留 **r74** 历史快照，取自当时 `packages/prompts/resources/` 的五个评测阶段、共用材料和工具说明；关键摘录与完整原文均来自同一快照。它不随当前 `configs/host.json` 的评测器标识或资源文件自动变化。流程案例仍是 **r73** 的已接受记录，不能将 r74 提示词视为这些案例的实际执行提示词。测试核对快照自身的字段、数量、摘录及来源关系；更新快照时同步这些信息，不改写原始输入、正式结果或生产统计契约。

## 视觉资源

页面仅使用黑、白、灰和少量强调色。比较单元格的 ✓ 为绿色、× 为红色，未判与不适用为灰色，待核实为琥珀色；符号形状同时区分状态。颜色集中在 `src/tokens.css`，只强调图标。AstraDraw 仅作为机制表达的视觉参考，未导入其代码或资源。机制图箭头与换位控件由本模块直接绘制。内嵌图形符号模块使用 [Phosphor Icons](https://github.com/phosphor-icons/core)，MIT 许可保存在 `PHOSPHOR-LICENSE.txt` 并内嵌于最终 HTML。
